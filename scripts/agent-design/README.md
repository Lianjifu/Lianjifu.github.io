# AI Agent 系统设计 · 生成规范

本目录是「AI Agent 系统设计」专题的文章页生成器。每一篇由两部分合成：

- **源稿**：`docs/agent-design-source/<source>.md`，从《系统设计知识点总纲》冻结下来的那一章。
- **手写计划**：`scripts/agent-design/plan-<篇号>.cjs`，作者写的导语、引导思考表、全景表、路线图、每小节的要点与思考笔记、结尾四小节，以及源稿编号的改写规则。

生成：`node scripts/agent-design/build.cjs <篇号>` → `2026/11/26/agent-design-<篇号>-<slug>/index.html`
自检：`node scripts/agent-design/check.cjs <篇号>`

## 目录

| 文件 | 作用 |
| --- | --- |
| `md.cjs` | Markdown → HTML（表格、代码块、引用、列表、粗体、行内代码） |
| `series.cjs` | 专题总表：博客篇号 ↔ 总纲章号 ↔ 标题 ↔ URL |
| `build.cjs` | 生成器 |
| `check.cjs` | 结构自检 |
| `audit-links.cjs` | 锚点体检：正文里的 `#…` 链接是否都能落到本页真实 id 上 |
| `integrate.cjs` | 全站接线：专题页、归档页、首页、搜索索引、订阅文件、正文基准 |
| `polish-targets.cjs` | 润色清单：列出与别的篇目撞开头前八字的正文字段 |
| `apply-polish.cjs` | 润色打补丁器：按映射替换 plan 里的字面串，每条必须命中且仅命中一次 |
| `audit-polish.cjs` | 横向体检：雷同句式、术语变体、跨篇共享数字 |
| `audit-numbers.cjs` | 数值口径核对：相邻匹配「指标名 + 数值」，同指标多个取值会报出来 |
| `audit-series.cjs` | 结构对照：各篇的段数、小节数、篇幅与面板密度 |
| `plan-<篇号>.cjs` | 手写内容 |
| `fixups-<总纲章号>.cjs` | 源稿编号与跨章引用的改写规则 |

## 一、plan 文件

以 `plan-01.cjs` 为样板。顶层按篇号取键：

```js
module.exports = {
  '03': {
    fixups: require('./fixups-22.cjs'),
    desc: '……一段 meta description',
    lead: '……章首导语一段',
    guide: [ [3 条], [3 条], [3 条], [3 条] ],   // 引导思考表四行
    overview: [ ['本章回答','…'], ['核心机制','…'], ['关键数字','…'], ['读完能做什么','…'] ],
    route: [ ['第一段 · …','一段说明'], …七段 ],
    segs: [
      {
        title: '段标题',
        part: '段标：这一段回答什么',
        secs: [
          {
            title: '小节标题',
            key: '本章要点 2–4 句',
            note: '思考笔记 2–4 句',
            subs: ['22.3.1', '22.3.2'],   // 或
            from: ['**定义**：'], to: ['**典型用户与场景**：'],
          },
        ],
      },
      …六段
    ],
    closing: {
      summary: '一句话总结',
      points: [ ['结论', '说明'], …3–5 条 ],
      next: '下一章 <a href="…">…</a>：……',
      reading: [ ['标题', '说明', '/路径/'], … ],
    },
  },
};
```

**不要**在 plan 里写 `slug` / `no` / `num` / `title` / `kicker` / `date`——这些由 `series.cjs` 提供，写两遍会漂。

## 二、层级映射

源稿的六节结构（定义 → 矛盾 → 方法论 → 护栏 → 案例 → 演进）直接升成六段：

| 博客 | 源稿 | 说明 |
| --- | --- | --- |
| h2 `seg-N` | `### NN.1` … `### NN.6` | 段，**按顺序一一对应**，数量必须相等 |
| h3 `sec-N.K` | 段内自拟分组 | 小节，编号 `章.段.小节` |
| h4 `sec-N.K.M` | `#### NN.3.M` | 子小节，标题不带编号，标 `data-toc-skip` |

小节正文有两种取法：

- **`subs`**：列出来源稿的 `####` 编号，按顺序取。生成器会把每个 `####` 变成一个 h4 子小节。
- **`from` / `to`**：源稿某一段里没有 `####` 时（通常是 `### NN.1` 与 `### NN.2`），用行首标记切分。`from` 是起始行的前缀，`to` 是结束行的前缀（不含）。标记必须唯一，否则生成器会报错。

小节分组不必与源稿的 `####` 一一对应：可以两三个 `####` 合成一个小节，让侧栏目录落在 25–40 条之间。

## 三、fixups：源稿编号的改写

源稿按 `22.3.x` 编号，博客按「章.段.小节」编号，两套对不上。**源稿里每一处 `§NN.N` 都必须改写掉**，改成指向博客锚点的链接：

```js
module.exports = [
  [
    '**本节是语义层与指标治理的权威版**，§23.4.3、§23.5 只引用。',
    '**本节是语义层与指标治理的权威版**，<a href="#sec-4.2.1">语义层护栏</a>与<a href="#seg-5">第 5 段</a>只引用。',
  ],
];
```

规则：

- 每条规则命中次数必须**恰好 1 次**，否则生成器报错。上下文不足以区分时，把整句写进 `from`。
- 链接文字用小节或子小节的标题，不用编号（编号在博客里不可见）。
- 源稿引用总纲其它章的，改成博客篇号 + 站内链接。映射见 `series.cjs`：
  源 22 客服 → 博客 03；源 23 问数 → 01；源 24 问答 → 02；源 25 营销 → 04；
  源 26 电商 → 05；源 27 供应链 → 11；源 28 文旅 → 06；源 29 运维 → 07；
  源 30 安全运营 → 08；源 31 合同审查 → 09；源 32 办公写作 → 10。
- 源稿引用「第一章 §1.4.4」的，改成「对照「单向门与双向门」的判据」。
- 源稿引用总纲里博客没有的章节（如 Feed、秒杀、广告），改写成可独立成立的表述，或指向站内其它专题。

### 锚点 id 怎么算（最容易踩的坑）

**显示编号 ≠ 锚点 id。** 标题上印的是「章.段.小节」，锚点却是不含章号的段内局部编号：

| 层级 | 锚点 | 例 |
| --- | --- | --- |
| 段（h2） | `seg-<段号>` | `seg-3` |
| 小节（h3） | `sec-<段号>.<该段内的小节序号>` | 第 3 段第 6 个小节 → `sec-3.6` |
| 子小节（h4） | `sec-<段号>.<该段内的小节序号>.<源稿 #### 编号的最后一段>` | 第 3 段第 6 个小节里的源稿 `#### 22.3.14` → `sec-3.6.14` |

子小节 id 的第三段是**源稿编号的最后一段**（`22.3.14` → `14`），不是它在段内的序号。
所以「段内第 2 个子小节」和「源稿编号第 2 段」完全是两回事。

**不要靠手算。** 先把页面生成出来，再跑：

```bash
node scripts/agent-design/audit-links.cjs <篇号>
```

它会列出每一个失效的锚点，并按「段内第 N 个子小节」换算出正确的 id。
把 `href="#…"` 里的 id 改成它给出的值，重新生成即可。已发布的 01 / 02 曾经 21 处、14 处
全部点不到，就是栽在这一点上。

### 行内 HTML

`md.cjs` 会把整段文本做 HTML 转义，但**只放行 `<a>` 标签**（fixups 写进来的锚点链接）。
写 fixups 时可以直接写 `<a href="#sec-3.6.14">小节标题</a>`，不要自己写实体转义。


## 四、手写内容的质量要求

- **本章要点**：说清这一节讲了什么、有什么结论或数字。2–4 句。
- **思考笔记**：说清这一节最容易误解或最值得带走的一点。2–4 句，要有判断，不要复述要点。
- 两段都写中文正文，不要写成提纲。
- 中文标点用全角，代码、指标名、路径用半角。

## 五、验证

```bash
node scripts/agent-design/build.cjs 03     # 生成
node scripts/agent-design/check.cjs 03      # 自检，必须通过
node scripts/agent-design/audit-links.cjs 03 # 锚点体检，必须全部命中
```

`check.cjs` 管结构（目录条数、面板数量、残留编号），`audit-links.cjs` 管锚点（正文里的
`#…` 链接有没有落空）。两个都过才算这一篇做完。

浏览器看一眼（本地服务 `python3 -m http.server 4000 --bind 127.0.0.1`）：

- 1440px 与 390px 都无横向溢出。
- 章首的引导思考表、要点面板、路线图都渲染正常。
- 表格在 390px 下不撑破版面。
- 侧栏目录点得动，条目数与正文标题数一致。

## 六、不要动的东西

生成器只写 `2026/11/26/agent-design-<篇号>-<slug>/index.html`。下面这些由主会话统一处理，单篇任务不要碰：

`archives/index.html`、`categories/agent-design/index.html`、`search.xml`、`atom.xml`、`docs/article-manifest.json`、`index.html`、`css/`、`docs/agent-design-series.md`，以及 `scripts/agent-design/` 下不属于本篇的文件。

也不要运行 `git add` / `git commit` / `git push`。

## 六、全站接线（主会话做）

单篇任务只写页面；专题页、归档页、首页、搜索索引、订阅文件、正文基准由主会话统一接：

```bash
node scripts/agent-design/integrate.cjs      # 接线（可重复执行，不会重复插入）
node scripts/update-manifest.cjs --write     # 重算正文哈希与篇数
node scripts/verify-articles.cjs             # 103 → 112 篇全绿
```

`integrate.cjs` 只处理「页面已生成、还没接进全站」的篇目。
