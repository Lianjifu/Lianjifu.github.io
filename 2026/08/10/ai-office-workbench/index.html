05 · 跑通 AI 办公工作台：从资料到出结果

发表于 2026-08-10 分类于 AI Agent 学习笔记 · 05 跑通 · 场景工作台

开篇 · 数字员工上线了，人还在五个窗口里打工

00 / 真实案例

能力在后台，入口还在散落窗口。工作台要解决的是：在一个现场里，把资料变成可消费的结果。

1. 承接上一层

04 里，ToB 产品组已经把「项目协同」数字员工装上平台：岗位说明书、会议到周报流程、权限矩阵、五指标都齐了。上线第三周，项目经理小陈的吐槽却很具体——「员工在后台很勤快，我还是要把纪要复制到 Word、再粘到 Excel、再手动建日历、周五再熬夜做周报。」

2. 五窗口时间线

时间发生了什么缺口
平台上线日数字员工能写纪要草稿、标逾期小陈仍在聊天窗里复制粘贴
会后当晚草稿在对话里，台账在网盘，日历靠脑子产物进不了工作流
周五例会前通宵拼 PPT；逾期条靠人工筛表链路每步断在「人肉搬运」
复盘结论：问题不在能力，在入口与链路缺工作台：同一现场完成理解→执行→校验

3. 本篇边界与主线

本篇用小陈跑通「一场评审会 → 一套办公成果」：读懂资料、加工内容、推动执行、完成交付。不重讲岗谱（04），不讲 Agent 机制（02）。

案例主线：多窗口痛苦 → 工作台入口 → 三层分工 → 会议到周报链路 → 任务五要素 → Word / Excel / PPT → 会议协同 → 权限入口 → 人机共作验收 → 一场会六步切片。

Part 01 · 工作台：把零散信息带进同一现场

01 / 入口

小陈要的不是「再问一个问题」，而是「完成一项办公任务」。终点是工作流里的产物，不是对话框里的一段话。

1. 多窗口 vs 同现场

过去（多窗口）工作台（目标态）
输入录音在会议软件、纪要在聊天、台账在网盘纪要草稿 / 台账 / 邮件一次性拖进工作区
过程人肉复制粘贴、靠记忆提醒理解 → 执行 → 校验，进度可见
输出聊天窗里一段「看起来对」的文字直接写入 Word / Excel / 日历 / PPT
沉淀每次从零找模板模板、历史周报、台账留在工作区

2. 入口三步：理解 · 执行 · 校验

  1. 理解：识别本场评审的目标、决策与待办；歧义先标出，不假装懂了
  2. 执行：调用已授权连接器——生成初稿、写台账候选行、建日历提醒
  3. 校验：缺负责人 / 截止则拦住；禁止静默「完成」
人

判断与授权

确认例外、拍板口径、点高风险闸。

AI

整理与推进

结构化、批量写入、标逾期、出草稿。

3. 入口自检

  1. 产物是否离开对话框、进入 Word/Excel/日历？否 → 还在聊天壳。
  2. 缺字段时是否可见阻塞，而不是假完成？否 → 补校验闸。
  3. 下次开工能否复用本项目模板与台账？否 → 工作区未沉淀。
这一幕带走：工作台是同一现场，不是又一个聊天窗。终点是进入工作流的产物。

Part 02 · 先分清：工作台 · Agent · 数字员工

02 / 边界

三个词混用，需求评审必开偏。先钉：入口层问什么、不做什么。

1. 边界对照表

层核心问题案例里谁负责本篇不做什么
工作台（本篇）员工怎么用？小陈：选项目、丢资料、确认、接管不重新设计岗谱
Agent 能力能力如何构建？理解 / 工具 / 校验等可复用能力不重讲原理课
数字员工平台岗位如何持续交付？项目协同岗的职责、权限、指标不重复 04 配置细节

2. 选型口令（纠偏一句话）

错

混用

「把 Agent 做进工作台，顺便把岗位也改了。」→ 三层一起改，评审发散。

对

钉入口

「平台岗已定；本轮只做小陈怎么在一个入口里完成会议到周报。」

口令：工作台负责使用；Agent 负责能力；数字员工负责岗位交付。
这一幕带走：本篇只设计入口与场景共作；岗谱与机制课各回各层。

Part 03 · 价值在链路上：会议到周报每步留产物

03 / 链路

关键变化不是「生成更多文字」，而是让信息进入任务、日程、台账和汇报——且每步可被下一步直接消费。

1. 标准链走读

  1. 输入：本场评审录音转写 + 当前项目台账
  2. 理解：决策 / 待办 / 风险（结构化字段，不是散文）
  3. 生成：结构化纪要 + 台账候选行
  4. 协同：确认后写任务、建日历提醒
  5. 交付：周五汇总进周报页（待确认再分享）

2. 每步产物必须可消费

步骤本步产物下一步如何消费断点信号
理解决策/待办/风险字段生成纪要段落与台账行只有大段摘要，无字段
生成纪要 + 候选行映射负责人/截止写入台账待办无法映射台账列
协同Task ID + 日历提醒D-1 点对点通知只发群消息，无 Task
交付周报页（带来源）例会讨论与下周跟进图表手填、无台账链接
干货：纪要里「待办」若不能映射台账字段，链路在生成步就断了——后面再漂亮也是废稿。

3. 断点自检

  1. 任意一步输出能否被机器或下一人直接用？否 → 补字段契约。
  2. 停在聊天窗的「漂亮总结」是否被当成交付？是 → 不算跑通。
  3. 周五周报数字是否全部可点回台账？否 → 交付断。
这一幕带走：完整链路让输出进现场；停在聊天窗口里的再漂亮也算没交付。

Part 04 · 任务表达：工作台表单，不是空白对话框

04 / 任务

「帮我做周报」必然翻车。五要素写不满，工作台不开跑。

1. 翻车对照

空白对话框（v0）五要素任务卡（定稿）
输入「帮我做周报」目标 / 资料 / 输出 / 约束 / 验收齐全
产出漂亮但无法对台账PPT 页可回溯到 Tasks sheet
风险外发、编造进度禁外发；未决议不得写成已完成

2. 五要素卡片

目标完成什么
资料依据哪些文件
输出什么格式
约束规则与禁区
验收什么算完成
【工作台任务卡 · 本周项目周报】 目标：生成本周项目周报，供周五例会使用 资料：本周 3 份会议纪要 + 项目台账 sheet「Tasks」 输出：PPT（进展/风险/逾期/下周）+ 可编辑备注 约束：不外发；不改台账结构；未决议不写成已完成 验收：数据有来源；逾期任务与台账一致；下一步有负责人 规则：五要素任一空 → 状态=blocked，不开生成。
硬规则：写不满不开跑。逼人补资料与验收，比事后改废稿便宜一个数量级。
这一幕带走：任务越具体，资料、工具、交付越容易对齐。空白对话框是翻车入口。

Part 05 · Word：把会开成可核对的正式纪要

05 / Word

正式纪要强制五段核对。缺字段拦截；未决不得混进决策。

1. 产物与能力

小陈要的产物工作台能力放行标准
评审纪要、变更说明、会后通知草稿 提炼结构 · 套模板 · 标未决 · 禁推测当事实 五段齐全；未决单独成段

2. 五段核对模板

事实

发生了什么

可核对的陈述；带来源句或转写锚点。

决策

已拍板项

仅写入明确确认的结论；禁止「可能」混入。

负责人

谁执行

每人名可映射台账；空名则阻塞。

截止 / 未决

何时 · 未定

截止进日历；未决单独成段，不得进「决策」。

案例坑：第一版把「可能下周上线」写成「已确认下周上线」。校验：未决事项单独成段，不得进入「决策」列表。

3. 缺字段拦截

  1. 待办缺负责人或截止 → 状态=待补全，@会议发起人；不写「已分派」。
  2. 决策段出现「可能/预计/或许」→ 打回，要求移到未决或补确认证据。
  3. 对外分发前 → 强制人工确认门（与 Part 09 联动）。
这一幕带走：Word 负责说清楚；说清楚 ≠ 可以写假确认。

Part 06 · Excel：台账要能回答「谁该跟进」

06 / Excel

填满表格不是终点；能支撑下一步决策才有价值。

1. 冻结字段

项目组冻结台账列：任务 · 负责人 · 截止时间 · 状态 · 风险 · 下一步 · 来源会议。少一列，协同与周报都会漂。

处理数据（后台）输出判断（工作台侧栏）
清洗字段 · 补公式 · 统计进度 · 标逾期 · 出简图 哪些卡住？谁要跟进？哪些风险上升？下周重点？

2. 填满 ≠ 能决策

错

漂亮空表

列都填了，但侧栏答不出「谁该跟进」——还要人肉筛。

对

判断入口

小陈周五打开：侧栏直接「逾期 4 条 / 缺负责人 1 条」，可点进任务。

这一幕带走：台账联动的是判断与行动，不是另存一份漂亮表格。

Part 07 · PPT：周报要能让人行动

07 / PPT

交付标准不是好看，是团队听得懂、下一步有人。无人名的「下一步」标红，禁止一键分享。

1. 行动页工序

  1. 提炼：本周主线（例如：认证合入阻塞）
  2. 结构：进展 → 问题 → 风险 → 下周
  3. 图表：闭环率 / 逾期来自台账，禁止手填
  4. 表达：听众是项目组，不写空话
  5. 交付：讲稿备注 + 待确认后分享

2. 验收：踢掉「好看」

不进验收必须过
版式炫、动画多、文案像人写数据有来源 · 结论有依据 · 页面有重点 · 下一步有负责人
硬闸：周报页上的「下一步」若无人名，工作台标红，不允许一键分享。
这一幕带走：周报是行动页，不是审美展。无人接的下一步等于没交付。

Part 08 · 会议协同：纪要只是中间产物

08 / 协同

真正目标是推动负责人按时完成行动。提醒与升级要在共作面上可见、可点、可留痕。

1. 从纪要到行动链

  1. 提炼：决定 / 待办 / 风险
  2. 创建：任务 / 负责人 / 截止（写入台账 + 日历）
  3. 提醒：D-1 点对点通知负责人
  4. 升级：逾期 24h → 项目经理（带升级包）
  5. 汇总：进入周报风险清单

2. 工作台如何露出

提醒

点对点

默认通知负责人本人；群发需确认门。

升级

带完整包

Task ID · 来源会 · 已尝试 · 证据 · 建议选项——禁止「你看下」。

干货：协同关键不是自动群发，而是信息到达正确的人、正确的时间。平台定义升级策略；工作台负责呈现在共作面。
这一幕带走：纪要只是中间产物；没有负责人行动链，会议没闭环。

Part 09 · 资料与权限：入口上的闸，不是事后追责

09 / 权限

接入 Word / Excel / 日历 ≠ 可以随意修改和发送。闸做在入口，审计当场可见。

1. 入口闸矩阵

动作工作台表现审计
写本项目纪要 / 台账直接执行谁、何时、改了哪行
生成周报 PPT预览 → 人工确认 → 分享确认人与版本号
外发客户、改权限、审批承诺按钮灰置或强制升级人工拦截原因留痕
误操作可撤回至上一检查点撤回前后快照

2. 入口四件套

最小权限只开本项目需要的连接器
确认门高危默认禁外发
审计可见侧栏可查近次操作
可撤回检查点一键回滚
原则：权限策略在平台定；确认、审计、撤回必须做进工作台入口——事后追责救不回已外发的文件。
这一幕带走：闸在入口。没矩阵就接通生产写权限，等于给幻觉开绿灯。

Part 10 · 共作面：AI 推进，人授权，结果可验收

10 / 共作

低风险自动；高风险保留人工；最后用业务结果验收——不看「聊得顺不顺」。

1. 三区责任

AI整理 · 批量生成 · 标逾期 · 提醒 · 出草稿
共同例外判断 · 方案确认 · 风险是否升级 · 结果复核
人对外口径 · 审批 · 权限 · 最终责任

2. 低风险 / 高风险

类型示例工作台行为
低风险套模板出纪要草稿、标逾期、侧栏汇总自动推进，进度可见
高风险外发、改权限、对外承诺、群发停自动，等人点确认门

小陈每场会后勾选：内容准确 · 数据正确 · 格式合规 · 责任清晰 · 任务可继续

升级不是失败，是企业级人机协作的一部分——工作台上升级节点必须可见、可点、可留痕。

3. 共作面自检

  1. 人能否看见「卡在哪、谁确认、证据在哪」？不能 → 共作面未完成。
  2. 验收是否落到业务结果（台账闭环、提醒 SLA）？否 → 还在看聊天流畅度。
这一幕带走：共作面要让人看见卡点、确认人与证据；用结果验收，不用「感觉顺」。

Part 11 · 实战：一场评审会变成一套成果

11 / 闭环切片

小陈用工作台跑完一场会的标准六步——可复制的工作台切片。四个产物要能被下一周继续消费。

1. 六步切片

01 输入转写 + 台账
02 纪要决策/待办/风险/未决
03 台账负责人·截止·状态
04 提醒日历 + 点对点通知
05 周报进展/风险/下周（待确认）
06 验收事实·权限·标准勾选
Word 纪要五段齐全
Excel 台账可回答谁跟进
日历任务带截止与负责人
PPT 草稿下一步有人名

2. 放行 / 打回

放行打回
五要素任务卡齐全；纪要五段过校验；台账无「已分派但无人」；周报数字可点回台账；高危未静默外发 空白对话开工；未决写入决策；图表手填；下一步无人名却已分享
【工作台蓝图产物】 1. 场景×能力矩阵（会议/台账/协同/周报 × 读懂/加工/执行/交付） 2. 任务五要素入口模板 3. 共作面：指派 · 确认 · 旁路 · 接管 · 升级包 4. 「会议→周报」六步切片验收清单 终点：不是生成文件，而是工作真正向前推进。
这一幕带走：四个产物要能被下一周继续消费；一次性附件不算跑通。

结语 · 五层跑通之后

收束

小陈不再靠五个窗口拼办公；工作台把数字员工的能力接到了现场。

案例收束

入口统一、链路完整、五要素任务卡、Word / Excel / PPT 各司其职、协同进日历、权限在入口拦截、人机共作可验收。从资料到出结果，这一场会算跑通。

带走：场景×能力矩阵 · 任务五要素模板 · 六步切片清单 · 共作面原则（低风险自动 / 高风险确认）。
