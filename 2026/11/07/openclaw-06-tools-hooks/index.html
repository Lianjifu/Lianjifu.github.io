工具与钩子——执行与拦截机制

发表于2026-11-07 分类于OpenClaw 源码笔记

不可信执行原则的落地——工具调用是 LLM 与现实世界交互的桥梁，也是最大的攻击面。4 档沙箱 + 8+ 钩子拦截点构成 OpenClaw 的"执行免疫系统"。

本章全景

前面讲的都是「怎么想」，这一章讲「怎么动手」。Agent 想调用一个工具，真正执行它的不是模型，而是 Gateway 里的工具网关。

主线只有一条：Tool Proposal → 参数与范围校验 → 策略判定 → 审批 → 沙箱执行 → 结果回填。每一关都能拦下来，工具执行因此才是可控的。

钩子是这套机制里唯一可扩展的信任边界：工具决定「能做什么」，钩子决定「允许做什么」。想加审计、改参数、阻断某类动作，都挂在钩子上，不必改核心代码。

6.1 定位与原则

第一段 · 定位与原则工具是 LLM 与外部世界的桥梁，钩子是 Gateway 在不可信侧与可信侧之间建立的受控接口。

本章要点

工具是 LLM 与外部世界的桥梁，钩子是 Gateway 在不可信侧（Agent 执行）与可信侧（策略）之间建立受控接口。

6.1.2 工具层的三个原则

思考笔记

工具层最容易出的问题是「模型想干什么就干什么」。三条原则把它压住：工具必须显式声明、必须经过沙箱与策略检查、结果必须回到模型继续推理。

原则 含义
沙箱 = 不可信侧的安全护栏LLM 生成的工具调用天然不可信——提示注入、幻觉参数、链式放大。沙箱用 4 级隔离把"最坏情况的影响范围"圈在边界内。
钩子 = 唯一可扩展的信任边界不修改核心代码就能加策略、加审计、加改写、加阻断——before_tool_call 决定"能不能"，after_tool_call 决定"结果怎么处理"。
8 个决策 = 关键路径速查每个 Agent 决策路径都对应一个明确配置点——会话隔离、运行时选择、队列模式、工具钩子、压缩、流式、Prompt 分层、超时取消。

6.1.3 模块位置

思考笔记

读法三条：要加一个新工具看 3 类来源与钩子注册；要排查工具为什么被拒看沙箱与钩子链；要理解整体取舍直接看 8 个核心决策。

6.2 工具执行

第二段 · 工具执行一次工具调用要过的五道关，以及沙箱、超时、并发与重试这四道限制。

6.2.1 工具执行流程

思考笔记

工具执行流程只有一条线：模型提出 Tool Proposal → 网关校验参数与范围 → 策略判定是否放行 → 沙箱内执行 → 结果回填给模型。任何一步都能拦下来，这就是可控性的来源。

6.2.3 沙箱机制

本章要点

学习要点

  • Host Exec 的五种权限模式（deny/allowlist/ask/auto/full）分别怎样工作？
  • 执行审批的完整流程是怎样的？Safe Bins、审批规则、权限模式如何协同？
  • 运行列表（Run List）和限制参数（argPattern）如何实现精细化控制？
  • OpenClaw 内置的安全 Binaries 包含哪些类别的命令？

思考笔记

exec 工具必须 ≥ container

：Shell 执行是最高风险的工具——即使是 trusted 用户，也建议至少 container 级别，防止命令注入、文件误删。

为什么需要沙箱？

LLM 驱动的工具调用有三个根本风险：

  • 提示注入——用户消息或工具结果含恶意指令，诱导工具执行危险操作
  • 幻觉参数——模型生成错误的参数（rm -rf / 而不是 rm -rf ./build)
  • 链式放大——一个工具调用触发不可控的连锁反应

沙箱的限制"最坏情况的影响范围"——即使出了事，也只损失沙箱内的内容。

4 级沙箱

none
无隔离——完全可信工具（自研、纯函数）
process
独立进程——默认级别，大多数工具
container
容器隔离——高危工具（shell、文件写）
vm
虚拟机隔离——极高危场景（网络下载执行）
级别隔离方式启动开销适用
none无~0msread · web_search
process独立 Node 进程~50msimage · web_fetch
containerDocker / bubblewrap~500msexec · write
vmFirecracker / QEMU~3s外部代码执行

权限模式与审批

权限模式

权限模式决定 Agent 在运行主机命令、写文件或向后端请求更高权限时，需要经过什么审批。

五种模式
模式行为安全等级适合场景
deny完全禁止 host exec最高不允许任何主机命令
allowlist只运行 allowlist 中的命令高命令集合明确且固定
askallowlist 直接运行，其他弹框询问中每个新命令都要人工确认
auto allowlist 直接运行，其他自动审查中编码会话，实用且受控的访问
full不提示，直接运行低完全可信的主机和会话
推荐默认值
openclaw config set tools.exec.mode auto
openclaw approvals get
openclaw gateway restart
openclaw exec-policy show

建议从 `auto` 开始：先放行 allowlist 中确定安全的命令；没命中的走自动审查，必要时回退到人工审批。

执行审批流程

一次完整的命令执行审批经过以下步骤：

审批规则存储
~/.openclaw/approvals.json

主机命令最终会取 OpenClaw 配置和本机 `approvals.json` 中更严格的结果。

规则配置
策略类型
策略说明执行方式
auto命令自动执行，无需确认静默放行
ask每次执行前弹出确认框，由你决定等待用户交互
deny命令直接拒绝，Agent 收到通知并调整方案返回拒绝
规则示例
{
  rules: [
    { pattern: "git *", policy: "auto" },
    { pattern: "npm install *", policy: "ask" },
    { pattern: "rm -rf *", policy: "deny" },
    { pattern: "sudo *", policy: "deny" },
  ],
}
运行列表（Run List）

运行列表是预批准的命令模式集合，匹配的命令自动执行：

{
  runList: [
    "git add *",
    "git commit *",
    "npm run build",
    "npm run test",
  ],
}
限制参数：argPattern

允许命令但限制参数范围：

{
  version: 1,
  agents: {
    main: {
      allowlist: [
        { pattern: "python3", argPattern: "^safe\\.py$" },
        { pattern: "cat", argPattern: "^/workspace/.*\\.(md\|txt)$" },
      ],
    },
  },
}
安全 Binaries（Safe Bins）

OpenClaw 内置的安全命令白名单，这些命令自动放行，无需审批：

类别命令说明

6.2.4 执行器实现

思考笔记

执行器是「工具声明」和「真实动作」之间的翻译层：同一份 Schema，落到 Shell、容器、浏览器还是 HTTP，差别只在执行器。

// 工具执行器伪代码
async function executeTool(name, params, ctx) {
  // 1. 解析工具
  const tool = registry.get(name);
  if (!tool) return { error: `Unknown tool: ${name}` };

  // 2. 钩子拦截(before)
  const beforeResult = await runHook("before_tool_call", {
    tool, params, session: ctx.session
  });
  if (!beforeResult.allow) {
    return { error: beforeResult.reason || "Permission denied" };
  }
  params = beforeResult.params || params;  // 可改写参数

  // 3. 沙箱创建与执行
  const sandbox = sandboxFactory.create(tool.sandboxLevel);
  let result;
  try {
    result = await sandbox.run(
      () => tool.execute(params, ctx),
      {
        timeoutMs:  tool.timeoutMs || 30000,
        memoryMb:   tool.memoryMb  || 512,
        netPolicy:  tool.networkPolicy
      }
    );
  } catch (err) {
    return { error: err.message, timeout: err.code === "ETIMEOUT" };
  }

  // 4. 结果钩子(after)
  const afterResult = await runHook("after_tool_call", {
    tool, params, result
  });
  return afterResult.result || result;
}

6.2.5 超时控制

思考笔记

超时后

：工具被 kill，返回 { error: "Timeout exceeded", timeout: true } 给 LLM——LLM 可重试或选择其他工具。

每个工具有自己的默认超时，防止失控占用资源：

工具类型默认超时可配置
文件操作（read、write)5s是
网络请求（web_fetch)30s是
Shell 命令（exec)60s是
长时间任务（自定义）5min是
图像理解（image)30s否
 
{
  tools: {
    exec: {
      timeoutMs: 60000,              // 60s
      memoryMb: 512,                // 512MB
      networkPolicy: "deny-all"     // 禁止网络
    },
    web_fetch: {
      timeoutMs: 30000,
      domainAllowlist: ["docs.example.com", "*.wikipedia.org"]
    }
  }
}

6.2.6 并发 · 结果限制 · 重试

思考笔记

设计哲学

：工具结果给 LLM 是"上下文"，不是"原始数据"——超大的结果应该写到文件，只让 LLM 看路径。

并发控制

OpenClaw 默认 串行 执行工具调用——避免竞态与依赖问题：

  • 同一会话内串行——保证状态一致性
  • 不同会话可并行——Gateway 调度多个 Runtime
  • 显式并行——工具声明 parallel: true 才并发
{
  tools: {
    web_fetch: {
      parallel: true,      // 多个 web_fetch 可并发
      maxConcurrency: 5   // 最多 5 个并发
    },
    exec: {
      parallel: false       // shell 必须串行
    }
  }
}

结果大小限制

为防止 LLM 上下文爆炸，工具结果有大小限制：

类型限制超出处理
文本最大 100KB截断 + [truncated: ...]
JSON最大 100K tokens截断字段 + 摘要
图像最大 5MB / 张缩略图 + 路径
媒体（视频/音频）不内联仅返回路径
二进制不内联Base64 仅小文件

重试与降级

工具失败时的默认行为：

  • 网络错误——自动重试 2 次（指数退避）
  • 超时——不重试，直接返回错误
  • 权限拒绝——不重试，让 LLM 换工具
  • 沙箱崩溃——重试 1 次（可能是偶然）
{
  tools: {
    web_fetch: {
      retry: {
        maxAttempts: 3,
        backoffMs: 1000,
        retryOn: ["ETIMEDOUT", "ECONNRESET"]
      }
    }
  }
}

6.3 钩子拦截

第三段 · 钩子拦截钩子挂在 Agent 生命周期、工具调用与内部命令三类点上，是唯一可扩展的信任边界。

6.3.1 3 大类钩子

思考笔记

最重要的两个钩子

:before_tool_call 决定"能不能调"，after_tool_call 决定"结果怎么处理"。所有安全策略都从这两个钩子落地。
类别 1 · AGENT

6.3.2 钩子注册

思考笔记

钩子在插件里用 api.on() 注册，注册的是「事件 + 处理函数」。要做的不是写钩子，而是知道该在哪个事件上挂——Agent 生命周期、Tool 调用、Command 三类。

钩子在插件中通过 api.on() 注册：

// plugin.ts — 一个完整的安全审计插件
export default {
  id: "audit-plugin",
  type: "tool",
  register(api) {

    // 前置钩子:审计 + 阻断 + 改写
    api.on("before_tool_call", async (ctx) => {
      const { tool, params, session } = ctx;

      // 1. 审计日志
      logger.info("tool_call", {
        tool: tool.name, params, user: session.peer, trust: session.trustLevel
      });

      // 2. 阻断 — 非管理员不能调 shell
      if (tool.name === "exec" && session.trustLevel !== "TRUSTED") {
        return { allow: false, reason: "Admin only" };
      }

      // 3. 改写参数 — 强制时区
      if (tool.name === "calendar.list_events") {
        return {
          allow: true,
          params: { ...params, tz: session.userTimezone || "Asia/Shanghai" }
        };
      }

      return { allow: true };
    });

    // 后置钩子:脱敏 API Key
    api.on("after_tool_call", async (ctx) => {
      const { result } = ctx;
      if (typeof result === "string" && result.includes("sk-")) {
        return { result: result.replace(/sk-[a-zA-Z0-9]+/g, "sk-***") };
      }
      return { result };
    });

    // Agent 钩子:自动写入审计摘要
    api.on("agent_end", async (ctx) => {
      await auditLog.write({
        sessionId: ctx.sessionId,
        messages: ctx.messages.length,
        tokens: ctx.metrics.totalTokens,
        duration: ctx.metrics.duration
      });
    });
  }
};

6.3.3 返回值约定 + 钩子链

思考笔记

阻断语义

：只有 before_* 钩子能返回 { allow: false }。after_* 钩子只是"数据加工"，不能改变"是否执行"的决定。

要点

LIFO 后置

：前置钩子按 1→2→3 顺序执行（注册顺序），后置钩子按 3→2→1 反向执行——这样后置钩子的处理顺序与前置钩子的拦截顺序"配对"。

返回值约定

每个钩子有约定的返回值——不返回值或返回 undefined 等于"放行"。

钩子返回值
before_tool_call{ allow: bool, reason?, params? }
after_tool_call{ result }
before_model_resolve{ provider?, model? }
before_prompt_build{ context? }
before_agent_reply{ messages? }
agent_end{ messages? }

钩子链执行

多个钩子按注册顺序链式执行——任何一个返回 allow: false，后续钩子和工具执行都被跳过：

6.3.4 调试技巧 · 钩子 vs 中间件

思考笔记

设计选择

：OpenClaw 选钩子而非中间件——因为 LLM 调用是"任务级"，不是"请求级"。钩子让你能在"完整任务"的视角下决策。

调试技巧

OpenClaw 提供 CLI 调试钩子：

# 列出所有已注册钩子
openclaw hooks list

# 查看特定钩子的调用历史
openclaw hooks log --name before_tool_call --limit 50

# 临时禁用某个钩子
openclaw hooks disable my-plugin:before_tool_call

# 启用
openclaw hooks enable my-plugin:before_tool_call

# 实时跟踪钩子调用
openclaw hooks trace --name after_tool_call --follow

钩子 vs 中间件

差异钩子中间件
时机离散事件点请求/响应链
粒度粗（几个关键时刻）细（每个调用）
上下文任务级（整个会话）请求级（单次请求）
适合业务逻辑扩展通用拦截
OpenClaw 用钩子不提供

6.4.1 8 个核心决策

思考笔记

8 个决策是理解整个系统的关键节点：会话隔离、运行时选择、队列模式、工具钩子、压缩触发、流式策略、提示词分层、超时与取消。读到这里，OpenClaw 的取舍就不再是零散的了。

如果只能记住一节 OpenClaw 文档，就是这一节。8 个决策是理解整个系统的"关键节点"。

DECISION 1 · 阶段 2 网关路由

1⃣ 会话隔离策略

配置位置:session.dmScope

影响阶段：阶段 2（网关路由）——消息如何归类到哪个会话

值行为
main所有 DM 共享主会话
per-peer按发送者隔离
per-channel-peer按通道+发送者隔离
per-account-channel-peer按账户+通道+发送者隔离
 
{
  session: {
    dmScope: "per-account-channel-peer"  // 最严格隔离
  }
}
DECISION 2 · 阶段 3 Agent 循环启动

2⃣ 运行时选择

配置位置：模型级 → Provider 级 → auto → fallback（4 级回退）

影响阶段：阶段 3（Agent 循环启动）——用哪个模型

{
  agents: {
    research: {
      model: "anthropic/claude-sonnet-4"     // Level 1(最高优先级)
    },
    auto: {
      strategy: "cost-quality-balanced"     // 自动选模型
    }
  },
  fallback: {
    chain: ["anthropic/claude-sonnet-4", "openai/gpt-4o", "ollama/llama3.1-70b"]
  }
}
DECISION 3 · 阶段 2/3 路由与启动

3⃣ 队列模式

配置位置:queue.mode

影响阶段：阶段 2 网关路由 / 阶段 3 循环启动——新消息到达时怎么处理

模式行为风险
steer （默认）注入到当前运行时可能干扰当前思考
followup排队等待当前完成延迟感知
collect合并多条消息用户连续发时合并
interrupt中止当前，运行新消息浪费 token
 
{
  queue: {
    mode: "steer",                       // 默认
    collectWindowMs: 1500           // collect 模式窗口
  }
}
DECISION 4 · 阶段 6 工具执行 · 核心安全门

4⃣ 工具钩子

配置位置：插件注册 before_tool_call / after_tool_call

影响阶段：阶段 6（工具执行）——安全策略的落地点

核心规则:

  • 任何一个钩子返回 { allow: false }，后续钩子和工具执行都被跳过
  • 钩子链按注册顺序执行（前置），反向执行（后置 LIFO）
  • 钩子是 OpenClaw 安全模型的核心——所有信任边界都在这里实现
{
  plugins: [
    {
      id: "security",
      hooks: {
        before_tool_call: "./hooks/audit.ts",
        after_tool_call:  "./hooks/sanitize.ts"
      }
    }
  ]
}
DECISION 5 · 阶段 7 流式输出与持久化

5⃣ 压缩触发

配置位置:compaction.threshold

影响阶段：阶段 7——控制上下文大小

  • 超过 N 轮后自动调用 compactTranscript
  • 把较早回合摘要归档
  • 让活跃上下文保持在窗口限制内
{
  compaction: {
    threshold: 50,             // 50 轮后触发压缩
    summaryMaxTokens: 500,
    keepRecent: 10             // 保留最近 10 轮完整
  }
}

6⃣ 流式策略

配置位置：通道插件 streaming 选项

影响阶段：阶段 7 → 阶段 8（通道回复）——如何把 LLM 输出展示给用户

模式行为适用
block最终块流式发送大多数通道

7⃣ 提示词分层

配置位置:agents.defaults.systemPrompt + bootstrap files

影响阶段：阶段 4——Prompt 怎么组装

8 层叠加:

  1. basePrompt——基础角色
  2. skills snapshot——技能上下文
  3. bootstrap files——启动文件
  4. memory context——长期记忆
  5. history——对话历史
  6. session context——会话上下文
  7. per-run overrides——本次运行覆盖

DECISION 8 · 贯穿所有阶段

8⃣ 超时与取消

配置位置:agents.defaults.timeout

影响阶段：贯穿所有阶段——防止失控

类型默认作用
agent.wait30s用户消息后等待 LLM 启动
Agent 运行时48h整个任务最长
模型空闲（云端）120s流式 token 间隔
模型空闲（本地）300s本地模型更宽容
工具执行5-300s每个工具的 deadline

{
  agents: {
    defaults: {
      timeout: {
        agentMs: 172800000,       // 48h
        idleMs: 120000,            // 2min(云端)
        toolMs: 60000              // 1min(默认工具)
      }
    }
  }
}

4 个设计哲学

OpenClaw 的所有设计决策都遵循以下 4 个原则：

原则含义实例
声明式策略在 config 中声明，不在代码中硬编码DM 策略、超时、压缩阈值
可恢复大部分错误有降级路径，而非直接失败fallback chain、自动重试
可观测所有关键事件都推送，便于调试events 表、metrics、hooks log
可扩展通过插件扩展，而非堆叠配置50+ 插件、钩子机制

6.5 总结

收束 · 本章结论把工具层的判断收成几条结论，并交代下一章的接口。

6.5.1 一句话总结

思考笔记

工具 = 3 类来源 × 4 级沙箱 × 5 类超时 × 显式并发——钩子 = 唯一可扩展的信任边界——8 个决策 = 关键路径速查。



安全默认：exec → container、并行默认关闭、超时必设、结果必截断；钩子默认审计、不阻断。

6.5.2 本章结论

  1. 工具与钩子是两种不同的东西。工具扩展「能做什么」，钩子决定「允许做什么」——钩子是唯一可扩展的信任边界。
  2. 一次工具调用要过五关：参数校验、范围匹配、策略判定、审批、沙箱执行。任何一关都能拦下来，可控性就来自这里。
  3. 默认串行执行是有意的。并行会引入竞态，依赖型工具调用会拿到错乱的结果；真要并行，得显式声明无依赖。
  4. 沙箱四级的差别是隔离强度，不是功能多少。能用更弱的隔离就别用更强的——隔离越强，调试越难。
  5. 超时、结果大小、并发、重试这四项限制，决定了工具调用在生产环境会不会失控。
