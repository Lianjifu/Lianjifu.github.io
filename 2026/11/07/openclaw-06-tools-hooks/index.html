工具执行与钩子拦截

发表于2026-11-07 分类于OpenClaw 源码笔记

不可信执行原则的落地——工具调用是 LLM 与现实世界交互的桥梁，也是最大的攻击面。4 档沙箱 + 8+ 钩子拦截点构成 OpenClaw 的"执行免疫系统"。

§ 1一句话定位

§ 2工具层的三个原则

沙箱 = 不可信侧的安全护栏
LLM 生成的工具调用天然不可信——提示注入、幻觉参数、链式放大。沙箱用 4 级隔离把"最坏情况的影响范围"圈在边界内。
钩子 = 唯一可扩展的信任边界
不修改核心代码就能加策略、加审计、加改写、加阻断——before_tool_call 决定"能不能"，after_tool_call 决定"结果怎么处理"。
8 个决策 = 关键路径速查
每个 Agent 决策路径都对应一个明确配置点——会话隔离、运行时选择、队列模式、工具钩子、压缩、流式、Prompt 分层、超时取消。

§ 6沙箱机制

§ 6.1为什么需要沙箱？why

LLM 驱动的工具调用有三个根本风险：

  • 提示注入——用户消息或工具结果含恶意指令，诱导工具执行危险操作
  • 幻觉参数——模型生成错误的参数（rm -rf / 而不是 rm -rf ./build)
  • 链式放大——一个工具调用触发不可控的连锁反应

沙箱的限制"最坏情况的影响范围"——即使出了事，也只损失沙箱内的内容。

§ 6.24 级沙箱levels

none
无隔离——完全可信工具（自研、纯函数）
process
独立进程——默认级别，大多数工具
container
容器隔离——高危工具（shell、文件写）
vm
虚拟机隔离——极高危场景（网络下载执行）
级别隔离方式启动开销适用
none无~0msread · web_search
process独立 Node 进程~50msimage · web_fetch
containerDocker / bubblewrap~500msexec · write
vmFirecracker / QEMU~3s外部代码执行
exec 工具必须 ≥ container：Shell 执行是最高风险的工具——即使是 trusted 用户，也建议至少 container 级别，防止命令注入、文件误删。

§ 6.3.1权限模式

权限模式决定 Agent 在运行主机命令、写文件或向后端请求更高权限时，需要经过什么审批。

§ 6.3.2 五种模式

模式行为安全等级适合场景
deny完全禁止 host exec最高不允许任何主机命令
allowlist只运行 allowlist 中的命令高命令集合明确且固定
askallowlist 直接运行，其他弹框询问中每个新命令都要人工确认
auto allowlist 直接运行，其他自动审查中编码会话，实用且受控的访问
full不提示，直接运行低完全可信的主机和会话

openclaw gateway restart

§ 7执行器实现

// 工具执行器伪代码
async function executeTool(name, params, ctx) {
  // 1. 解析工具
  const tool = registry.get(name);
  if (!tool) return { error: `Unknown tool: ${name}` };

  // 2. 钩子拦截(before)
  const beforeResult = await runHook("before_tool_call", {
    tool, params, session: ctx.session
  });
  if (!beforeResult.allow) {
    return { error: beforeResult.reason || "Permission denied" };
  }
  params = beforeResult.params || params;  // 可改写参数

  // 3. 沙箱创建与执行
  const sandbox = sandboxFactory.create(tool.sandboxLevel);
  let result;
  try {
    result = await sandbox.run(
      () => tool.execute(params, ctx),
      {
        timeoutMs:  tool.timeoutMs || 30000,
        memoryMb:   tool.memoryMb  || 512,
        netPolicy:  tool.networkPolicy
      }
    );
  } catch (err) {
    return { error: err.message, timeout: err.code === "ETIMEOUT" };
  }

  // 4. 结果钩子(after)
  const afterResult = await runHook("after_tool_call", {
    tool, params, result
  });
  return afterResult.result || result;
}

§ 8超时控制

每个工具有自己的默认超时，防止失控占用资源：

工具类型默认超时可配置
文件操作（read、write)5s是
网络请求（web_fetch)30s是
Shell 命令（exec)60s是
长时间任务（自定义）5min是
图像理解（image)30s否
 
{
  tools: {
    exec: {
      timeoutMs: 60000,              // 60s
      memoryMb: 512,                // 512MB
      networkPolicy: "deny-all"     // 禁止网络
    },
    web_fetch: {
      timeoutMs: 30000,
      domainAllowlist: ["docs.example.com", "*.wikipedia.org"]
    }
  }
}
超时后：工具被 kill，返回 { error: "Timeout exceeded", timeout: true } 给 LLM——LLM 可重试或选择其他工具。

§ 9并发 · 结果限制 · 重试

§ 9.1并发控制parallel

OpenClaw 默认 串行 执行工具调用——避免竞态与依赖问题：

  • 同一会话内串行——保证状态一致性
  • 不同会话可并行——Gateway 调度多个 Runtime
  • 显式并行——工具声明 parallel: true 才并发
{
  tools: {
    web_fetch: {
      parallel: true,      // 多个 web_fetch 可并发
      maxConcurrency: 5   // 最多 5 个并发
    },
    exec: {
      parallel: false       // shell 必须串行
    }
  }
}

§ 9.2结果大小限制limits

为防止 LLM 上下文爆炸，工具结果有大小限制：

类型限制超出处理
文本最大 100KB截断 + [truncated: ...]
JSON最大 100K tokens截断字段 + 摘要
图像最大 5MB / 张缩略图 + 路径
媒体（视频/音频）不内联仅返回路径
二进制不内联Base64 仅小文件
设计哲学：工具结果给 LLM 是"上下文"，不是"原始数据"——超大的结果应该写到文件，只让 LLM 看路径。

§ 9.3重试与降级retries

工具失败时的默认行为：

  • 网络错误——自动重试 2 次（指数退避）
  • 超时——不重试，直接返回错误
  • 权限拒绝——不重试，让 LLM 换工具
  • 沙箱崩溃——重试 1 次（可能是偶然）
{
  tools: {
    web_fetch: {
      retry: {
        maxAttempts: 3,
        backoffMs: 1000,
        retryOn: ["ETIMEDOUT", "ECONNRESET"]
      }
    }
  }
}

§ 11钩子注册

钩子在插件中通过 api.on() 注册：

// plugin.ts — 一个完整的安全审计插件
export default {
  id: "audit-plugin",
  type: "tool",
  register(api) {

    // 前置钩子:审计 + 阻断 + 改写
    api.on("before_tool_call", async (ctx) => {
      const { tool, params, session } = ctx;

      // 1. 审计日志
      logger.info("tool_call", {
        tool: tool.name, params, user: session.peer, trust: session.trustLevel
      });

      // 2. 阻断 — 非管理员不能调 shell
      if (tool.name === "exec" && session.trustLevel !== "TRUSTED") {
        return { allow: false, reason: "Admin only" };
      }

      // 3. 改写参数 — 强制时区
      if (tool.name === "calendar.list_events") {
        return {
          allow: true,
          params: { ...params, tz: session.userTimezone || "Asia/Shanghai" }
        };
      }

      return { allow: true };
    });

    // 后置钩子:脱敏 API Key
    api.on("after_tool_call", async (ctx) => {
      const { result } = ctx;
      if (typeof result === "string" && result.includes("sk-")) {
        return { result: result.replace(/sk-[a-zA-Z0-9]+/g, "sk-***") };
      }
      return { result };
    });

    // Agent 钩子:自动写入审计摘要
    api.on("agent_end", async (ctx) => {
      await auditLog.write({
        sessionId: ctx.sessionId,
        messages: ctx.messages.length,
        tokens: ctx.metrics.totalTokens,
        duration: ctx.metrics.duration
      });
    });
  }
};

§ 12返回值约定 + 钩子链

§ 12.1返回值约定return

每个钩子有约定的返回值——不返回值或返回 undefined 等于"放行"。

钩子返回值
before_tool_call{ allow: bool, reason?, params? }
after_tool_call{ result }
before_model_resolve{ provider?, model? }
before_prompt_build{ context? }
before_agent_reply{ messages? }
agent_end{ messages? }
阻断语义：只有 before_* 钩子能返回 { allow: false }。after_* 钩子只是"数据加工"，不能改变"是否执行"的决定。

§ 12.2钩子链执行chain

多个钩子按注册顺序链式执行——任何一个返回 allow: false，后续钩子和工具执行都被跳过：

LIFO 后置：前置钩子按 1→2→3 顺序执行（注册顺序），后置钩子按 3→2→1 反向执行——这样后置钩子的处理顺序与前置钩子的拦截顺序"配对"。

§ 13.2钩子 vs 中间件middleware

差异钩子中间件
时机离散事件点请求/响应链
粒度粗（几个关键时刻）细（每个调用）
上下文任务级（整个会话）请求级（单次请求）
适合业务逻辑扩展通用拦截
OpenClaw 用钩子不提供
设计选择：OpenClaw 选钩子而非中间件——因为 LLM 调用是"任务级"，不是"请求级"。钩子让你能在"完整任务"的视角下决策。

DECISION 4 · 阶段 6 工具执行 · 核心安全门

§ 14.4 4⃣ 工具钩子

配置位置：插件注册 before_tool_call / after_tool_call

影响阶段：阶段 6（工具执行）——安全策略的落地点

}

配置位置:compaction.threshold

影响阶段：阶段 7——控制上下文大小

  • 超过 N 轮后自动调用 compactTranscript

§ 14.8 8⃣ 超时与取消

配置位置:agents.defaults.timeout

    }
  }

§ 15.24 个设计哲学philosophy

OpenClaw 的所有设计决策都遵循以下 4 个原则：

原则含义实例
声明式策略在 config 中声明，不在代码中硬编码DM 策略、超时、压缩阈值
可恢复大部分错误有降级路径，而非直接失败fallback chain、自动重试
可观测所有关键事件都推送，便于调试events 表、metrics、hooks log
可扩展通过插件扩展，而非堆叠配置50+ 插件、钩子机制
这 4 条不是空话：每个核心决策都能对应到至少一条——比如会话隔离 = 声明式；fallback = 可恢复；hook log = 可观测；插件机制 = 可扩展。

§ 16.2常见问题faq

  • 工具调用失败会怎样？
    默认返回错误给 LLM，LLM 可重试或换工具。超时（默认 30s）会自动 kill。
  • 如何限制某个用户不能调 shell？
    在 before_tool_call 钩子里检查 session.trustLevel，非管理员返回 { allow: false }。
  • 钩子和中间件有什么区别？
    钩子是离散事件点（粗粒度、任务级）；中间件是请求/响应链（细粒度、请求级）。OpenClaw 用钩子。
  • 插件能阻止工具调用吗？
    能。任何一个钩子返回 { allow: false }，后续钩子和工具执行都被跳过。
  • exec 必须用 container 沙箱吗？
    强烈建议 ≥ container（默认 OpenClaw 也这么配）。即使 trusted 用户，Shell 仍是高风险工具，container 隔离防止命令注入、文件误删。
  • 并行执行安全吗？
    默认串行（同会话内）。需要并行必须显式声明 parallel: true + maxConcurrency。exec 永远串行。
  • 钩子性能开销大吗？
    每个钩子目标 <；5ms。审计类钩子可以异步批写日志，几乎不阻塞主流程。详见 openclaw hooks trace 实时监控。

§ 16.3一句话总结summary

工具 = 3 类来源 × 4 级沙箱 × 5 类超时 × 显式并发——钩子 = 唯一可扩展的信任边界——8 个决策 = 关键路径速查。

安全默认：exec → container、并行默认关闭、超时必设、结果必截断；钩子默认审计、不阻断。
