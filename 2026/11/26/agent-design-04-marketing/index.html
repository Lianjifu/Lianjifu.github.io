营销 Agent——从自然语言目标到可归因的触达

发表于2026-11-26 分类于AI Agent 系统设计

营销 AI Agent 接收自然语言营销目标，完成目标解析、人群圈选、物料生成、合规审核、延迟调度、实时状态复核、原子频控、幂等下发、增量归因与策略调优。它和客服 Agent 的根本差别在方向：客服是响应式的，用户先来系统再答；营销是主动式的，系统先决定打扰谁再去打扰。难点不在生成文案，而在「高并发下不发错、不超发、不违规、不算错」。本章围绕目标解析与动态分群、千人千面与合规、触达放大与频控阈值、增量归因与降级矩阵展开。

4.1 营销 Agent 是什么

第一段 · 营销 Agent 是什么这一段回答：营销 Agent 究竟是什么、给谁用、边界划在哪里，以及哪些决策一旦做错就要停机迁移。

4.1.1 定义与营销闭环七段

本章要点

营销 AI Agent 接收自然语言营销目标（例如「对加购未支付用户做 30 分钟召回，预算 5 万，增量 ROI 不低于 3」），完成目标解析、人群圈选、物料生成、合规审核、延迟调度、实时状态复核、原子频控、幂等下发、增量归因与策略调优。它和客服 Agent 的根本差别在方向：客服是响应式的，用户先来系统再答；营销是主动式的，系统先决定打扰谁再去打扰。闭环七段是目标解析、人群圈选、策略与物料、合规审核、调度触达、行为归因、策略调优。

思考笔记

「主动式的系统天生带着放大能力」这句话是全章的地基：客服的一次误判最多害了一个用户，营销的一次误判会复制到百万人的手机里。所以营销的第一性问题不是「怎么做得更准」，而是「一次决策最多能放大到多少」——这个数必须先算出来，再谈链路怎么搭。

定义：营销 AI Agent 是面向增长场景的智能体系统。它接收自然语言营销目标（如「对加购未支付用户做 30 分钟召回，预算 5 万，ROI ≥ 3」），完成目标解析、人群圈选、物料生成、合规审核、延迟调度、实时状态复核、原子频控、幂等下发、增量归因与策略调优。

它和客服 Agent 的根本差别在于方向：客服是响应式的——用户先来，系统再答；营销是主动式的——系统先决定打扰谁，再去打扰。主动式的系统，天生带着放大能力：客服的一次误判最多害了一个用户，营销的一次误判会复制到百万人的手机里。

目标解析 → 人群圈选 → 策略与物料 → 合规审核 → 调度触达 → 行为归因 → 策略调优

4.1.2 与其他系统的区别与三方价值

本章要点

广告投放是竞价买量，营销 Agent 主要用自有渠道触达；CRM 管客户关系与销售流程，营销 Agent 是自动化触达闭环；营销自动化用规则流程编排，Agent 多出目标解析、生成与多臂老虎机；推荐系统做站内内容分发，营销 Agent 跨渠道主动触达；风控 Agent 的默认动作是拦截，营销 Agent 的默认动作是放行与打扰——两者的默认动作正好相反。三方价值分别是用户的不过度打扰、商家的转化与留存、平台的增长与商业化，任何一方失效都会反噬。

思考笔记

最后一行值得单独记住：营销与风控面对同一个决策时，默认动作是相反的——风控的默认值是「拦」，营销的默认值是「发」。这意味着营销系统的护栏必须是显式的、可熔断的、并且带明确预算上限的，而不是「系统里恰好有这些检查」。

4.2 核心矛盾与设计原则

第二段 · 核心矛盾这一段回答：多触达与不打扰之间的矛盾到底有多大，为什么这六条原则在冲突时说了算。

4.2.1 本质与六条章级原则

本章要点

本质矛盾是「尽可能多触达以提升 GMV」与「不能打扰、不能违规、不能资损」之间的冲突，设计原则一句话：模型负责「更优」，规则负责「不出事」。六条章级原则规定冲突时以谁为准：模型只能决定哪个变体更好、什么时候更值得发，不能决定能不能发；顺序铁律是状态复核、决策、频控扣减、下发，绝不先扣后查；宁可少发不可发错；触达量必须与错误率一起写进方案；快信号止损、慢信号调优；每一次降级都要打标。

思考笔记

「模型负责更优，规则负责出事」这句话是本章最省事的判据。落到日常争论上，它能一刀切开大多数分歧：要不要换更大的模型，是「更优」的问题，可以讨论；要不要在下发前查一次订单状态，是「出事」的问题，不能讨论——因为它与模型强弱无关，只与系统敢不敢放行有关。

本质：营销 Agent 的核心矛盾，是「尽可能多触达以提升 GMV」与「不能打扰、不能违规、不能资损」之间的冲突。设计原则一句话：模型负责「更优」，规则负责「不出事」。

六条章级原则（贯穿全章，冲突时以这六条为准）：

  1. 模型负责「更优」，规则负责「不出事」——模型只能决定「哪个变体更好」「什么时候更值得发」，不能决定「能不能发」。所有合规、权限、频控、预算判定必须落在确定性代码层。
  2. 顺序铁律：状态复核 → 决策 → 频控扣减 → 下发——绝不先扣后查。先扣频控再查状态，会给已付款的用户扣掉额度并发出一条催单。
  3. 宁可少发，不可发错——一次错误触达的代价是单次价值的上百倍（打扰成本与频控阈值）。少发只是少一次机会，发错是永久损失一个用户。
  4. 触达量必须与错误率一起写进方案——每次决策的放大倍数要显式算出来。「一次决策触达 564 万人」和「一次决策触达 564 人」是两个完全不同风险等级的系统，而它们在目标描述里长得一模一样。
  5. 快信号止损，慢信号调优——退订与投诉 5 分钟能发现，转化与 ROI 24 小时才能发现。慢信号永远来不及止损，只能用来调权重。
  6. 每一次降级都要打标——degraded + fallback_mode + reason_code 三件套缺一不可。不打标的降级会让效果被算成策略效果，模型会因此学到错误的因果。

4.2.2 三个不等式、四大挑战与三个放大器

本章要点

三个不等式：一次决策的触达量远大于一次决策的纠错能力，快信号检测窗 5 分钟远小于慢信号检测窗 24 小时，打扰强度远大于退订率的线性预期。四大挑战是高并发下的状态一致性与防过期触达、多维频控的原子性、千人千面多模态物料的合规性、短期点击与长期净转化的平衡。三个放大器量化代价：触达放大让一次决策复制成 564 万次打扰，资损放大让一张券错发到全量变成 100 万沉没成本，合规放大让一句违禁词进入全量文案变成 8460 次投诉。

思考笔记

三个不等式里最要命的是第一条：一次决策的触达量远大于纠错能力，所以错误必须在发出前拦住，不能靠事后修。而第二条进一步说明为什么必须前置——慢信号 24 小时才出结果，这期间一个坏策略能触达 2.5 亿次。「事后归因发现不对再改」是营销系统最贵的错误。

三个不等式：

一次决策的触达量   >>  一次决策的纠错能力     → 错误必须在发出前拦住，不能靠事后修
快信号检测窗(5min) <<  慢信号检测窗(24h)     → 止损只能靠快信号与前置护栏
打扰强度            >>  退订率的线性预期      → 频控阈值必须按退订曲线的拐点定

四大挑战：

  1. 高并发下的状态一致性与防过期触达：用户可能已经下单、退订或标的失效，消息却仍在队列里。
  2. 多维频控的原子性：日 / 周上限、活动冷却、静默时段、退订黑名单往往同时生效，不能并发超发。
  3. 千人千面多模态物料的合规性：文案、图片、权益必须真实一致，且不能触碰违禁词与品牌底线。
  4. 短期点击 / 探索 vs 长期净转化与 ROI 的平衡：高点击可能带来高退订，自然转化又容易把功劳误记给营销。

本章要点

目标解析把自然语言变成结构化字段：目标、人群、预算、周期、渠道、约束、护栏；缺字段必须追问，预算、周期与护栏必须显式确认，解析结果进审批不能直接执行。分群侧给五类标签（生命周期、时间、偏好、价值、约束）与四条执行前预检：预估规模与样本特征、防止条件写反导致误圈全量或圈出 0 人、规模上下界告警、高预算与敏感人群挂起审批。规模预检给了量化阈值：超过人群池 20% 强制审批，超过 60% 强制收紧频控，预估为 0 直接阻断。

思考笔记

「必须解析出触达量与预算的比值」是本章新增的硬要求：一个「预算 5 万、覆盖 1000 万人」的目标，人均补贴只有 0.5 元——要么根本发不出有意义的权益，要么必然大面积打扰却换不来转化。所以目标解析阶段就要把人均补贴算出来显示给审批人，因为它是「这个活动值不值得做」的第一道判断。

4.3.4 千人千面物料生成与合规

本章要点

生成侧只向模型输入标签化、脱敏后的偏好与画像；双层合规网关是硬规则与一致性校验加语义与多模态审核；兜底是预审通过的安全模板，模板也失败就跳过。权益、价格与有效期必须来自结构化权益服务，不能让模型编造。生成粒度给了成本与收益表：不分群 3 次生成约 0.02 元，20 个人群包 60 次约 0.38 元，100 个人群包 300 次约 1.92 元，每人一份 10 万次约 640 元。

思考笔记

4.3.5 触达放大的三段放大

本章要点

第一段人群放大：一次决策的触达量等于圈选人数乘决策通过率乘渠道成功率乘送达率，大促全量 Push 的例子是 1000 万乘 60% 乘 99% 乘 95%，放大 564 万倍。第二段并发放大：读限额、判断、写计数三步之间有约 1ms 的时间缝隙，热点键上会出现 50 到 100 并发，单用户收到 50 到 100 条而不是 1 条；Lua 原子脚本把并发窗口压到 0。第三段时间放大：快信号 5 分钟可抑制 87 万条，慢信号 24 小时可抑制 2.5 亿条，倍差 288 倍。

思考笔记

三段里前两段可以彻底解决，第三段不能。所以真正的架构问题不是「怎么发现错」，而是「怎么让它错得少、错得早」——止损只能靠前置护栏、幂等与原子频控、快信号熔断这三样。指望事后归因再改，是营销系统最贵的错误。

触达放大的三段放大

本节是触达放大的权威版，打扰成本与频控阈值、变体：大促全量 Push与扩容 10 倍，哪里先坏只引用。

营销系统与其它系统最根本的差别：一次决策会复制成百万次触达。别的系统错了是一行脏数据，营销错了是几百万人今天被打扰。因此本章的第一性问题不是「怎么做得更准」，而是「一次决策最多能放大到多少」。

第一段：人群放大（决策 → 触达）

一次决策 → 触达 N 人
N = 圈选人数 × 决策通过率 × 渠道成功率 × 送达率

以大促全量 Push 为例（目标 1000 万人，人群池 1 亿）：

环节系数剩余
圈选人数—10,000,000
决策通过率（值得立即触达）60%6,000,000
渠道成功率99%5,940,000
送达率95%5,640,000

放大倍率 = 564 万倍。一次自然语言目标、一个人群圈选、一条策略，复制成 564 万次打扰。这个数字必须出现在方案里，因为它是后续所有风险（合规、退订、资损）的公共乘数。

第二段：并发放大（幂等 / 频控不原子）

做法并发窗口单 key 并发结果
GET 读限额 → 判断 → INCR 写计数读返回到写入生效 ≈ 1ms热点 key 上 50–100单用户收到 50–100 条，而不是 1 条
Lua 原子脚本0（单次脚本内完成）不限单用户恒为 1 条

量化：1000 万次下发中，若 0.5% 落在已触达用户上 → 5 万条重复触达；重复触达是退订的第一诱因，退订率因此额外 +0.03%。

并发放大的本质是「读—判断—写」这三步之间存在一个时间缝隙。这个缝隙在低并发时看不出来（单用户并发为 1），在大促首分钟才暴露。幂等键 + Lua 原子是唯一的解——加机器、加超时都无效。

快信号（退订、投诉、点击异常）5 min2,894 × 300 ≈ 87 万条

这条是本章最重要的结论：慢信号永远来不及止损。 转化和 ROI 要 24 小时后才算得出来，而在这一天里，一个坏策略可以触达 2.5 亿次。止损只能靠三样东西：前置护栏（规模预检、审批、合规审核）、幂等与原子频控、快信号熔断。指望「事后归因发现不对再改」是营销系统最贵的错误。

4.3.6 打扰成本与频控阈值

本章要点

单次触达的总成本里渠道成本可忽略，补贴可占 90%，而打扰成本当期看不见、事后最大：退订的 LTV 损失按人均月毛利 30 元乘 24 个月算约 720 元。以 564 万次触达、退订率从 0.02% 升到 0.15% 为例，增量退订 7332 人、LTV 损失约 528 万、投诉 8460 次，是活动补贴预算 50 万的 10.6 倍。退订率与打扰强度是超线性关系：人均 0.5 次对应 0.02%，1 次 0.03%，2 次 0.07%，3 次 0.11%，5 次 0.15%。

思考笔记

「日上限 2」和「日上限 3」在退订率上是 0.07% 与 0.11% 的差别，而这两个数字通常是被随手拍出来的。所以频控阈值必须按曲线的拐点定，三步是：量出自己的退订率与人均日触达曲线（按渠道、按人群分层）、找拐点、阈值设在拐点之前并对高价值人群单独放宽。

打扰成本与频控阈值

本节是打扰成本核算的权威版，成本模型与变体 D：频控阈值与打扰曲线只引用。

退订的 LTV 损失量化（这是最容易被漏算的一项）：

这是本章最重要的一组对比：一次触达放大造成的用户资产损失，是整个活动补贴预算的十倍。补贴花的是「这一单的钱」，打扰花的是「这个用户剩下的所有钱」。 而后者在当期报表上完全看不见——它只表现为「下个月的转化率莫名其妙降了」。

净价值模型（用来定「最优触达量」）：

净增量价值 = 触达人数 × (增量转化率 × 客单毛利 − 人均补贴) − 触达人数 × 单位打扰成本
最优点在：边际增量价值 = 边际打扰成本

4.3.7 事件触达、状态复核与幂等设计

本章要点

下发前二次校验要重新检查实时业务状态：是否已支付、是否已退订、标的是否失效、是否处于免打扰时段，状态已变就取消或顺延。顺序铁律是状态复核、决策、频控扣减、下发，颠倒的代价分别是误扣额度并发催单、超发且无法回补、决策基于过期状态。延迟与顺延任务要三重防重：任务级幂等键、到达时刻二次状态复核、用户加活动级短锁加原子频控；顺延时递增版本号，只有版本一致才允许执行。幂等分七层，各有各的职责。

思考笔记

「无副作用的检查永远放在有副作用的动作之前」是这一段的核心，理由很直白：状态复核是只读的、免费的、无副作用的；频控扣减是有副作用的、不可撤销的。这个原则的迁移价值远超营销场景——它可以直接当成所有有副作用链路的排序准则。

事件驱动触达与频控

触发方式：实时行为事件（加购未支付、浏览未下单、会员到期）或定时任务；支持延迟触发与多步推进。

下发前二次校验：真正发送前重新检查实时业务状态——是否已支付、是否已退订、标的是否失效、是否处于免打扰时段。状态已变则取消或顺延。

任务幂等：campaign_id + user_id + step_id + trigger_ts_bucket 等幂等键，防止重试、乱序、跨节点重复下发。

分布式频控（Redis Lua 原子）：

  • 日 / 周触达上限；
  • 活动冷却期；
  • 静默时段；
  • 退订 / 黑名单强拦截；
  • 同用户多策略的配额抢占。

Lua 一次完成「检查 + 计数 + 记录原因」，避免 check-then-act 竞态。

关键顺序：

状态复核 → 决策 → 频控扣减 → 下发
顺序颠倒的后果具体表现
先扣频控再查状态已付款用户被扣掉额度，并收到一条催单
先下发再扣频控超发，且无法回补
先决策再复核状态决策基于已过期的状态，方向就错了

顺序铁律的四步里，「状态复核」在最前、「频控扣减」在第三。 理由是：状态复核是只读的、免费的、无副作用的；频控扣减是有副作用的、不可撤销的。 永远把无副作用的检查放在有副作用的动作之前——这是本章最容易被违反、也最容易修的一条。

决策模型超时兜底：短超时（50–150ms），超时降级到确定性规则（默认低打扰渠道或 SKIP），但仍必须通过硬频控与退订校验。

延迟 / 顺延任务的状态复核与并发防重入

延迟触发（加购 30 分钟后）与静默顺延（22:00–08:00 顺延到次日 08:30）最容易出现状态过期、重复消费与并发抢占。

三重防重：

  1. 任务级幂等键：campaign_id:user_id:step_id:biz_id，多轮触发加入 trigger_bucket。
  2. 到达时刻二次状态复核：入队状态只代表过去，执行前重新拉取订单、退订、库存 / 券状态。
  3. 用户 + 活动级短锁 + 原子频控：短 TTL 锁串行化关键门控检查，再由 Lua 原子扣减配额。

顺延版本控制：重新计算唤醒时间时更新 schedule_seq；只有当前调度单的 schedule_seq 与消息携带值一致才允许执行，防止旧延迟消息在顺延后误触发。

状态机原子跃迁：

SCHEDULED → EVALUATING → DISPATCHED / CANCELLED

使用条件更新或版本号，确保同一任务不会被两个 Worker 同时推进。

常见竞态：

  • 先扣频控还是先查状态？→ 先查状态，再扣频控。
  • 频控已扣但渠道报错？→ 记录 delivery_failed，按规则回补额度并告警。
  • 锁超时？→ 合理 TTL + 幂等键兜底，避免死锁与重复发送。

4.3.8 增量归因、MAB 与降级矩阵

本章要点

固定 A/B 适合验证明确假设，MAB 适合在探索与利用之间动态分配流量，三种策略分别是 ε-greedy、UCB 与 Thompson Sampling；快慢双信号决定用途：快信号 5 分钟内用于熔断高退订高投诉变体，慢信号 24 小时到 7 天用于修正权重与最终评估。Holdout 增量归因用处理组减对照组的转化差，再算净价值。降级矩阵的判据只有一条：依赖失效时，后果是少赚一点还是伤到用户。

思考笔记

「护栏指标与收益指标不在同一个量纲上，必须硬隔离」是这一段的关键。一个变体可以点击率最高但退订率也最高，如果两者一起加权，模型会去探索「高点击高退订」的变体——那是在优化打扰，不是在优化生意。所以护栏指标触达上限直接熔断，不参与常规放量。

自动化 A/B、MAB 与增量归因

固定 A/B 适合验证明确假设；Multi-Armed Bandit 适合在探索与利用之间动态分配流量：

  • ε-greedy：以 ε 概率探索，其余选择当前最优。
  • UCB：按均值 + 不确定性给冷门臂探索机会。
  • Thompson Sampling：从各变体后验分布采样，选择采样收益最高者。

快慢双信号：

快信号检测窗 = 5 min  → 峰值 2,894 QPS 下可抑制 87 万条
慢信号检测窗 = 24 h   → 峰值 2,894 QPS 下可抑制 2.5 亿条
倍差 288 倍 → 慢信号永远来不及止损，止损只能靠快信号 + 前置护栏
信号内容延迟用途
快信号曝光、点击、退订、投诉T+0（5 min 内）熔断高退订 / 高投诉变体——止损
慢信号归因窗口内的真实转化、客单价、补贴成本、净贡献、ROIT+24h / T+7d修正权重与最终评估——调优，不是止损

Holdout 增量归因：保留空白对照组，计算真实增量提升（Uplift），剔除自然转化水分：

Uplift = Conversion(TREATMENT) − Conversion(HOLDOUT)
Net Value_i = Attributed GMV_i × Margin Rate − Subsidy Cost_i − Channel Cost_i

Thompson Sampling 细节：

  • 二元转化用 Beta-Bernoulli 后验，成功 / 失败计数可加先验与时间衰减。
  • 连续收益（客单价、净 ROI 差异大）用正态 / 伽马等后验或分桶近似，避免「大额券拉高 CVR 却亏毛利」。
  • 保留最小探索比例（Floor Exploration）与 Holdout，防止早期噪音锁死变体。
  • 大促、季节、生命周期变化时使用滑动窗口 / 折扣因子，避免旧赢家长期霸占流量。

护栏优先：退订率、投诉率触达上限直接熔断（mkt.strategy.circuit_broken），不参与常规放量。

护栏指标与收益指标不在同一个量纲上，必须硬隔离。一个变体可以「点击率最高」但「退订率也最高」。如果退订与 ROI 一起参与加权，模型会去探索「高点击高退订」的变体——那是在优化打扰，不是在优化生意。

降级矩阵（Fail-Open / Fail-Closed）

本节是降级的权威版，降级与熔断与故障与兜底只引用。

不能一刀切全拦截，也不能在资金 / 合规 / 防打扰场景盲目放行。判据只有一条：依赖失效时，失效的后果是「少赚一点」还是「伤到用户」？

依赖 / 门控环节典型故障推荐策略降级动作
退订与全局黑名单状态服务超时Fail-Closed状态不明直接跳过，记 SYS_STATE_SERVICE_TIMEOUT
召回标的实时状态订单 / 加购服务超时视场景强时效召回（防催单）Fail-Closed；仅辅助标签且有快照可设短容忍窗口
Redis 分布式频控节点抖动 / 超时Fail-Closed拦截并告警，或切本地粗粒度限流兜底
预算 / 权益额度预算中心超时或余额不足Fail-Closed拦截发券 / 补贴，防超发资损
决策模型（时机 / 渠道）超时 / 降级降级兜底切确定性规则（默认低打扰渠道或 SKIP），仍过硬频控与退订
千人千面物料生成生成失败 / 超时降级兜底切预审安全模板；模板也失败则 Fail-Closed

治理要点：

  • 每次降级打标 degraded=true、fallback_mode 与 reason_code，避免把降级效果误算成策略效果。
  • 高频抖动依赖配置熔断器，触发后快速失败（SYS_CIRCUIT_BREAKER_OPEN），避免线程堆积。
  • 降级比例、原因码分布进入监控与告警。

「语义层 / 权限不可用就停」在本章对应的是「退订状态不可用就停」「预算不可用就停」。这两条与第 1 章 · 问数 Agent的 fail-closed 是同一个原则：宁可少触达，不可打扰一个不该被打扰的人；宁可少发券，不可超发资金。

4.3.9 事件规范、样本回流与渠道容量成本

本章要点

统一事件 Envelope 里有事件标识、追踪标识、幂等键、活动与策略与变体标识、实验分组、用户标识、决策元数据与原因码；核心事件按圈群调度、决策物料、触达执行、反馈归因四层组织。原因码按领域分类规范，每一类指向明确的排查方向。样本回流以追踪标识对齐，慢信号在归因窗口结束后回填并排除未到期样本。渠道必须显式声明七类能力：限流、内容、回执、重试、幂等、费用、合规。容量口径给出：峰值下发 2894 QPS、峰值下游合计约 1.3 万 QPS、决策链路硬约束 150ms、离线生成每天约 960 元、事件链路每天 2.5 亿条。

思考笔记

原因码是营销系统最被低估的可观测性资产：它把「退订率上升」这个笼统现象拆成可定位的原因——取消类上升说明延迟窗口太长，频控类上升说明触达量超了人群承受力，合规类上升说明文案模板出了问题。没有原因码，退订率上升永远只能靠猜。另一处要点是决策链路的 150ms：频控与状态复核只能分到 50ms，这不是性能优化项而是架构约束。

  2. 生成成本可忽略（¥960 / 天），触达成本才可怕——生成不是成本问题，补贴与打扰才是（打扰成本与频控阈值、成本模型）。
  3. 频控 key 空间（3 亿）比 QPS 更需要治理——靠 TTL 分层，不靠扩容。
  4. 事件链路（1.4 万 QPS、125 GB / 天）是最大存储消耗——必须分层与 TTL。
  5. 必须先量人群池——它决定打扰强度，进而决定退订率与全部合规风险。

4.4.1 端到端链路与目标解析护栏

本章要点

营销的端到端链路 13 站：自然语言目标、目标解析、人群圈选、内容生成、合规审核、调度、决策、状态复核、频控、下发、归因、实验与样本回流。目标解析护栏五条：输出结构化 JSON 且字段缺失必须追问，预算、周期、护栏显式确认，必须计算并展示人均补贴与预估人均日触达次数，高风险目标强制审批，解析结果可回放可审计。

思考笔记

营销链路图上最该盯的两行是「规模预检」与「状态复核」：前者把「圈了 600 万人」翻译成「人均打扰 6 次每天」让审批人看见，后者保证发出的每一条都不是过期状态。这两行决定了错误是在发出前被拦住，还是在 24 小时后被归因发现。

4.4.2 圈选、生成与审核护栏

本章要点

圈选护栏六条：规模上下界、打扰强度换算、样本预览、快照版本、排除规则与分级审批。生成与审核护栏七条：只输入脱敏标签，权益来自结构化服务，硬规则查违禁词、绝对化用语与价格有效期一致性，语义与多模态查品牌调性、歧视与误导，失败降级安全模板，外部文本清洗防注入，以及生成必须离线批量且粒度受人群包数约束。

思考笔记

「打扰强度换算」这条是本章特有的护栏：规模上下界只能告诉你圈了多少人，换算才能告诉审批人这个规模意味着用户会收到几条。少这一条，规模预检就退化成一道纯粹的容量检查——它能拦住 0 人和全量，却拦不住「圈了 20% 人群池、也就是人均每天被打扰一次」这种真正危险的情况。

  • 只输入脱敏标签，不输入原始 PII。
  • 权益来自结构化服务，模型不得编造。
  • 硬规则：违禁词、绝对化用语、价格 / 有效期一致性。
  • 语义 / 多模态：品牌调性、歧视、误导。
  • 失败降级安全模板；模板失败则跳过。
  • 外部文本清洗，防 Prompt 注入。
  • 生成必须离线批量，且粒度受「人群包数」约束（千人千面物料生成与合规）。

4.4.3 调度复核、频控幂等与降级熔断

本章要点

调度与状态复核四条：延迟任务带版本号且顺延时递增，到达时先复核状态再决定发送、取消或顺延，状态机条件更新防并发推进，用户加活动级短锁防重复进入；复核覆盖率必须 100% 并单独监控而不是抽样。频控与幂等强调顺序「先复核后扣减」、一次脚本完成多维度检查、扣减成功后写幂等键、下发失败按规则回补并记录失败。降级与熔断分两级：单变体熔断与全局降级，所有降级都要打上降级标记、兜底模式与原因码。

思考笔记

「复核覆盖率 100%，不是抽样」这条常被当成可以妥协的工程指标，但它是这一章里唯一一条必须全量的检查：抽样等于接受一定比例的催单，而催单是投诉的直接来源。另一条容易被漏掉的是「下发失败要回补额度」——不回补的话，渠道抖动会悄悄吃掉用户的频控额度，用户明明没收到消息却再也收不到下一条。

调度与状态复核

  • 延迟任务带 schedule_seq，顺延时递增。
  • 到达时先复核状态，再决定发送 / 取消 / 顺延。
  • 状态机条件更新，防并发推进。
  • 用户 + 活动级短锁，防重复进入。
  • 复核覆盖率必须为 100%，并单独监控（不是抽样）。

频控与幂等

顺序：状态复核 → 决策 → 频控扣减 → 下发。绝不先扣后查（理由见 事件触达、状态复核与幂等设计）。

Lua 频控要点：

  • 一次脚本完成多维度检查（日 / 周 / 冷却 / 静默 / 黑名单）。
  • 返回明确原因码。
  • 扣减成功后写入幂等键。
  • 下发失败按规则回补，并记录 delivery_failed。

频控阈值的三步法：① 量退订-打扰曲线 → ② 找拐点 → ③ 阈值设在拐点前，并按人群价值分层（打扰成本与频控阈值）。

降级与熔断

降级矩阵以增量归因、MAB 与降级矩阵为准，本节只列执行动作：

  • 退订 / 黑名单、频控、预算：Fail-Closed。
  • 物料生成、决策模型：降级到安全模板 / 规则。
  • 高频抖动依赖配置熔断器。
  • 所有降级打标 degraded + fallback_mode + reason_code。
  • 熔断要分两级：单变体熔断（护栏指标触发）与全局降级（依赖故障触发）。

4.5.1 案例：加购未支付 30 分钟召回

本章要点

目标是对加购未支付用户做 30 分钟召回、预算 5 万、增量 ROI 不低于 3、退订率不高于 0.1%。先算放大：圈选 12 万人乘决策通过率 85% 乘渠道成功率 99% 乘送达率 95%，放大 9.6 万倍，但人均日触达只有 0.001 次，是低放大低打扰的良性活动。链路九步里最关键的是第一步：目标解析算出人均补贴 0.42 元，直接决定只能发小额券而不能发满减。结果是增量转化提升 1.8 个百分点、净 ROI 4.2、退订率 0.03%。

思考笔记

这个案例最有价值的地方就在第一步。如果等生成阶段才发券，很可能给 12 万人各发一张 10 元的券——那是 120 万的沉没成本，而预算是 5 万。同时它示范了本章的习惯：先算放大倍数，再设计链路；先算人均补贴，再决定发什么权益。

案例：加购未支付 30 分钟召回

目标：对加购未支付用户做 30 分钟召回，预算 5 万，要求增量 ROI ≥ 3，退订率 ≤ 0.1%。

先算触达放大（这是本章的习惯：先算放大倍数，再设计链路）：

环节系数剩余
圈选人数—120,000
决策通过率（30 分钟后仍值得召回）85%102,000
渠道成功率99%100,980
送达率95%95,931

放大倍率 ≈ 9.6 万倍；但对照人群池 1 亿，这个活动贡献的人均日触达只有 0.001 次——这是一个低放大、低打扰的良性活动，可以放心跑自动化。

链路：

  1. 目标解析：解析出「人群 = 近 24h 加购未支付；预算 ¥50,000；延迟 30 分钟；ROI ≥ 3；护栏 = 日上限 2、72h 冷却」。计算并展示人均补贴 = ¥50,000 / 120,000 ≈ ¥0.42 / 人——低于常规券面额，因此只能发小额券或权益，不能发满减。这个提示直接决定了后续的权益设计。
  2. 圈选：近 24h 加购、未支付、未退订、非黑名单、近 7 天未购买；预估 12 万人，抽样 10% 作为 Holdout。规模预检通过（12 万 ÷ 1 亿，远低于阈值）。
  3. 生成：按品类与价格带切 20 个人群包 × 3 套文案，权益为小额券；离线批量生成 60 次（成本约 ¥0.4）。硬规则校验「限时」「最高」等措辞与券有效期一致。
  4. 触发：消费 add_to_cart_unpaid，延迟 30 分钟；到达后决策模型输出渠道 Push、置信度 0.82。
  5. 复核：8% 用户已支付 → CANCEL_ALREADY_CONVERTED；部分处于静默时段 → 顺延并更新 schedule_seq。
  6. 频控：日上限 2、活动冷却 72h；超限记 FREQ_USER_DAILY_CAP，不扣减、不发送。
  7. 下发：渲染通过后带幂等键发送；渠道失败记 delivery_failed 并按规则回补额度。
  8. 归因：点击与退订实时回流；T+24h 回填支付转化与补贴成本，对比 Holdout 计算 Uplift 与净 ROI。
  9. 调优：变体 B 退订率超护栏被熔断；变体 A/C 由 Thompson Sampling 动态倾斜流量，保留 10% 探索。

结果示例：增量转化 +1.8pp，净 ROI 4.2，退订率 0.03%；确认「先状态复核、再频控、后下发」的顺序避免了催单投诉。

这个案例最有价值的地方是第 1 步：人均补贴 ¥0.42 在目标解析阶段就把「发什么权益」定了。如果等生成阶段才发券，很可能发了一张 ¥10 的券给 12 万人 —— 那是 ¥120 万的沉没成本，而预算是 ¥5 万。

4.5.2 变体：大促全量、会员续费与多渠道协同

本章要点

三个变体分别加不同的护栏。大促全量 Push 的放大倍率是 564 万倍，单个活动贡献人均日触达 0.1 次，是大促日基线 0.5 次的两成，所以要全量审批、分批放量、频控阈值临时收紧从 2 降到 1、渠道容量预估、按批释放预算。会员到期续费强时效，要下发前核验会员状态与到期时间、已续费必须取消、三步递进提醒共享同一活动配额。多渠道协同要统一频控口径跨渠道共享配额，渠道失败切换时不重复计数、不重复计费、不重复占用配额。

思考笔记

大促全量最危险的地方不是技术，而是它把「日上限 2」在事实上架空了：全量推送让 564 万人各收到一条，而这一天还有别的活动在跑。频控阈值不随活动规模收紧，就等于没有频控。多渠道那条坑同样隐蔽——切换时多扣一次额度，系统会误判「打扰强度高」而提前收紧频控，久而久之营销量自己就上不去了。

特点：人群大、预算高、时效强。

变体 B：会员到期续费

特点：标的时效强，错发代价高。

额外护栏：

  • 下发前核验会员状态与到期时间。
  • 已续费用户必须取消（CANCEL_ALREADY_CONVERTED）。
  • 权益与价格以结构化服务为准。
  • 归因窗口对齐续费周期。
  • 到期前 30 / 7 / 1 天三步递进提醒，三步共享同一活动配额（否则「递进提醒」变成三次打扰）。

变体 C：多渠道协同

特点：Push、短信、站内信、IM 组合。

额外护栏：

  • 统一频控口径，跨渠道共享配额。
  • 渠道优先级与降级链。
  • 同一用户同一活动只触达一次。
  • 渠道失败自动切换，但不重复计数、不重复计费、不重复占用配额。

「渠道切换不重复占用配额」是本章特有的一个坑：Push 失败降级到短信，如果短信侧再扣一次频控配额，用户实际收到 1 条却扣了 2 次额度，系统会误判「打扰强度高」而提前收紧频控，久而久之营销量自己就上不去了。

4.5.3 频控阈值、故障兜底与扩容取舍

本章要点

频控阈值用一组数据做决策：日触达从 3 亿压到 2 亿，人均从 3 次降到 2 次，退订率从 0.11% 降到 0.07%，日新增退订从 33 万降到 14 万，日 LTV 损失从 2376 万降到 1008 万，节省 1368 万；代价是少转化 3 万单、毛利 150 万且是一次性的，收益是代价的 9 倍且是永久的。故障兜底补三条：渠道切换后重复计费、频控扣减成功但下发失败、生成缓存未命中且超时。扩容 10 倍的先坏顺序是频控 Redis、渠道网关、然后是打扰。取舍复盘用十条决策记录了各自的代价、收益与重新评估条件。

思考笔记

「用永久收益去换一次性损失，永远划算」是这一段的判断准则。扩容那一段的提醒更刺人：触达量涨 10 倍、人群池不变，人均日触达就从 0.5 次涨到 5 次，退订率涨 7.5 倍，日 LTV 损失从 720 万涨到 5.4 亿，而频控 key 空间完全不变——成本的增长百分之百来自打扰，不来自技术。

4.6 演进、指标与误区

第六段 · 演进与误区这一段回答：营销这套系统怎么一步步长大，成熟后看哪几个数，以及哪些坑最贵。

4.6.1 演进路线与指标体系

本章要点

营销的演进路线 L0 到 L5：人工配置活动、规则自动化、数据驱动圈选、生成加合规、MAB 加增量归因、自主策略，每一级都有触发条件与关键改造。指标体系六层：触达、体验、效果、合规、成本，以及护栏层——频控超发数、预算超发数、复核覆盖率。护栏指标必须与业务指标分层看板，因为业务指标涨了但护栏指标也涨了并不是好消息。

思考笔记

4.6.2 实验调优与成本优化

本章要点

实验与调优六条：固定 A/B 验证明确假设，MAB 做动态分配并保留最小探索比例，护栏指标优先直接熔断不参与收益加权，快信号熔断慢信号定输赢，每次策略变更记录版本与实验分组，阈值类参数变更必须带归因回归。成本优化分两条轨道：补贴与触达成本占大头（精准圈选、延迟发券、增量归因、渠道选择），模型与计算成本占小头（离线生成加人群包粒度、模型分级、模板缓存）。

思考笔记

两条轨道的量级差三个数量级，而大家最爱讨论的生成质量属于小头那条轨道的第三项。所以有一个反直觉的结论：把资源投在「生成得更好看」上，优化空间不到「少发一点」的二十分之一。阈值类参数尤其要小心——它们改变的不是一次活动，是所有未来活动的打扰强度。

实验与调优

  • 固定 A/B 验证明确假设。
  • MAB 做动态流量分配，保留最小探索比例。
  • 护栏指标优先：退订 / 投诉超限直接熔断，不参与收益加权。
  • 快信号熔断，慢信号定输赢。
  • 每次策略变更记录版本与实验分组。
  • 阈值类参数（频控、折扣、预算）变更必须带归因回归——它们改变的不是一次活动，是所有未来活动的打扰强度。

思考笔记

「只算当期转化不算 LTV」这条误区低估的量级最夸张——退订的损失被低估了一百倍，而它恰恰是这套系统里唯一一项当期看不见的损失：它不体现在这个月的报表上，只表现为下个月的转化率莫名其妙降了。所以凡是讨论打扰成本的场合，都必须把 LTV 摊开，否则整个讨论会系统性地偏向多发。

4.6.4 高频追问、答题提纲与一页纸作战手册

本章要点

高频追问 14 条覆盖催单、频控故障、重复触达、增量评估、高点击高退订、生成超时、扣减与查状态的顺序、扣减后失败、阈值怎么定、薅羊毛、多渠道协同、样本回流、选择偏差，以及一次活动最多能打扰多少人。答题提纲给 10 分钟版与 35 分钟版，一页纸作战手册按 S0 到 S5 六阶段组织，每阶段配动作、自检问题与合格线，S0 里多了一条专门量人群池的自检。

思考笔记

高频追问最后一条值得当成本章的验收标准：「一次活动最多能打扰多少人」——圈选乘决策通过率乘渠道成功率乘送达率，这个数必须写进方案与审批。一个说不清这个数的营销方案，本质上是一份没有风险评估的排期表。

高频追问

  • 如何避免「刚付款又收到催单」？ → 下发前实时状态复核，状态已变记 CANCEL_ALREADY_CONVERTED；复核覆盖率必须 100%。
  • Redis 频控挂了怎么办？ → 默认 Fail-Closed，本地粗粒度限流兜底并告警。
  • 如何保证不重复发？ → 七层幂等键 + 状态机条件更新 + schedule_seq 版本校验。
  • 如何评估营销真实增量？ → Holdout 对照组 + 归因窗口 + 净 ROI；同一活动同一问法必须可复现。
  • 高点击高退订的变体怎么处理？ → 护栏指标熔断，不参与收益加权。
  • 生成模型超时怎么办？ → 降级预审安全模板，仍失败则跳过。
  • 先扣频控还是先查状态？ → 先查状态，再扣频控。无副作用的检查永远在前。
  • 频控扣了但下发失败？ → 回补额度、记录失败、告警；回补失败需人工兜底。
  • 频控阈值怎么定？ → 量退订-打扰曲线 → 找拐点 → 设在拐点前，按人群价值分层。
  • 如何防薅羊毛？ → 限购、设备指纹、风控、预算锁。
  • 如何做多渠道协同？ → 统一频控口径、渠道优先级、失败切换不重复计数也不重复占用配额。
  • 如何做样本回流？ → trace_id 对齐，快慢信号分层回填。
  • 如何避免选择偏差？ → 保留随机探索与 Holdout，排除未到期样本。
  • 一次活动最多能打扰多少人？ → 圈选 × 决策通过率 × 渠道成功率 × 送达率，这个数必须写进方案与审批。

4.7 总结

总结把这一章收成一页纸：结论、边界，以及下一章要解决什么。

4.7.1 一句话总结

思考笔记

营销 Agent 的第一性问题不是「怎么做得更准」，而是「一次决策最多能放大到多少」：先算放大倍数，再把触达规模换算成人均可读的打扰数字，然后把无副作用的状态复核放在有副作用的扣减之前——剩下的才是模型能优化的空间。

4.7.2 本章结论

  1. 一次决策的触达量必须先算出来。圈选乘通过率乘成功率乘送达率，大促全量是 564 万倍。慢信号比快信号晚 288 倍才能止损，所以错误必须在发出前拦住，不能靠事后归因。
  2. 打扰是这套系统里最大、也最看不见的成本。一次退订按 LTV 720 元算，564 万次触达让退订率从 0.02% 升到 0.15%，就是 528 万的用户资产损失，是活动补贴预算的 10.6 倍。
  3. 顺序铁律：状态复核 → 决策 → 频控扣减 → 下发。状态复核是只读免费的，频控扣减是有副作用且不可撤销的。先扣后查会给已付款的用户扣掉额度并发出一条催单，而这条原则可以迁移到所有有副作用的链路。
  4. 降级必须分级，而且每次都要打标。退订状态、频控、预算一律 Fail-Closed；生成与决策可以降级兜底。不打标的降级会让兜底效果被算成策略效果，模型因此学到错误的因果。
  5. 生成与模型不是成本问题，补贴与打扰才是。生成每天约 960 元可以忽略，补贴是活动大头，扩容带来的打扰成本甚至涨到日 LTV 5.4 亿。把资源投在文案质量上，优化空间不到「少发一点」的二十分之一。
