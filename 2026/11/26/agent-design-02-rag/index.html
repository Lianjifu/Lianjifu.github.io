问答 Agent——从知识库到可核验答案

发表于2026-11-26 分类于AI Agent 系统设计

问答 Agent 把用户提问变成有依据、可核验、可追溯的答案。难点不在「答得像人」，而在「答得准、且知道什么时候不该答」——检索噪声会被模型编成结论，过期知识会被反复复用，答不上来时还必须敢拒答。本章围绕知识切分与多路召回、重排与注入预算、引用与拒答、权限隔离与知识时效展开。

2.1 问答 Agent 是什么

第一段 · 问答 Agent 是什么这一段回答：问答 Agent 究竟是什么、与 FAQ 和全文检索差在哪、给谁用，以及哪些决策一旦做错就要停机迁移。

2.1.1 定义与能力层次

本章要点

问答 AI Agent 接收自然语言问题，完成意图路由、检索规划、多路召回、重排、上下文构建、生成与引用、置信度判定与拒答、以及基于反馈的评测闭环。它与问数 Agent 是同构的兄弟：都是「读 → 推理 → 答」，差别只在事实源——问数读结构化数仓，问答读非结构化知识库。

思考笔记

这一段最值得带走的是那句镜像关系：问数章说「先下推再回传，绝不靠截断控制上下文」，本章说「召回宽、注入窄，绝不靠加宽召回换命中率」。同一个底层道理的两面——送进模型的东西，要么是算好的，要么是筛过的，不能是原样倒进去的。

定义：问答 AI Agent 是面向知识密集型场景的智能体系统。它接收自然语言问题，完成意图路由、检索规划、多路召回、重排、上下文构建、答案生成与引用、置信度判定与拒答、以及基于反馈的评测闭环，最终给出有依据、可核验、可追溯的答案。

它与问数 Agent 是同构的兄弟：两者都是「读 → 推理 → 答」，差别只在数据源——问数读的是结构化数仓，问答读的是非结构化知识库。这个同构性是本章的骨架：

维度问数 Agent（<a href="/2026/11/26/agent-design-01-text2sql/">第 1 篇</a>）问答 Agent（本章）
事实源语义层 + 数仓切分后的知识块 + 版本
事实的形态结构化、可计算非结构化、需引用
幻觉的形态口径错、Join 错无依据生成
防线口径固化 + AST 校验 + 沙箱召回 + 重排 + 引用 + 拒答
正确的证明SQL 可执行可复现引用可点开可核验

两章的核心方法论也是镜像的：问数章说「先下推再回传，绝不靠截断控制上下文」，本章说「召回宽、注入窄，绝不靠加宽召回换命中率」。同一个底层道理的两面：送进模型的东西，要么是算好的，要么是筛过的；不能是原样倒进去的。

2.1.2 用户、场景与相近系统

本章要点

内部员工、客服一线、客户、知识管理员是四类主要用户，风险各不相同。与 FAQ、全文检索、文档摘要、通用 LLM 聊天的区别是：那些系统要么不组织答案，要么不引用，要么会一本正经地编。

思考笔记

「答案必须挂在一个可点开的来源上」是这一段唯一不可妥协的产品定义。没有这一条，它就退化成一个「回答得很像人、但你没法验证」的搜索框——而这恰恰是用户不信任 AI 回答的根本原因。所有后面的工程量，都是为了让这句话能兑现。

2.1.3 边界、指标与不可逆决策

本章要点

范围内是问题理解、切分索引、召回重排、生成引用、拒答澄清、反馈回流六件事，范围外是知识生产与审核流程、文档协作与权限系统本身。核心指标分效果、引用、检索、体验、成本、安全六类。另有七项不可逆决策，其中切分策略、Embedding 模型、引用契约三项代价最大。

思考笔记

不可逆清单里最容易被低估的是「引用契约与答案结构」：引用是可信度的唯一载体，一旦换了粒度或校验方式，全量答案与引用要重新生成，下游解析全部失效。它不像切分策略那样「早就听说过」，但它一旦上线就极难改。

系统边界：

范围内范围外

切分、入库、索引与版本文档协作与权限系统本身
召回、重排、上下文构建通用搜索引擎的实现
生成、引用、拒答、澄清人工知识运营
反馈回流与评测闭环企业微信 / 邮件等通知渠道

检索recall@k、重排前后命中率、注入块数

两个新指标是本章的核心：幻觉率（答了但没有依据）与误拒率（本可答却拒答）。它们是一对此消彼长的指标，必须一起看——单看任何一个都能得出「应该调松/调紧」的反向结论。

注入预算与注入条数的口径（k 是多少、怎么算、超了怎么办）决定成本、延迟与幻觉率三者改 k 要重跑成本与质量双回归

2.2 核心矛盾与设计原则

第二段 · 核心矛盾这一段回答：开放提问与封闭答案之间到底隔着什么，为什么这六条原则在冲突时说了算。

2.2.1 本质与六条章级原则

本章要点

本质矛盾是开放提问的表达空间与封闭答案的证据要求之间的冲突——用户可以问任何事，但答案必须挂在一个存在的、可点开的、当前生效的知识块上。六条章级原则规定了冲突时以谁为准：召回宽注入窄、没有依据就不作答、答案必须带可点开的引用、知识时效要标截止时点、权限在检索层过滤、拒答率是双面指标。

思考笔记

六条原则里第三条和第五条最容易被违反，因为它们都要求「把约束放在模型外面」。模型看不见的文档，就不可能被写进答案；Prompt 里那句「请不要透露内部制度」是提示，不是防线。一个好用的自检：如果某条护栏要靠模型自觉执行，它就不是护栏。

本质：问答 Agent 的核心矛盾，是「开放提问的表达空间」与「封闭答案的证据要求」之间的冲突。用户可以问任何事，但答案必须挂在一个存在的、可点开的、当前生效的知识块上。这意味着「答不上来」是一个必须被产品化的一等公民，而不是失败。

六条章级原则（贯穿全章，冲突时以这六条为准）：

  1. 召回宽、注入窄——召回保证不漏（宽），重排后注入保证不噪（窄）。这是本章的第一原则：宽召回 + 窄注入同时成立，两个指标才同时改善。
  2. 没有依据就不作答——检索不到就明说「知识库里没有」，宁可拒答，不可流畅地编。模型的生成能力远强于它的判别能力（<a href="#sec-3.3.4">重排</a>）。
  3. 答案必须带引用，且引用可点开原文——不可核验的答案不可信。每个实质性论断都要有引用，这是 P0 而非加分项。
  4. 知识有时效，答案要带截止时点——过期知识不静默使用；答案要说明「基于哪一版知识、截至什么时候」。
  5. 权限在检索层过滤，不在生成层声明——模型看不到的文档，就不可能被写进答案。「请不要透露内部制度」是提示，不是防线。
  6. 拒答率是双面指标——幻觉率与误拒率必须一起看。单看拒答率，永远会得出「应该放宽」的错误结论。

2.2.2 三个不等式与三个放大器

本章要点

三组不等式划定了问题边界：生成能力远超判别能力、开放提问远超封闭答案、知识规模远超人工维护速度。三个放大器量化了代价：召回放大让准确率反降 3pp 而幻觉率涨 13pp，幻觉放大让错误答案比错误检索更贵，知识复用放大让一条过期条款每天被复用 6 万次。

思考笔记

这一段最反直觉的一句在「生成能力 >> 判别能力」：模型被问「住宿标准是多少」，上下文里有 50 块、其中 12 块提到金额，它会从这 12 块里「综合」出一个看起来合理的数字——它无法区分「这块说的是住宿标准」和「这块说的是餐补标准」。所以幻觉的根源不是模型撒谎，是模型分不清。

三个不等式：

生成能力  >>  判别能力   →  噪音一旦进上下文，就会被编成合乎逻辑的结论
开放提问  >>  封闭答案   →  拒答与澄清不是失败，是产品的一部分
知识规模  >>  人工维护速度 →  靠版本与时效标注，不靠人肉

三个放大器（本章最贵的量都藏在这里）：

放大器说明后果量化
召回放大（宽度 vs 精度）召回集变宽，命中更多、噪声更多幻觉率上升，上下文暴涨k 从 10 → 50：命中率 +11pp，准确率反降 3pp，幻觉率涨 13pp，上下文 +168%（<a href="#sec-3.3.4">重排</a>）
幻觉放大模型的生成能力远强于判别能力错误答案比错误检索更贵18% 幻觉率 → 若 1% 被采信并纠正，¥18 万/天，比省下的 token 还多（<a href="#sec-3.4.3">拒答、澄清与置信度</a>）
知识复用放大一条过期条款被命中一次，就被复用成千上万次错误知识被规模化传播过期块贡献 3% 的问答 → 6 万次/天基于过期知识作答（<a href="#sec-3.5.3">知识时效与版本</a>）

本章的放大器方向值得单独记：别的系统放大的是数据量，问答章放大的是「不确定的证据量」——它是唯一一个「为了不漏答案而做的动作，会系统性地制造错答案」的架构。

2.2.3 四层正确性与八组关键矛盾

本章要点

正确性分证据正确、依据完整、知识有效、权限正确四层，必须分开保证。八组矛盾给每一条标注了默认策略与反转条件，比如「拒答 vs 体验」默认澄清一次后给候选，高价值场景可以多拒。

思考笔记

四层里最容易被漏掉的是「知识有效」：检索到的块确实支持答案、每个论断都有依据、依据是当前生效的版本——三件事都要成立。尤其是第三件：库里同时存在新旧两版时，答案可能完全有据却已经过期，这在四层里是独立的错误类型，不能被「有引用」掩盖。

四层正确性（必须分开保证）：

层次要求保障手段典型漏法

2.2.4 失败模式、信任分级与威胁模型

本章要点

八类失败模式里，幻觉、引用错位、过期作答、越权泄露是本章特有的四类。信任分级多出一档「低」——只给有依据的部分并明确指出不确定的部分。威胁模型里提示注入的危险级别高于其它 Agent：别的章注入是要模型多做事，本章注入是要模型把恶意文本当成知识讲出来。

思考笔记

2.3.3 切分、召回与重排

本章要点

切分有三条铁律：每块带标题路径、表格行携带表头、重叠 10–20%。切分粒度与注入粒度必须解耦——检索用 200 token 小块，注入用 600 token 合并段。召回走五路并用 RRF 融合。重排用交叉编码把宽召回收敛成窄注入，k 的倒 U 型拐点在 10–20 之间。

思考笔记

这一段有一个数据特别值得记：「检索 200 token 块，不合并」召回到 91%，准确率却只有 81%——它召回到了正确的块，却因为块被切碎而答不对。**召回到 ≠ 答得对**。检索粒度与注入粒度必须分别设计，这是本章最容易被做错的一个工程点。

问题理解与意图路由

类型示例路由
事实型「出差住宿标准是多少」单跳快路径

对比型「A 方案和 B 方案的差别」单跳 + 多块对比

路由的关键判断：这个问题库里有答案吗？

在生成之前先做一次可行性判断（用检索结果的最高重排分做阈值）：

  • 最高分 ≥ 阈值 → 正常生成
  • 最高分在灰区 → 先澄清（「你说的 X 是 A 还是 B？」）
  • 最高分 < 阈值 → 直接拒答，不进生成

这一层能省掉大量幻觉：让模型在「检索不到」的情况下自由发挥，它一定会编。把「答不上来」这个判断前移到检索之后、生成之前，是本章最有效的一道防线——它比任何事后的幻觉检测都便宜、都可靠。

  1. 向量 + BM25 是最小可用组合，各加一路都有明确收益。
  2. 历史问答对是性价比最高的一路：成本几乎为零（问题字符串匹配 + 已确认答案），命中率却从 82% 提到 89%。而且它天然带「已确认」的语义——这份答案是人核过的。
  3. 专有名词场景必须上 BM25：向量检索对型号、编号、政策代号是弱项，而这些恰好是企业知识库里最常被问的东西。

重排：把宽召回收敛成窄注入

本节是重排的权威版，<a href="#sec-4.2.1">检索与重排护栏</a>只引用。

为什么必须有重排：召回是双塔结构——query 和 chunk 分别编码再算相似度，快但粗；重排是交叉编码结构——query 与 chunk 一起进模型，能判断「这个块是否真的回答了这个问题」，准但慢。双塔负责不漏，交叉编码负责不噪。

  1. k 从 10 → 50：证据命中率 +11pp，答案准确率反降 3pp，幻觉率从 5% 涨到 18%。
  2. 倒 U 型的拐点在 k = 10–20 之间；超过拐点，多召回的每一条都在为答案的噪音做贡献。
  3. 幻觉率是随 k 单调上升的（14% → 8% → 5% → 9% → 18%，先降后升是过少噪声导致），准确率的最高点远早于命中率的最高点。

这说明了一个普遍规律：很多「模型不够强」的问题，实际是「喂给模型的东西不够干净」。 换更强的模型往往更贵且收益有限；加一层重排，往往同时更便宜更准。

为什么噪音会被编成答案（幻觉的机制）：

生成能力 >> 判别能力
模型被问「住宿标准是多少」，上下文里有 50 块，其中 12 块提到金额
→ 模型会从这 12 块里「综合」出一个看起来合理的数字
→ 它无法区分「这块说的是住宿标准」和「这块说的是餐补标准」

模型的判别能力弱于生成能力，是幻觉的根源。 推理模型能写「根据文档，标准是 XX 元」，但它未必能意识到这 12 块里其实有 8 块讲的是另一个标准。重排的作用，就是把「模型要判断的东西」从 50 块减到 5 块——它不提升模型的判别能力，它减少了模型需要判别的东西。

重排的工程约束：

约束说明
只重排 top-NN 从 50 降到 20，重排耗时减半，召回命中率掉 3pp（实测）
批处理一次请求的 N 对一起打分，避免逐对串行
重排模型可降级交叉编码不可用时退回向量分数排序，并打标 degraded
重排结果要落日志没有重排日志，就无法解释「为什么这条没被引用」

拒答、澄清与置信度

本节是拒答决策的权威版，<a href="#sec-4.3.1">引用与拒答护栏</a>只引用。

拒答与澄清的三种类型：

类型场景动作
无依据拒答检索不到相关内容「知识库中没有找到相关制度」+ 可走的下一步（问谁 / 提工单 / 换问法）

置信度不可信（与其它 Agent 场景同理）：模型自报的 confidence 不可靠。更稳的做法是用重排分数 + 独立分类器头，或多次采样看一致性。

双面指标：幻觉率 vs 误拒率

拒答阈值幻觉率误拒率综合可用率 = 1 − 幻觉 − 误拒
严格（高阈值）2%18%82%
平衡（推荐）5%8%87%
宽松（低阈值）14%3%86%

看这张表最重要的一行不是「平衡」那一行，而是「严格」与「宽松」两行的对比：两者的综合可用率几乎相同（82% vs 86%），但信任代价完全不同——

  • 幻觉率 14%：用户按错误答案操作 → 信任崩塌，且不可逆
  • 误拒率 18%：用户多问一次 / 换个问法 → 成本是一次交互，可恢复

所以拒答策略必须偏向严格。 单看「综合可用率」会得出「严格和宽松差不多」的结论，从而在阈值上调时反复摇摆；必须给「信任损失」单独定价。这就是「拒答率是双面指标」的真正含义：它不是往一边调的问题，而是要按两类错误的代价不对称来定。

阈值决策：

幻觉率 vs 误拒率
  → 严格（高阈值）：幻觉  2% + 误拒 18% → 综合可用率 82%
  → 平衡（推荐）  ：幻觉  5% + 误拒  8% → 综合可用率 87%
  → 宽松（低阈值）：幻觉 14% + 误拒  3% → 综合可用率 86%
  → 严格与宽松的综合可用率接近，但信任代价完全不同
  → 幻觉不可逆，误拒可恢复 → 阈值必须偏向严格

幻觉的成本量化（回到<a href="#sec-2.2">三个不等式与三个放大器</a>）：

日问答 200 万 × 幻觉率 18% = 36 万条无依据答案 / 天
假设 1% 被用户采信并据此行动，需要人工纠正（每次 ¥50）
→ 1,800 次 × ¥50 = ¥18 万 / 天 ≈ ¥540 万 / 月
对比：把 top-50 改成重排后 top-10 每月省 ¥192 万 token
→ **省下的 token 钱，会被幻觉的纠正成本吃掉还多**

这个对比是本章最实用的一条结论：在问答 Agent 里，降低幻觉率的收益大于降低 token 成本。 而降低幻觉率最便宜的手段不是换更强的模型，是重排。

拒绝时的输出契约：拒答也必须是有用的答案——「库里没有 + 你可以问谁 + 你可以换什么问法 + 已知的相近制度是什么」。一句「无法回答」是最差的拒答。

2.3.5 多跳、权限与知识时效

本章要点

多跳要串起两个以上来源或先定位实体，分解后逐跳检索重排，最后必须做合并一致性校验——只验子步骤不验合并等于没验。权限分 ACL 进索引与检索后过滤两种，前者命中率 89%、后者 62%。知识时效靠版本、生效时间与状态三件套。

思考笔记

多跳的失败模式与单跳完全不同：单跳的失败是「证据不对」，多跳的失败是「每一步都对，但组合是错的」。合同在检索期间被换成修订版，子答案各自都答对，合并起来就是错的。所以合并一致性校验，尤其是版本一致性，是多跳链路里最不能省的一步。

多跳与复杂问题拆解

多跳的判定：答案需要串联 ≥ 2 个来源，或需要先定位一个实体。

分解流程：

问题 → 实体链接（找到「X 公司」「3 号合同」）
     → 拆成子问题（子问题之间有依赖）
     → 逐个检索 + 重排（每个子问题独立预算）
     → 逐步作答
     → **合并一致性校验**（子答案之间是否矛盾）

权限与租户隔离

核心原则：ACL 进索引，检索层过滤。模型看不到的文档，不可能被写进答案。

两种方案的量化对比：

方案做法召回命中率风险
A：ACL 进索引块带 acl 字段，检索时过滤89%（top-50 中过滤后仍余 50 块）权限变更需更新受影响块的索引字段
B：检索后过滤索引不带 ACL，取回 top-50 再按用户过滤62%（top-50 中 40 块被过滤掉，只余 10 块）召回预算被悄悄吃掉 44%

方案 B 的失败极其隐蔽：它不报错、不越权，只是让有效召回从 50 变成 10，检索质量断崖式下降。团队通常会去调 top-k 或换模型，而真正的病根是过滤位置错了。

所以「权限过滤放在检索之前还是之后」不只是安全选择，也是质量选择。

权限变更的传播：

机制延迟说明
增量更新索引的 ACL 字段秒级按受影响用户 / 部门 / 密级反查块并更新
权限变更事件 → 重建受影响文档的块分钟级兜底
过滤层版本号—权限服务版本与索引版本对齐，落后则拒绝而非放行

权限版本落后时必须 fail-closed（拒绝检索）而不是 fail-open（放行旧权限）。这与问数章「权限服务故障就拒绝」是同一条原则。

2.3.6 评测、成本与容量

本章要点

黄金集必须分可答题、不可答题、越权题三个区，缺一不可。评测以引用精确率优先——标注成本低、定位准。容量估算给出日 136.4 亿 token、约 ¥35,920（约 ¥108 万/月），注入占输入 73%，重排算力 5800 对/秒。

思考笔记

「引用精确率」比「答案准确率」更值得优先做，因为它标注成本低得多——只需判断「这段文字支持这句话吗」，不需要写出标准答案，而且它能直接告诉你是「召回错了」还是「重排错了」还是「生成错了」。recall@k 是上游指标，只看它加大召回是本章最常见的误诊。

评测方法

黄金集的三个维度（缺一不可）：

维度内容为什么必须有
可答题问题 + 标准答案基本盘
不可答题库里没有的问题不覆盖它，就等于把拒答能力训没了
越权题有答案但用户无权只测可答题的系统，会在权限上裸奔

指标体系：

指标定义地位
幻觉率答案含无依据论断的比例核心
误拒率本可回答却拒答的比例核心
答案准确率与标准答案语义一致结果指标（标注成本高）
引用精确率引用的块确实支持该论断核心（比准确率更易标注）
引用召回率标准答案的关键论断都被引用核心
引用完整率每个论断都有引用硬约束
拒答恰当率该拒的拒了与误拒率一起看
recall@k（检索层）证据在 top-k 内上游指标，不是结果指标
线上：答案质疑率用户点「这个不对」生产环境的幻觉代理指标
线上：引用点击率用户点开引用核对可信度代理指标

「引用精确率」比「答案准确率」更值得优先做，因为它标注成本低得多（只需判断「这段文字支持这句话吗」，不需要写出标准答案），而且定位更准——它能直接告诉你是「召回错了」还是「重排错了」还是「生成错了」。

recall@k 是上游指标：retrieval 命中率 90% 但准确率只有 70%，说明问题出在重排与生成，不是召回。只看 recall@k 就去加大召回，是本章最常见的误诊。

2.4.1 端到端链路与意图路由

本章要点

端到端链路有 11 步，从 Gateway 到 Feedback。其中 Intent Router 负责分类与快慢分离，Verifier 是代码层的最后一道关卡，Context Builder 是唯一的注入收敛点。路由护栏里最关键的一条是「可行性前置判断」：检索后重排分低于阈值就直接拒答，不进生成。

思考笔记

「把「答不上来」这个判断前移到检索之后、生成之前，是本章最有效的一道防线」——它比任何事后的幻觉检测都便宜、都可靠。让模型在「检索不到」的情况下自由发挥，它一定会编；而在它编之前拦住，成本几乎为零。

端到端链路

  → Intent Router（事实型 / 流程型 / 多跳 / 越界；单跳快路径 vs 多跳慢路径）
  → Query Planner（仅多跳：实体链接 + 子问题分解）
  → Retriever（五路召回 + 融合 RRF + ACL 过滤）

2.4.4 降级、延迟预算与观测

本章要点

思考笔记

「只返回引用块，不生成答案」是本章最有价值的一条降级——它把系统从「编答案」拉回「给证据」，用户仍能自己看原文。同理，延迟预算里那 150ms 的校验不是可选的质量增强，它是「不输出未校验答案」的最后一道关卡，所以不能被前面的环节挤掉。

  9. 知识时效三道防线是否都在？答案是否标了知识截止时点？
  10. 黄金集是否包含不可答题与越权题？提示注入红队是否通过？

2.5.2 四个变体：多跳、隔离、版本与取舍

本章要点

四个变体覆盖多跳问题（实体链接加分解加合并一致性校验）、跨租户与密级隔离（ACL 进索引 vs 检索后过滤）、知识过期与版本冲突（冲突摊开而非悄悄裁决）、召回宽度与重排的取舍（先查重排再查召回路数）。

思考笔记

变体 D 最反直觉：团队提议把注入条数从 top-10 加到 top-50，诊断后发现重排在丢证据，换了重排模型之后把召回范围从 50 收到 30，准确率反而从 85% 升到 88%、幻觉率从 5% 降到 3%、重排算力还省了 40%。召回范围收窄了，质量反而提升——因为证据还有第二道机会。

变体 A：多跳问题

问题：「我们和 X 公司的合同里违约金条款是什么？」

  1. 实体链接：「X 公司」→ 公司实体 ID；「合同」→ 我方主体 + 合同文档类型。
  2. 拆子问题：① 我方与 X 公司的合同是哪一份？② 该合同的违约金条款是什么？
  3. 子问题 1：检索（结构化过滤 + 向量）→ 合同《2024-089 号框架协议》→ 锁定文档。
  4. 子问题 2：在该合同的块中检索「违约金」→ 命中 3 块（第 8.2 条 + 附件二违约金表）。
  5. 合并一致性校验：条款版本与合同版本一致 ✓；条款金额与附件表格一致 ✓。
  6. 输出：答案 + 引用（合同 2024-089 第 8.2 条 + 附件二）+ 合同生效期。
  7. 成本：3 次 LLM 调用、注入 6,500 token（比单跳多 45%）。

第 5 步是最容易漏的：子问题 ① 和 ② 各自都答对了，但如果合同在检索期间被换成了修订版，② 的答案就来自旧版合同——每一步都对，组合是错的。所以多跳必须做合并一致性校验，尤其是版本一致性。

变体 B：跨租户与密级隔离

问题：「我们事业部今年和去年同期的营收对比如何？」（用户仅有本事业部数据权限）

方案 A（ACL 进索引）：

步骤候选数

方案 B（先召回后过滤）：

步骤候选数
全库语义召回 top-5050
其中前 20 位是集团口径与其他事业部的营收块（语义极近，标题里都有「营收」「同期对比」）—
过滤后实际可用30

差异不在安全，在质量：两种方案都不泄露任何越权内容（方案 B 同样安全）。但方案 B 的有效召回从 50 掉到 30，且排名头部被过滤掉——黄金集上命中率从 89% 掉到 62%。

所以「ACL 过滤放在检索前还是检索后」是质量决策，不是安全决策。 很多团队把它当安全问题处理，于是选了检索后过滤（因为实现简单），悄悄损失了 27pp 的召回命中率，然后跑去调 top-k 和换模型——治错了地方。

输出：仅本事业部数据，答案带权限范围说明；审计记录「召回了哪些块、过滤掉了哪些块」。

变体 C：知识过期与版本冲突

问题：「年假政策现在是怎么规定的？」

库里的三份材料：

文档版本生效时间状态
《员工手册》年假条款v5.02023-06-01已废止
《员工手册》年假条款v6.02025-01-01生效中
《2026 年假补充通知》—2026-06-01生效中

处理：

  1. 检索时按状态过滤：只召回生效中版本 → v5.0 被挡在召回层。
  2. 冲突检测：v6.0 与 2026 补充通知在「病假天数」上有出入。
  3. 裁决规则：以 effective_from 更晚且状态为生效中的为准 → 补充通知优先。
  4. 答案显式说明冲突：「按 2026-06-01 生效的《2026 年假补充通知》，病假天数为 X；2025-01-01 版《员工手册》v6.0 中为 Y，以新通知为准。」

第 4 步比「选一个对的」更重要：把冲突摊开给用户，比悄悄选一个更可信。用户能自己判断「公司到底按哪个执行」，而一个被悄悄裁决过的答案，用户只能选择信或不信。

量化这个风险：不做版本过滤时，这道题有 43% 的概率召回 v5.0（向量检索对「年假政策」的语义相似度，两个版本几乎一样）——用户拿到的可能是已废止一年的规定。

变体 D：召回宽度与重排的取舍

场景：团队反馈「召回不准，命中只有 78%」，提议把注入条数从 top-10 加到 top-50。

先查表（<a href="#sec-3.3.4">重排</a>）：

方案证据命中率准确率幻觉率上下文
现状 top-1086%85%5%4,000
提议 top-5097%82%18%20,000

诊断：命中率确实涨了 11pp，但准确率掉了 3pp、幻觉率涨了 13pp、上下文涨了 5 倍。加宽 k 没有解决任何问题，它只是把噪音也一起加了进来。

正确的三步诊断顺序：

召回命中率低
  → ① 先查重排：召回 top-50 里本来有 97% 的证据，
              重排后 top-10 只剩 86% → **重排在丢证据**
  → ② 再查召回路数：只用向量？加 BM25 后 top-10 命中率 71% → 82%，
                  **成本几乎为零，收益比加宽 k 大得多**
  → ③ 最后才考虑加宽 k，且必须窄注入

本案例的实际修复：

第 4 步是本案例最反直觉的地方：召回范围收窄了，质量反而提升。

原因就是「召回宽、注入窄」这六个字的意思：宽是为了不漏，但漏掉的证据本该由重排捡回来。当重排变强之后，召回范围可以往回收——因为证据还有第二道机会。

反过来说：如果重排没做对，加宽召回就是在给模型喂噪音。 「召回不够」这个判断，几乎总是应该先怀疑重排，而不是先怀疑召回。

2.6 演进、指标与误区

第六段 · 演进与误区这一段回答：这套系统怎么一步步长大，成熟后看哪几个数，以及哪些坑最贵。

本章要点

2.6.2 评测回归与成本优化

本章要点

评测回归的黄金集分三区，标注以引用精确率优先；换 embedding、改切分、改召回权重、改重排、调 k、改拒答阈值——六类变更都要重跑黄金集。成本优化第一刀是重排收敛注入条数，输入 token −72%，第二刀是收窄召回范围。

思考笔记

「只看准确率会把系统调成『什么都不敢答』」——变更回归必须同时看幻觉率与误拒率。这是本章双面指标最实际的用处：两个数一起看才知道阈值往哪边调。成本那一侧，第一行是全部优化的 90%，其余手段都在个位数到十几个百分点。

评测与回归

  • 黄金集三个分区：可答题 / 不可答题 / 越权题，缺一不可。
  • 标注以引用精确率优先（标注成本低、定位准），答案准确率作为结果指标。
  • 每周重跑：换 embedding 模型、改切分、改召回权重、改重排、调整 k 值、改拒答阈值——六类变更全都要重跑黄金集，因为它们都直接改变幻觉率与误拒率。
  • 变更回归要看两个数：幻觉率与误拒率同时看；只看准确率会把系统调成「什么都不敢答」。
  • 线上以答案质疑率与引用点击率做生产环境的幻觉代理；质疑率上升即回滚。
  • 重排日志是回归的抓手：出现一条坏答案，要能回溯到「召回给了什么、重排排成了什么、注入了什么」。

成本优化

顺序手段收益说明
1重排收敛注入条数输入 token −72%同时提准确率、降幻觉率
2收窄召回范围（重排变强后）重排算力 −40%质量反而提升
3Query 缓存 / 热门问答直答请求 −15%无损
4模型分级（单跳走小模型）约 −20%简单题不需要大模型
5引用块去重与裁剪注入 −5%收益有限

第 1 行是本章全部成本优化的 90%：「让更少的 token 承载更可靠的证据」。其余手段都在个位数到十几个百分点，而第 1 行是 −72%。

2.6.4 高频追问、答题提纲与一页纸手册

本章要点

高频追问 12 条覆盖减少幻觉、召回与准确率的关系、为什么不用更大上下文、权限过滤放哪层、答案可信的条件、什么时候拒答、如何平衡幻觉与误拒、怎么评估、成本、多跳、知识过期与模型不可用。答题提纲给 10 分钟版与 35 分钟版，一页纸手册按 S0 到 S5 六阶段组织。

思考笔记

高频追问里第一条「如何减少幻觉」给了三层：重排收敛注入、引用精确率校验、可行性前置判断——三层的成本递减而可靠性递增，第一层还顺带省 72% 的 token。答题提纲里 35 分钟版把「召回放大的倒 U 型曲线推导」「三指标同时改善」「幻觉成本的量化」放在前 14 分钟，因为这三处最能区分背过与算过。

高频追问

  • 如何减少幻觉？ → 三层：① 重排收敛注入（最有效，且同时省 72% token）；② 引用精确率校验（代码层逐句校验）；③ 可行性前置判断（检索不到就不进生成）。
  • 召回和准确率是矛盾的吗？ → 不矛盾，但要先重排后加宽：召回宽保证不漏，重排窄保证不噪。加宽 k 只在重排已经做对之后才安全。
  • 为什么不直接用更大的上下文？ → 更大的上下文只是把更多噪音塞进去，准确率在 k=20 之后就下降了；成本还是线性涨。上下文不是答案质量的免费午餐。
  • 权限过滤放哪一层？ → 检索层。放检索后会吃掉 27pp 召回命中率，而且不报错，只是变差。
  • 如何让答案可信？ → 引用完整率 100% + 引用可点开 + 引用逐句校验 + 标注知识截止时点。可信度不是靠措辞，是靠可核验。
  • 什么时候该拒答？ → 检索后最高重排分低于阈值、越权、或歧义无法消解。拒答必须有用：说明库里没有 + 问谁 + 换什么问法。
  • 如何平衡幻觉与误拒？ → 按代价不对称定阈值：幻觉不可逆、误拒可恢复，所以偏向严格；且两率必须一起看。
  • 怎么评估问答 Agent？ → 黄金集含「可答 / 不可答 / 越权」三类；主指标引用精确率 + 幻觉率 + 误拒率；recall@k 只是上游指标。
  • 如何控成本？ → 第一刀是注入 token（占输入 73%），重排收敛是唯一量级级别的手段。
  • 多跳怎么做？ → 实体链接 → 分解 → 逐跳检索重排 → 合并一致性校验；每跳注入预算要比单跳少。
  • 知识过期怎么办？ → 入库必填生效时间与 owner、检索只取生效中、答案标截止时点；冲突要摊开而不是悄悄裁决。
  • 模型不可用怎么办？ → 只返回引用块，不生成答案——把系统从「编答案」拉回「给证据」。

2.7 总结

总结把这一章收成一页纸：结论、边界，以及下一章要解决什么。

2.7.1 一句话总结

思考笔记

问答 Agent 的可信度不来自更强的模型，而来自一条干净的检索链路：召回宽、注入窄、引用可点开、答不上来敢拒答。再加一条成本真相——幻觉的代价远高于 token 的代价。

2.7.2 本章结论

  1. 召回宽、注入窄是第一原则。召回保证不漏，重排保证不噪。k 从 10 加到 50，命中率涨 11pp 而准确率反降 3pp、幻觉率涨 13pp——多召回的每一条都在为噪音做贡献。
  2. 「答不上来」是一等公民。可行性判断要前移到检索之后、生成之前。拒答必须有用：库里没有、问谁、换什么问法、相近制度是什么，一句「无法回答」是最差的拒答。
  3. 引用完整率是 100%，不是 95%。引用是非线性的信任指标：100% 与 95% 的差别不是「差 5% 的答案」，而是用户还愿不愿意点开引用。一条无依据的引用会污染整个答案。
  4. ACL 必须进索引。检索后过滤同样安全，却会悄悄吃掉 27pp 的召回命中率。这不只是安全选择，也是质量选择——放错位置的团队会跑去调 top-k 换模型，治错了地方。
  5. 幻觉的代价大于 token 的代价。18% 幻觉率若 1% 被采信并纠正，每天 18 万元；而重排这一个动作同时省 72% 的钱、提 3pp 准确率、降 13pp 幻觉率。
