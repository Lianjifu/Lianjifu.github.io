第 11 章：供应链 Agent

供应链 Agent——预测、补货与履约的约束求解

发表于2026-11-26 分类于AI Agent 系统设计

供应链 AI Agent 接收自然语言经营目标（例如「华东仓未来 4 周要保证不断货，同时把滞销库存压降 20%，预算 200 万」），完成需求预测、缺口推演、补货与调拨建议生成、供应商评估与询价、多级履约调度、异常处置与根因归因。它和其它 Agent 最大的差别在决策周期：一次补货的后果 45 天后才兑现，错单撤不回——货已经在路上，钱已经付了，合同已经签了。难点不在模型算得多准，而在「决策周期长、物理约束硬、多方协同」这三件事叠加之后，怎么在承诺之前把错误拦住。本章围绕需求预测分层与牛鞭效应、安全库存与补货约束、多级履约与异常归因展开。

11.1 供应链 Agent 是什么

第一段 · 供应链 Agent 是什么这一段回答：供应链 Agent 究竟是什么、给谁用、与既有系统差在哪，以及哪些决策一旦做错就要停机迁移。

11.1.1 定义与三个根本差别

本章要点

供应链 AI Agent 接收自然语言经营目标（例如「华东仓未来 4 周要保证不断货，同时把滞销库存压降 20%，预算 200 万」），完成需求预测、缺口推演、补货与调拨建议生成、供应商评估与询价、多级履约调度、异常处置与根因归因。它与其它 Agent 有三个根本差别：决策周期长，一次补货的后果 45 天后才兑现；物理约束硬，仓容、MOQ、箱规、供应商产能、承运商运力都是硬边界；多方协同，供应商、仓库、承运商、门店各有各的目标与承诺。三个差别合起来决定了本章的架构重心——供应链 Agent 不能像营销 Agent 那样「先做再熔断」，因为营销发错的消息能撤回一部分，供应链的错单不行：货已经在路上，钱已经付了，合同已经签了。

思考笔记

最容易被低估的是第一个差别。「决策周期长」意味着纠错窗口落在决策点之后而不是之前：45 天前下的单，你只有等到 45 天后才知道错了，那时货已经躺在库里卖不掉。所以这套系统的错误拦截必须发生在下单之前，而不能寄希望于事后调整。这是它与客服、营销两章在工程上分野最大的地方，也是本章所有护栏的位置都压在承诺之前的原因。

定义：供应链 AI Agent 是面向商品供给与履约链路的智能体系统。它接收自然语言的经营目标（如「华东仓未来 4 周要保证不断货，同时把滞销库存压降 20%，预算 200 万」），完成需求预测、缺口推演、补货与调拨建议生成、供应商评估与询价、多级履约调度、异常处置与根因归因。

它与前面几章的 Agent 有三个根本差别，这三个差别决定了本章的架构：

差别具体含义对设计的影响
决策周期长一次补货决策的后果在 45 天后才兑现错误不能靠「马上改」补救，必须在决策前拦住
物理约束硬仓容、MOQ、箱规、供应商产能、承运商运力都是硬边界模型输出是建议，不是指令；约束求解层不可省

这三个差别合起来意味着：供应链 Agent 不能像营销 Agent 那样「先做再熔断」。营销的错消息能撤回一部分，供应链的错单不行——货已经在路上，钱已经付了，合同已经签了。所以本章的护栏重心全部压在下单之前。

11.1.2 三个能力层次、用户场景与相近系统

本章要点

能力分三层：L1 执行回答「补多少、发给谁」，决策周期日或周；L2 优化回答「怎么摆、怎么调」，周期周到月；L3 决策回答「换供应商还是换渠道、要不要砍 SKU」，周期季到年。用户面覆盖计划员、采购、仓储、物流与管理层，风险各不相同——计划员要建议可解释且约束可满足，采购怕承诺超产能，物流怕承诺时效兑现不了，管理层只看金额不看风险敞口。与 ERP、WMS、TMS 和传统 MRP/S&OP 的区别在于：ERP 有账无脑，记录发生了什么但不判断该发生什么；WMS 管库位与批次，不管「该进多少货」；TMS 管在途，不管「要不要发这一单」；MRP 规则固定、层级逐级、不看异常。

思考笔记

「有账无脑」四个字划清了 Agent 与 ERP 的边界。供应链 Agent 的产出不是账，是建议与约束求解的结果——账仍然由 ERP 记，但「该发生什么」这个判断得有人来做，而这个判断恰恰是在逐级传递中最容易被放大的地方。这也解释了为什么它不能像 ERP 那样只做记录与执行：记录不放大，判断才放大。

三个能力层次：

L1 执行补多少、发给谁补货单、调拨单、发货单日 / 周中
L2 优化怎么摆、怎么调多级库存配置、调拨路径、订单分配周 / 月较高
L3 决策换供应商还是换渠道、要不要砍 SKU寻源建议、组合优化、供应网络方案季 / 年高

11.1.3 系统边界、核心指标与不可逆决策

本章要点

范围内是需求预测与预测分层、库存水位与缺口推演、补货与调拨建议生成、供应商评估与寻源建议、履约异常检测与处置建议、库存资金与周转分析；范围外是商品主数据生产、采购合同法律条款、仓库作业与库位管理、实际下单与合同签署、承运商实际运输与财务结算。核心指标覆盖服务、库存、成本、预测、履约、系统六类，其中两个是本章特有：分位数覆盖率衡量预测区间准不准，产能挤占率衡量一个 SKU 的决策吃掉了多少供应商资源，后者是最容易被忽略、后果最严重的一个。SLO 的形态与其它章完全不同——实时性要求低得多，但重复下单 0、对账差异率 ≤ 0.01%、约束违反的建议 0 这三项硬约束更多；本章七项不可逆决策覆盖库存成本核算口径、安全库存公式、预测粒度与层级、库存事实源、主数据主键、订单承诺契约与重规划触发条件。

思考笔记

「重复下单 0」是本章唯一会立刻造成现金损失的失败模式：货订两次，钱付两次，货到两次。对应的护栏是「不重试不落单」——下单写入失败时宁可不写、转人工核销，也不重试。在一个 45 天后才暴露错误的系统里，这种看起来过于保守的做法是唯一能用的选择。另外注意七项不可逆决策的共同点：它们都改变了「每一个数字怎么算」，而不只是改了某个参数，所以做错时要停机迁移加全量回填。

对照「单向门与双向门」的判据：这七项属单向门，决策时要多评审、做原型、留迁移方案。其余（预测模型选择、求解器选型、服务水平 z 值数值、批量大小、提前期）是双向门，可以快速试错——但 z 值与服务水平分层的口径属于「可逆但很贵」：它们改变每一笔补货量，必须伴随离线回测。

第二段 · 核心矛盾与设计原则这一段回答：逐级放大与不可撤销之间的矛盾到底有多大，以及六条原则在冲突时凭什么说了算。

11.2.1 本质与六条章级原则

本章要点

核心矛盾是「让每一级都做出最优决策」与「让信息在逐级传递中不失真」之间的冲突——每一级拿到的都不是真实需求，而是上一级被加工过的订单。模型越准，放大的误差越大，因为它更忠实地执行了一个被扭曲的信号。六条章级原则规定了冲突时以谁为准：物理约束优先于模型偏好，预测越接近终端越好，决策周期与数据窗口必须匹配，不确定性必须变成显式缓冲而不是被平均掉，不可撤销的承诺要分级审批，每次重规划都要能解释「为什么变了」。

思考笔记

六条里最容易被跳过的是第三条「决策周期与数据窗口必须匹配」：日级补货决策如果只用 5 分钟的抖动数据、或者只看 3 年前的历史，再准的模型也没用。它和第四条「不确定性必须变成显式缓冲」是一对：一条管输入的时间尺度，一条管输出的概率形状。第二条「预测越接近终端越好」看着像常识，但它的极端版本——屏蔽上游订单量——反而是反直觉的，那条会在第三段展开。

本质：供应链 Agent 的核心矛盾，是「让每一级都做出最优决策」与「让信息在逐级传递中不失真」之间的冲突。每一级拿到的都不是真实需求，而是上一级被加工过的订单。 模型越准，放大的误差越大——因为它更忠实地执行了一个被扭曲的信号。

六条章级原则（贯穿全章，冲突时以这六条为准）：

  1. 物理约束优先于模型偏好——模型说补 5,000 件，但仓容只允许 3,000、MOQ 是 1,000、提前期 45 天、供应商月产能 8,000。约束求解层永远在模型之上，模型的输出是建议，不是指令。
  2. 预测越接近终端越好——逐级预测必然放大。能直接看终端 POS 数据，就不要看上一级的订单。
  3. 决策周期与数据窗口必须匹配——日级补货决策不能只用 5 分钟的抖动数据，也不能只用 3 年前的历史。窗口不对，再准的模型也没用。
  4. 不确定性必须变成显式缓冲，而不是被平均掉——补货决策要的是分位数（P50 / P90 / P95），不是点估计。点估计 + 固定安全库存 = 把风险藏在了一个拍出来的常数里。
  5. 不可撤销的承诺要分级审批——下单给供应商 = 现金支出 + 履约义务 + 产能挤占。金额小、量大、品类敏感三种风险要分别设阈值。
  6. 每次重规划都要能解释「为什么变了」——补货建议从 5,000 变成 3,000，必须能归因到「销量预测下调」「仓容收紧」「供应商延期」。不能解释的重规划，执行侧就不敢执行，计划也就废了。

11.2.2 三个不等式与三个放大器

本章要点

三个不等式划出了本章的物理边界：终端需求的小波动远小于上游订单的大波动（牛鞭效应，逐级放大 16 倍），补货决策的周期远长于纠错能到达的时间（货在 45 天后，错误无法撤回），模型能给的最优远大于物理世界允许的最优（约束求解层不可省）。三个放大器是本章最贵的量：牛鞭放大让终端 ±10% 变成原料订单 ±160%；库存资金放大让预测误差减半对应年库存总成本降 39%；产能挤占放大让 1 个 SKU 的错误变成 20 个 SKU 延期 3 天。

思考笔记

三个放大器里产能挤占最阴险，因为它的暴露是延迟的：超量订单当天所有看板都显示正常，要几天后其它 SKU 陆续延期才看得出来。所以对它的防御不是「更保守」，而是「看得见」——供应商产能视图必须进求解器，按产能做全局分配。逐 SKU 独立求解再汇总，就是产能挤占的系统性来源。

三个不等式：

终端需求的小波动  <<  上游订单的大波动    → 牛鞭效应：逐级放大 16 倍
补货决策的周期    >>  纠错能到达的时间    → 货在 45 天后，错误无法撤回
模型能给的最优    >>  物理世界允许的最优  → 约束求解层不可省

三个放大器（本章最贵的量都藏在这里）：

放大器说明后果量化
牛鞭放大（信息失真）需求信号沿供应链逐级被加工放大产能、库存、运力全被推到错误的位置终端 ±10% → 原料订单 ±160%，放大 16 倍（牛鞭效应：信息失真的四类机制）

11.2.3 四类正确性与八组关键矛盾

本章要点

四类正确性必须分开保证：预测正确要的是需求分布而非点估计，靠分位数预测与区间校准；可执行正确要的是建议满足全部物理约束，靠约束求解与可行性校验；账实正确要的是库存数量与金额对得上，靠幂等事件与全量对账；承诺正确要的是对上下游的承诺可兑现，靠承诺契约与违约监控。八组关键矛盾各配默认策略与反转条件：服务水平对库存资金、集中对分散、安全对灵活、稳定对响应、自营对外包、成本对时效、预测对响应、全局最优对局部最优。

思考笔记

四类正确性的排序透露了判断：预测正确排在最前，但它的典型漏法是「MAPE 好看却系统性高估」，说明它其实是四类里最好测、也最容易给人虚假安全感的一类。真正需要独立工程投入的是账实正确与承诺正确，它们和模型能力无关，纯粹是幂等、对账与契约的事。把四类混成一类，就会在模型指标全绿时被账实问题打个措手不及。

11.2.4 失败模式、信任分级与成本结构

本章要点

八类失败模式各有防线：牛鞭靠共享终端数据与缺货感知，超量靠促销日历与缺货率入模，欠量靠分位数预测与分层服务水平，积压靠动态安全库存与生命周期特征，不可执行靠约束求解与可行性校验，账实不符靠幂等事件与全量对账，产能挤占靠产能分配与违约监控，重复下单靠下单幂等键与计划版本。信任分级给建议标注了四种输出契约：高等级直接给可执行建议，中等级给建议加区间加风险提示，低等级只给数据与风险、明确不给补货量，约束不可满足时明确说清哪条约束挡住了。成本结构里库存持有成本最大，常占收入 15–30%，模型与计算成本可以忽略。

思考笔记

「不给补货量也是一种输出」是这一节里最反直觉但最正确的一条。当库存账实不符时，系统给一个精确的补货数字，等于给了一个精确的错误答案，而执行侧会照单执行，45 天后变成一批错货。这与营销章「宁可不发」的逻辑同源：不产出也是一种合规的产出。反过来看，信任分级里的「拒绝」档是设计出来的一等公民，它要求系统有能力说「我算不了」，而不是硬凑一个数字出来。

本章要点

七项前置锚点划定可行域：业务目标与成功标准、规模量级、质量属性优先级、硬约束、不可逆决策清单、核心路径与事实源、竞争与协作边界。第 2 项之所以改变答案，是因为供应链的规模参数不只是 QPS，还有补货周期与提前期：同样是 SKU 50 万、日销 200 万件，提前期 45 天还是 5 天，安全库存差约 3 倍（√45/√5），不给提前期分布就算不出安全库存，整个补货模型就无从谈起。4S 收敛顺序是定题、场景、服务、存储、规模。

11.3.2 场景与规模参数

本章要点

规模给全：在售 SKU 50 万、仓 200、日销 200 万件 / 80 万单、供应商 300 家（主供 30 家）、单次订货成本 ¥2,000、单位库存成本 ¥60 且持有成本率 25%/年（h = ¥15/件/年）。三个决定一切的参数是补货周期（常规 7 天、大促 3 天）、提前期 L（海运 45 天、陆运 7 天、空运 5 天）与服务水平分层（A 类 99%、B 类 97%、C 类 95%），ABC 分层是 A 类 20% 占 80% 销量、B 类 30%、C 类 50%。决策节奏是 T+1 日批加事件驱动重规划，对应「批量轨道 + 在线轨道」两条链路。

思考笔记

服务水平按 ABC 分层而不是全局一个数，是这一节最实用的一个决定。它的含义是长尾 SKU 主动接受更差的服务水平，把资金让给高价值品类——这与「全线提高服务水平」的直觉相反。所以服务水平的设定不是技术参数，而是资金配置决策：定错了，后面所有成本推导都会跟着错。

11.3.3 服务、存储与扩展兜底

本章要点

11 个服务分清同步与异步：预测与求解异步离线批，缺口推演同步，承诺下单同步且必须幂等加版本，异常检测同步事件驱动，对账异步批。存储侧的事实源只有四类——库存流水、订单与履约记录、主数据、供应商履约记录，预测表、建议表、可用量缓存与求解任务全是可重建的投影。库存的口径四件套是实物、可用、在途、可售，每个数字都必须说清是哪一种；库存流水的不可变性是地基，因为库存是派生量，只能由事件累加得到，任何直接改写库存的接口都必须被禁止。扩展与兜底六个维度：预测用 ABC 分层，计划用 T+1 批加事件驱动增量重规划，求解用分区与启发式加精确混合，库存用事件流加增量聚合，异常用规则优先，依赖故障时降级到规则补货并冻结下单。

11.3.4 需求预测与预测分层

本章要点

预测必须输出分位数而不是点估计：P50 用于常规补货基线，P90 对应 A 类高服务水平，P95 与 P99 用于极端场景与加急预案。ABC 分层对应三套粒度：A 类 20% 的 SKU 承担 80% 销量，做 SKU × 仓 × 日、60 天窗口的融合模型加促销特征；B 类做 SKU × 大区 × 日、30 天；C 类 50% 的 SKU 只占 5% 销量，做类目 × 日、14 天，并给类目均值加人工兜底。预测不只要准，还要校准：评测主指标是区间覆盖率与偏置，WAPE 只是辅助；特征清单里必须有的四项是终端 POS、促销日历、缺货率与生命周期阶段。

思考笔记

「C 类不做个体预测不是偷懒，是正确的资源分配」——但后面那句「但必须给兜底值」才是重点：用类目均值必须是一个写进模型的明确规则，而不是「预测不出来就填 0」。填 0 会让 C 类全部断货，这是把「省资源」变成「造事故」的典型路径。另外「WAPE 好看但区间不校准是最危险的组合」值得记：点估计误差会互相抵消，而安全库存是按分位数算的，点准而区间偏，安全库存照样系统性错。

11.3.5 牛鞭效应：信息失真的四类机制

本章要点

牛鞭效应指终端需求的小幅波动沿供应链逐级被放大：终端 ±10% 依次变成零售商 ±20%、批发商 ±40%、制造商 ±80%、原料 ±160%，放大 16 倍。四类机制分别是预测逐级叠加、订单批量、价格促销与缺货配给，其中只有第一类是 Agent 直接放大的——批量与促销是商务政策、配给是缺货的后果，Agent 只能在设计里补偿。治牛鞭的四条落地动作是特征层屏蔽上游订单量只保留终端销售、促销日历进特征、缺货率进特征并对缺货期需求做还原、需求信号按周建模而非按日。

思考笔记

这一节最反直觉也最重要的一条是「放弃一部分信息」：上游订单量明明是最丰富的特征，屏蔽它看起来像自缚手脚，但它正是牛鞭的第一机制。在逐级预测的架构里，「看得更近」比「看得更多」重要。一个用了最先进模型、却只在上一级订单上预测的 Agent，比一个用移动平均、但直接看终端销售的 Agent 更糟——因为它会把扭曲的信号忠实地放大 16 倍。

11.3.6 库存策略：再订货点与安全库存

本章要点

再订货点模型是 ROP = d̄ × L + SS，其中 SS = z × σ_daily × √L，z 按 ABC 分层取 2.33、1.88、1.645。把基准值代进去：日均需求 1,000 件、σ 200 件、提前期 5 天、缺货成本 ¥80/件时，安全库存 736 件、年缺货成本约 ¥24.6 万、年持有成本约 ¥8.5 万、年库存总成本约 ¥33.1 万——缺货成本是持有成本的 2.9 倍。Agent 的价值体现在把预测误差减半：σ 从 200 降到 100，安全库存 736 变 368 件，总成本降 39%（省 ¥12.8 万）。动态安全库存的三个输入是需求波动 σ、提前期 L 与服务水平 z，全部要从静态常数改成动态估计。

思考笔记

「Agent 的价值不在预测得更准本身」是全章的核心结论，准只是手段，它兑现的路径是安全库存减半——而安全库存之所以能减半，是因为 SS 与 σ 成正比、σ 又与预测精度同向。但要注意反向陷阱：SS 与 √L 成正比，缩短提前期看着更省，可提前期波动的那部分不受这个折扣保护。缩短提前期是最有效的降库存手段，但它要动供应链本身，不是模型能替代的。

11.3.7 补货决策与约束求解

本章要点

补货量不是「缺口」，而是「约束下的最优」：名义缺口等于目标库存减可售库存，实际补货量是在约束下最接近名义缺口且可行的量。约束清单分硬软：MOQ、箱规、仓容、供应商月产能、承运商周运力、合同价与量价阶梯是硬约束，持有上限与效期、预算上限、服务水平偏差是软约束。产能挤占是最容易被忽略的硬约束：一次超量下单 10,000 件而供应商月产能只有 8,000 件，就吃掉 125% 的月产能、挤占另外 25%，让其它 20 个 SKU 平均延期 3 天。求解器三层策略是规则补货、启发式加局部调整、精确求解。

思考笔记

「逐 SKU 独立求解是产能挤占的系统性来源」这句话值得贴在墙上，它揭示了一种常见的架构惰性：每个 SKU 各自算各自的最优，汇总起来就超出了供应商的真实产能，而且当期看板完全看不出来。所以产能视图必须进求解器，按产能做全局分配。另外三层求解器的定位是「先进兜底落后」而不是「先进替代落后」——求解器超时或数据缺失时必须能退回规则层继续出计划，「规则补货是永远可跑的最后一层」是硬性架构约束，不是可选项。

补货决策与约束求解

补货量不是「缺口」，是「约束下的最优」：

名义缺口 = 目标库存（ROP + Q*/2） − 可售库存（可用 + 在途）
实际补货量 = 在约束下最接近名义缺口且可行的量

约束清单（求解器必须全部满足）：

约束类型违反后果
供应商 MOQ（最小起订量）硬供应商拒单
箱规 / 包装规格硬无法发货
仓库容量与库位硬货到无处放
供应商月产能硬（共享）挤占其他 SKU
承运商周运力硬排队或拒运
合同价与量价阶梯硬违反合同价
库存持有上限 / 效期软（可带惩罚）积压与减值
预算上限软超支
服务水平偏差软缺货或积压

产能挤占是本章最容易被忽略的约束：

一次超量下单 10,000 件，供应商月产能 8,000 件
→ 该 SKU 占掉月产能的 125%
→ 挤占另外 25% 的产能
→ 供应商其它 20 个 SKU 平均延期 3 天
→ 缺货成本 = 20 SKU × 3 天 × 日销 × 毛利

一次错误决策的影响面从 1 个 SKU 变成了 20 个 SKU。 而且这 20 个 SKU 的延期是在几天后才暴露的——当期所有看板都显示正常。这就是「产能挤占放大」：它是唯一一个会把 1 个错误变成 N 个错误、且延迟暴露的机制。

对策不是「更保守」，而是「看得见」：供应商产能视图必须进入补货求解器，求解时按产能做全局分配，而不是每个 SKU 各自算完再汇总。逐 SKU 独立求解，是产能挤占的系统性来源。

求解器的三层策略：

层方法适用特点
1规则补货（ROP + EOQ）兜底、C 类 SKU毫秒级、永远可跑
2启发式 + 局部调整B 类、大部分场景快、可解释
3精确求解（整数规划 / CP）A 类、跨仓调拨、新品首发慢，但全局最优

三层不是「先进替代落后」，而是「先进兜底落后」。求解器超时、算力不够、数据缺失时，必须能退回规则层继续出计划——而不是整个计划失败。「规则补货是永远可跑的最后一层」是本章的一个硬性架构约束。

11.3.8 供应商选择与履约调拨

本章要点

供应商评估五个维度是履约、质量、产能、商务与集中度，其中产能维度决定「能不能挤占别人」，集中度过高则是单点风险。寻源建议必须给出替代方案，并按可替代性分层转移比例：完全可替代转移 80%，部分可替代（认证、模具、包材限制）转移 20%，不可替代只能加急或降级供应。多级履约的三个决策是库存配置、履约路由与调拨；缺货的三级处置是跨仓调拨（¥3/件、1 天）、供应商加急空运（¥30/件、5 天）、放弃销售（毛利损失 ¥80/件），成本比 1 : 10 : 27。

思考笔记

「不可替代」这一档的存在，是供应链与其它 Agent 的重要差别：营销可以随便换一个渠道，供应链很多物料换个供应商要 3 个月认证。所以替代方案不是一个建议，是一道必须提前回答的问题——主供明天就断，备选是谁、能不能接、多久能接上。同样值得记的是那句操作原则：先找库存，而不是先找货。若默认动作是「催供应商加急」，那是在花 10 倍的钱买 4 天的速度。

供应商选择与寻源

供应商评估的五个维度：

维度指标为什么重要

产能月产能、可用产能窗口决定能不能挤占别人

集中度该供应商占该品类采购额比过高则单点风险

寻源建议必须给出「替代方案」：换供应商不是把量全给新供应商，而是按可替代性分层：完全可替代 → 转移 80%；部分可替代（认证、模具、包材限制） → 转移 20%；不可替代 → 只能加急或降级供应。

多级库存的三个决策：

决策问题关键约束

缺货三级处置决策树（本章最实用的一张图）：

缺货发生
  → 第一步：跨仓调拨（¥3/件，1 天到）
  → 第二步：供应商加急空运（¥30/件，5 天到）
  → 第三步：放弃销售（毛利损失 ¥80/件 + 客户流失）
  → 成本比 调拨 : 加急 : 放弃 = 1 : 10 : 27

调拨不是万能的：它受调拨仓自身库存约束（把 A 仓调给 B，B 的销量要靠 C 补上，C 又可能没有——调拨只是把缺口往后挪，不一定消除它），而且受调拨本身的物流成本与时效约束。所以调拨决策必须看全网库存，不能只看两个仓。

「先找库存，而不是先找货」是本章的核心操作原则。 一次 1,000 件的缺口：调拨花 ¥3,000、加急花 ¥30,000、放弃损失 ¥80,000。调拨比加急便宜 10 倍，比放弃便宜 27 倍。 大多数系统的默认动作是「催供应商加急」，那是在花 10 倍的钱买 4 天的速度。

11.3.9 异常归因、对账、评测与容量成本

本章要点

异常处置分四类：缺货、延迟、超量积压、质量异常，各自的检测信号、根因方向与处置动作都不同；归因必须区分需求侧、供给侧、物流侧与数据侧，其中数据侧的账实不符必须先修账再谈补货。对账有三条线：账实对账日/周、差异 ≤ 0.1%，在途对账日、差异 ≤ 0.01%，订单对账日、差异必须为 0；差异超阈值即冻结对应范围的自动补货。评测侧，离线主指标是区间覆盖率、偏置与牛鞭系数（上游订单波动除以终端需求波动，可逐层测，被称为供应链系统的「体温」），在线指标是缺货率、OTIF、建议采纳率与修改率；回测三条纪律是回放完整策略、包含促销与缺货期样本、使用当时的库存状态。容量侧，本章的容量单位不是 QPS 而是「一个补货窗口内能算完多少计划」：峰值只有约 56 个 SKU 决策/秒、在线轨道峰值约 1,400 QPS，但单次精确求解要 30–120 秒，200 个计划不可能串行跑完，批量轨道全链路硬限 8 小时。成本侧的结论是钱主要花在库存持有与缺货上，模型成本可忽略，杠杆排序是降 σ 与降 L。

思考笔记

「牛鞭系数是本章的体温计」这个说法能解释很多现场现象：WAPE 变差说明模型不准了，牛鞭系数变差说明架构里某处的信息在失真——后者是架构问题，改模型没用。对账那三行里最容易漏的是在途对账：系统显示已下单 10,000 件而供应商只确认了 8,000 件，这 2,000 件的缺口从那一刻起就存在，却没有任何看板会显示它，直到货期到了才发现到不了。成本杠杆的排序同样值得留意：降 σ 和降 L 都作用在同一个公式 SS ∝ σ × √L 上，其余手段都不在这两个变量上，天花板很低。

最后一档是本章特有的高频陷阱：很多「缺货」其实是账实不符。在账实不符被修复之前，任何补货决策都是在给一个假缺口补货。 所以异常处置的第一步永远是先校验账实，再判断根因。

承诺兑现率是本章特有的过程指标：

承诺兑现率 = 按承诺期到货的订单量 / 承诺订单量

它同时衡量供应商履约、内部承诺管理与异常响应的质量。低于阈值时，下游的可售量承诺就不该继续往下游传——否则缺货会从供应商一路传导到渠道，形成断货的连锁反应。

三条对账线：

在途对账是本章最容易漏掉的一条。系统里显示「已下单 10,000 件」，如果供应商只确认了 8,000 件，那么这 2,000 件的缺口从这一刻起就存在，但没有任何看板会显示它——直到货期到了才发现到不了。在途库存是补货决策的输入，它错了，缺口推演就全错。

11.4 工程落地与规则护栏

第四段 · 工程落地与规则护栏这一段回答：方法论怎么变成链路上的一环一环——哪些依赖必须 fail-closed，哪些可以降级，降级时打什么标。

11.4.1 端到端链路与目标解析护栏

本章要点

端到端链路十一站，从自然语言目标、目标解析、预测、库存、缺口推演、约束求解、寻源与承诺、履约、异常、对账到审计与校准；两条轨道分别是 T+1 批量轨道（8 小时内必须完成，否则错过下一个补货窗口）与毫秒级在线轨道，另有事件驱动重规划与规则兜底层。目标解析护栏五条：输出结构化 JSON 且缺字段必须追问，必须显式确认服务水平目标、预算上限、约束清单、可接受提前期与不可动物料，必须解析出「缺口口径」（按可售还是实物、按本级需求还是终端需求），高风险目标强制审批，解析结果可回放可审计。

思考笔记

「缺口口径不问清，后面所有数字都是空的」是这一节的核心。同一句「未来 4 周要保证不断货」，按可售库存还是按实物库存算、按本级需求还是按终端需求算，缺口可以从 18,600 件变成另一个数，而求解、采购与预算全都建在这个数上。所以目标解析阶段的追问不是流程上的客气，它是这一章里唯一一次能低成本纠正口径的机会。

  → Fulfilment（多级路由、批次分配、效期先出）
  → Exception Service（缺货 / 延迟 / 超量 / 质量 → 局部重规划）
  → Reconcile Service（账实对账 + 在途对账 + 订单对账）
  → Audit & Calibration（决策留痕 + 牛鞭系数监控 + 模型回放）

两条轨道：

T+1 批量轨道
  → 数据清洗 → 特征 → 分位数预测 → 缺口推演 → 约束求解 → 审批
  → 8h 内必须完成，否则错过下一个补货窗口

在线轨道
  → 库存查询 / 异常检测 / 下单写入 / 承诺下发（毫秒级）
  → 决策 P95 < 200ms

事件驱动重规划
  → 缺货 / 延迟 / 超量 / 质量异常 → 只重算受影响的 SKU × 仓
  → 全网重排会让执行侧无所适从

规则兜底层
  → ROP + EOQ 规则补货：永远可跑，求解器超时也出得了计划

这张图里有三条「不可省」的线：约束求解（模型只是建议）、规则兜底层（永远能出计划）、对账（账实不符时不能补货）。前两条决定系统能不能跑，第三条决定它跑出来的东西是不是真的。

目标解析护栏

  • 输出结构化 JSON，字段缺失必须追问。
  • 必须显式确认：服务水平目标、预算上限、约束清单、可接受的提前期、不可动的物料（认证 / 模具限制）。
  • 必须解析出「缺口口径」：按可售库存还是按实物库存？按本级需求还是终端需求？口径不问清，后面所有数字都是空的。
  • 高风险目标（全网大额、动认证物料、单一供应商超集中）强制审批。
  • 解析结果可回放、可审计。

思考笔记

11.4.3 补货、履约与审计护栏

本章要点

补货与约束护栏十条，P0 有七条：约束不可违反（违反数为 0）、产能可见（禁止逐 SKU 独立求解后汇总）、不可逆承诺分级审批、重复下单为 0（计划版本加幂等键，写入失败不重试不落单）、单 SKU 与单供应商补货量上限、生效范围不得超过最大仓容与最大库龄。履约与异常护栏强调下发前复核承诺的量、期、价、批次四项锁定，承运商运力与时效承诺必须来自合同能力声明而非模型估计，承诺兑现率低于阈值即停止向下游继续承诺，异常检测必须区分需求侧、供给侧、物流侧与数据侧，且数据侧的账实不符必须先修账再谈补货。审计与对账护栏给出三条对账线（账实 ≤ 0.1%、在途 ≤ 0.01%、订单差异必须为 0）与超阈值即冻结对应范围自动补货。

思考笔记

「建议被采纳后改了多少」是这一节里最有价值的一个审计字段，因为它衡量的是模型与计划员的真实分歧。长期分歧大，说明要么模型不准、要么约束口径没对齐，两者都需要修，而不是让计划员每次手工覆盖。这也解释了为什么不能只看采纳率：采纳率高可能只是大家懒得改，修改率才是分歧的诚实读数。另一个必须记住的是订单对账差异必须为 0，它比另外两条严得多，因为另外两条只影响账，订单差异直接等于重复下单。

11.4.4 降级矩阵与延迟预算

本章要点

降级的判据只有一条：依赖失效时，失效的后果是「少补一点」还是「多买一批 / 少卖一单」。据此，库存账实、在途确认、供应商主数据与价格、ERP/WMS 写入、主数据映射全部 Fail-Closed；供应商产能视图按上次已知产能打折 50% 分配；预测退回类目均值加移动平均；求解器三级降级到规则补货；承运商运力按历史均值估算并下调时效承诺；促销日历缺失时按无促销预测并标记高风险批次。延迟预算分在线与批量两条轨道：在线下单写入硬限 2 秒且 Fail-Closed，批量轨道从拉数清洗到审批下发全链路硬限 8 小时。

思考笔记

「不重试不落单」是降级矩阵的第一原则：重试一次下单就是多买一批货，而重试恰恰是超时场景里最自然的下意识动作。它和营销章的「不重试」是同一个道理，但供应链的下场更重——营销重试最多多发一条消息，供应链重试多出的是一整车货。另一处要点是 8 小时硬限：别的系统超时是「慢一点」，本章超时是「这一轮计划废了」，所以求解必须分层降级，审批必须顺延而不是无限等。

11.4.5 观测压测、护栏清单与上线检查

本章要点

观测分八类，其中两个是本章特有的健康指标：牛鞭系数（订单波动比终端需求波动）与产能挤占率；决策类里的建议采纳率与建议修改率要一起看。压测九项覆盖单窗口 200 个计划并发、单计划 2,000 SKU 精确求解超时、提前期从 45 天跳到 90 天、供应商产能骤降 50%、库存流水重复事件、在途确认接口超时与 ERP 写入超时。规则护栏清单 18 条，其中十项 P0，七项是「下单之前」的检查。另有上线检查 10 问，其中第 2 问直接问「预测特征里是否有上游订单量」，第 10 问问「牛鞭系数是否被逐层测量」。

  3. 预测是否输出分位数？区间覆盖率与偏置是否独立监控，而不是只看 WAPE？
  4. 安全库存口径是否全网统一（z 值分层、提前期取均值还是 P90、σ 怎么估）？
  5. 约束求解器是否读供应商产能视图？是否仍存在逐 SKU 独立求解后汇总的路径？
  6. 建议发出前是否通过可行性校验（MOQ / 箱规 / 仓容 / 运力 / 合同价）？违反数是否为 0？
  7. 下单是否幂等？写入失败是否「不重试不落单」？ 是否有任何路径会重复下单？
  8. 账实 / 在途 / 订单三条对账线是否都已上线？差异超阈值是否真的会冻结自动补货？
  9. 降级矩阵是否演练过？求解器超时是否能退回规则层出计划？ 降级是否打了 degraded + 原因码？
  10. 牛鞭系数是否被逐层测量并监控？ 建议采纳率与修改率是否有看板？

11.5 端到端案例

第五段 · 端到端案例这一段回答：一个真实的补货与滞销压降目标怎么走完整条链路，以及四个变体分别暴露什么。

11.5.1 案例：华东仓断货风险与滞销压降

本章要点

目标是「华东仓未来 4 周要保证不断货，同时把滞销库存压降 20%，预算 200 万」。链路十步里最关键的是第一步：系统主动追问「在途是否计入」，缺口口径定为 P90 需求（4 周）减可售库存，得出的缺口是 120 个风险 SKU 合计 18,600 件。约束求解后直接补货只能覆盖 76 个 SKU、13,200 件；调拨覆盖 31 个 SKU、4,100 件花 ¥12,300；剩余 9 个 SKU 走空运加急 ¥30,000；4 个 SKU、300 件因毛利低于加急成本而主动接受缺货；18,300 件采购花 ¥109.8 万，低于 ¥200 万预算。滞销压降释放 ¥720 万，比补货预算还多 3.6 倍。牛鞭验证给出全章最硬的一组对比：用上游订单量做特征 WAPE 18%、牛鞭系数 2.4，改用终端 POS 加促销日历加缺货率后 WAPE 15%、牛鞭系数 1.3。

思考笔记

这个案例最该带走的是两个数字的对比：WAPE 只降了 3 个点，牛鞭系数却降了 46%。如果只看 WAPE，会得出「提升有限、不值得投」的结论——而真正该看的指标是牛鞭系数，它从 2.4 降到 1.3 意味着上游订单的波动从终端的 2.4 倍回到 1.3 倍，产能、库存与运力不再被推到错误的位置上。另一个数字是滞销压降释放 ¥720 万远大于补货预算 ¥200 万：「砍库存」和「补库存」是同一笔钱的两个方向，压降指标不是需求侧的附属项，它就是补货预算的来源。

案例：华东仓断货风险与滞销压降

目标：「华东仓未来 4 周要保证不断货，同时把滞销库存压降 20%，预算 200 万。」

S0 落锚点：

#锚点本案例答案
1成功标准断货 SKU 数 0、A 类缺货率 ≤ 1%、滞销金额降 20%、OTIF ≥ 98%
2规模华东 3 仓、A 类 SKU 4,000 个、风险 SKU 120 个、滞销 SKU 860 个
3质量优先级不断货 > 不积压 > 不违约 > 资金成本 > 响应速度
4硬约束仓容 12,000 m³、主供商本月产能已用 62%、预算 ¥200 万、MOQ 与箱规
5不可逆清单库存成本口径、安全库存口径、预测粒度、账实归属、主数据标识、承诺契约、重规划范围
6事实源库存流水 + 订单 + 主数据 + 供应商履约记录
7边界ERP / WMS / TMS 与供应商门户在外部；预测、缺口推演、求解、异常处置自建

链路：

  1. 目标解析：确认缺口口径 = P90 需求（4 周）− 可售库存（可用 + 在途，按 ETA 计入），服务水平 A 类 99%；「滞销」定义为库龄 > 90 天且近 8 周无动销。系统主动追问「在途是否计入」——这一条决定了后面 18,600 件里有多少是真实缺口。
  2. 预测（T+1 批）：A 类 SKU × 仓 × 日 × P50/P90/P95；特征 = 终端 POS + 促销日历 + 缺货率 + 生命周期，不含上游订单量。
  3. 缺口推演：120 个风险 SKU，合计缺口 18,600 件；按提前期分组：陆运 7 天 7,200 件、海运 45 天 11,400 件。
  4. 约束求解（精确 + 产能视图）：受 MOQ / 箱规 / 仓容 / 主供商剩余产能 38% / 预算约束，直接补货只能覆盖 76 个 SKU、13,200 件。
  5. 调拨：华东三仓互调 + 相邻华中仓调入，覆盖 31 个 SKU、4,100 件，物流 ¥3/件 = ¥12,300。
  6. 加急与取舍：剩余 9 个 SKU 走空运加急（1,000 件，¥30/件 = ¥30,000）；4 个 SKU、300 件因毛利低于加急成本而主动接受缺货。
  7. 采购与预算：18,300 件 × ¥60 采购成本 = ¥109.8 万 < ¥200 万预算，余额 ¥90.2 万。
  8. 滞销压降：860 个 SKU、占用资金 ¥3,600 万；压降 20% = 释放 ¥720 万——比补货预算还多 3.6 倍。
  9. 下单：带计划版本与幂等键写入 ERP，落承诺契约（量 / 期 / 价 / 批次四项锁定）。
  10. 对账：日账实 + 日在途；差异超阈值即冻结对应范围自动补货。

本案例最重要的一个数字：

滞销压降释放资金 ¥720 万  ≫  补货预算 ¥200 万

「砍库存」和「补库存」是同一笔钱的两个方向。 一个只看补货需求的系统，会把「缺货」和「积压」当成两个独立问题分别要预算；真正有效的做法是先算「滞销释放的资金」，再决定补货能力。本章的「压降 20%」不是需求侧的附属指标，它就是补货预算的来源。

用上游订单量做特征18%2.4信号被放大，产能与库存被推到错误位置

11.5.2 变体：周度补货、新品首发与供应商违约

本章要点

变体 A 常规周度补货周期 7 天、SKU 多量大，以规则补货层为主只对异常 SKU 走模型层，计划在补货窗口前 8 小时完成，建议必须附约束余量（离 MOQ、离仓容、离产能各还有多少）。变体 B 新品首发无历史数据，不做点估计只做分位数铺货：首批取 P50，试销期按 P90 追单，首批受 MOQ 约束时取 MOQ，并在上市后第 7、14、30 天强制复盘点。变体 C 供应商延迟与违约处置，下发前复核承诺的量、期、价、批次四项锁定，承诺兑现率低于阈值即停止向下游继续承诺，违约处置走延迟、改承诺期、部分切备供、全切备供的分级切换，不可替代物料必须提前登记。

思考笔记

新品是这一章里唯一一个「模型主动说不知道」的合法场景，此时正确的输出不是「建议铺 1,000 件」，而是「P50 铺 600 件、P90 追 1,400 件，首批受 MOQ 约束取 1,000 件，7 天后按实际曲线决定是否追单」——把不确定性显式交给后续决策，而不是藏在一个点估计里。这个例子说明了一条通用原则：当输入最不可靠时，系统最有价值的输出是分层的选项加一个明确的复核点，而不是一个假装确定的数字。

变体 A：常规周度补货

特点：周期 7 天、SKU 多、量大、时效宽松。

额外护栏：

  • 走规则补货层为主（ROP + EOQ），只对异常 SKU 走模型层。
  • 计划在补货窗口前 8h 完成；求解超时自动降级到规则层。
  • 建议必须附约束余量（离 MOQ、离仓容、离产能各还有多少）。
  • 建议采纳率与修改率进看板——分歧大说明模型或口径要修，不是让计划员每次手工覆盖。

变体 B：新品首发铺货

特点：无历史数据、预测最不可靠、错误成本高（首批压太多就滞销，压太少就断货）。

额外护栏：

  • 不做点估计，只做分位数铺货：首批 = P50，试销期再按 P90 追单。
  • 必须有人工审批（新品是决策，不是执行）。
  • 首单必须考虑供应商 MOQ 与最小起订量——很多新品的合理首批量就是 MOQ，此时「多备一点」不是失误而是约束。
  • 试销期设强制复盘点：上市后第 7 / 14 / 30 天各复核一次销量曲线，偏差超阈值即调整追单。

新品是本章唯一一个「模型主动说不知道」的合法场景。此时正确的输出不是「建议铺 1,000 件」，而是「P50 铺 600 件、P90 追 1,400 件，首批受 MOQ 约束取 1,000 件；7 天后按实际曲线决定是否追单」——把不确定性显式地交给后续决策，而不是藏在一个点估计里。

变体 C：供应商延迟与违约处置

特点：标的时效强，承诺不可兑现。

额外护栏：

  • 下发前复核承诺参数：量、期、价、批次四项锁定。
  • 承诺兑现率低于阈值时，停止向下游继续承诺（否则缺货会沿链传导）。
  • 供应商评估五维中，产能维度必须进补货求解器——否则下一个超量订单会挤占产能。
  • 违约处置走分级切换：延迟 → 改承诺期 → 部分切备供 → 全切备供。
  • 不可替代物料必须提前登记，其主供中断时直接进入「加急 / 降级供应」路径，而不是走常规寻源（认证要 3 个月，来不及）。

11.5.3 调拨替代、故障兜底、扩容与取舍

本章要点

变体 D 跨仓调拨替代补货给出三级处置的成本比 1 : 10 : 27，并强调调拨的隐性成本：调走 A 仓的 1,000 件，A 仓自己的缺口要靠下一轮补货填上，所以真实成本等于物流成本加下一轮补货量的增加，但即便如此通常仍划算，因为下一轮补货是计划内的便宜货，而这一轮缺货是计划外的贵货。故障与兜底补两条：下单接口超时不重试不落单、转人工核销；预测与人工判断冲突不视为模型失败，但必须记录修改量并回流。扩容 10 倍的先坏顺序是批量轨道的求解窗口、预测计算、库存查询、在途对账、产能视图、事件链路、库存持有成本。取舍复盘用九条决策记录各自的代价、收益与重新评估条件。

思考笔记

「计划外的贵 vs 计划内的便宜」是这一段的核心成本直觉，它解释了为什么调拨即使有隐性成本也通常划算。扩容那一段的提醒更刺人：先坏的不是 QPS 而是「一个补货窗口内算不计算得完」，因为它的 QPS 峰值只有 1,400 很轻，但每个计划是 30–120 秒的精确求解，2,000 个计划挤在同一个窗口里——所以扩容的第一件事是「让计划滚动起来」，而不是加机器。最后一位的结论反直觉：新增 SKU 多半是长尾，给长尾提高服务水平的边际毛利小于它带来的持有成本，所以扩容第一个该动的不是把预测做得更好，而是收紧长尾的服务水平。

变体 D：跨仓调拨替代补货

场景：华南某 A 类 SKU 缺 1,000 件，5 天后断货。

三级处置对比：

方案单价到货成本备注
跨仓调拨¥3 / 件1 天¥3,000最优先
供应商加急空运¥30 / 件5 天¥30,000比调拨贵 10 倍
放弃销售毛利损失 ¥80 / 件—¥80,000比调拨贵 27 倍

调拨的决策顺序：

1. 查全网可用库存（含相邻大区）——不是只看相邻两仓
2. 评估调出仓的代价：调走后它自己的缺口由谁补？
3. 比对物流时效与成本（调拨也可能来不及）
4. 都不行才加急；加急仍不划算才接受缺货

调拨的隐性成本必须算进去：调走 A 仓的 1,000 件，A 仓自己的缺口只能靠下一轮补货填上。所以调拨的真实成本 = 物流成本（¥3,000）+ 下一轮补货量的增加。很多系统只比了物流成本，就以为调拨「免费」——它其实是把缺口从这一轮挪到了下一轮。

但即便如此，它通常仍然划算：因为下一轮的补货是计划内的（可以被提前安排、可以和其它 SKU 合并下单、可以用海运），而这一轮的缺货是计划外的（只能加急、只能放弃）。「计划外的贵 vs 计划内的便宜」是本章的核心成本直觉。

11.6 演进、指标与误区

第六段 · 演进、指标与误区这一段回答：这套系统怎么一步步长大，成熟后看哪几个数，以及哪些坑最贵。

11.6.1 演进路线与指标体系

本章要点

演进六级：L0 人工加 Excel、L1 MRP 固定参数补货、L2 统计预测加分层服务水平、L3 约束求解加产能可见、L4 信号保真（牛鞭治理）、L5 供应网络联合决策。L4 是最容易被跳过也最不该跳过的一层，很多系统从 L1 直接跳到 L3，但只要信息还在逐级失真，求解器越精确放大的误差就越大，它会把「算得更准」变成「把错的算得更精确」。指标体系八层：预测、信号、库存、服务、产能、决策、对账、成本，其中信号层的牛鞭系数与缺货期下单比专门用来判断架构是否失真。

思考笔记

L4 的关键是数据链路而不是模型，这解释了为什么它最容易被跳过：模型升级有明确的技术指标和收益故事，而接通终端数据是一件脏活。但跳过它的后果是 L3 的精确求解器会把被扭曲的信号算得更精确。所以演进顺序不是「从简单到高级」，而是「从没有失真到不失真，再到不失真地优化」。

11.6.2 评测回归与成本优化

本章要点

回放三纪律是最容易作弊的地方：回放完整策略（含安全库存、提前期、MOQ 约束）否则会系统性高估收益，包含促销期与缺货期样本否则模型在最重要的样本上从未被评测，使用当时的库存状态否则缺货本身被消除。变更与回归对应四类：预测模型与特征变更要回归区间覆盖率、偏置与牛鞭系数，安全库存口径变更要回归全量 SKU 的补货量与库存金额，约束规则变更要回归可行性与计划稳定性，主数据变更要回归对账与异常率。成本优化按杠杆排序：把预测做准（降 σ）让安全库存减半、总成本降 39%，缩短提前期（降 L）让安全库存降 29%，缺口处置先调拨后加急降 27 倍，分层服务水平把资金从长尾挪到高价值品类。

思考笔记

「建议修改率是变更回归里最灵敏的指标」这句值得记：模型换了一版，如果计划员的修改率从 5% 涨到 20%，说明新模型与人的判断分歧变大了，即使所有离线指标都变好了。因为离线指标衡量的是「预测准不准」，修改率衡量的是「这个建议能不能被执行」。成本那一段给出一个很克制的结论：前两条杠杆都作用在同一个公式上，其余手段天花板很低，所以别把资源投在更复杂的求解器上。

评测与回归

回放三纪律（本章最容易作弊的地方）：

纪律不遵守的后果
回放完整策略（含安全库存、提前期、MOQ 约束）系统性高估收益——只回放预测精度，会算出「预测准了就能省钱」的假结论
包含促销期与缺货期样本模型在最重要的样本上从未被评测
使用当时的库存状态用今天的库存回放历史，缺货本身被消除，结论失真

变更与回归：

变更类型必须回归什么
预测模型 / 特征变更区间覆盖率、偏置、牛鞭系数
安全库存口径变更全量 SKU 的补货量、库存金额、缺货率回放
约束规则变更求解可行性、产能占用、计划稳定性
主数据 / 映射变更对账、异常率

建议修改率是变更回归里最灵敏的指标：模型换了一版，如果计划员的修改率从 5% 涨到 20%，说明新模型与人的判断分歧变大了——即使所有离线指标都变好了。因为离线指标衡量的只是「预测准不准」，而修改率衡量的是「这个建议能不能被执行」。

成本优化

按杠杆排序（不是按实现难度）：

顺序手段收益量级说明
1把预测做准（降 σ）安全库存减半 → 库存总成本降 39%本章最大杠杆
2缩短提前期（降 L）安全库存 ∝ √L，L 降一半 → 降 29%收益更大但周期更长，不靠软件
3缺口处置先调拨后加急单次缺口成本降 27 倍运营与仓网布局
4分层服务水平资金从长尾挪到高价值品类与「全线提高」相反
5滞销与补货同账核算释放资金反哺补货案例：华东仓断货风险与滞销压降
6求解器分层（精确 / 启发式 / 规则）算力成本降质量略降

第 1、2 两条都作用在同一个公式上：SS ∝ σ × √L。这两个变量是本章的全部杠杆——预测精度是软件能做的，提前期是供应链本身能做的。其余手段（模型更复杂、求解更精确）都不在这两个变量上，天花板很低。

本章要点

思考笔记

高频追问的最后一条可以当成本章的验收标准：「Agent 在这里最大的价值是什么」——答案不是预测更准，是让信号不失真：WAPE 只降 3 个点，牛鞭系数却降 46%。这句话把整章的技术细节收回到一个可复述的判断上。一页纸作战手册则相反，它是唯一可以背下来的部分：每一步都有自检问题和合格线，适合照着填。

高频追问

  • 为什么用上游订单做预测特征是错的？ → 那是逐级预测，误差逐级叠加，放大 16 倍；预测越准，放大越狠。要用终端 POS。
  • 牛鞭效应的四个机制是什么？ → 预测逐级叠加、订单批量、价格促销、缺货配给；只有第一个是 Agent 直接放大的。
  • 怎么定安全库存？ → SS = z × σ_daily × √L；z 按 ABC 分层，σ 按生命周期分档，L 取分布的 P90 而非均值。
  • 为什么模型不能直接输出补货量？ → MOQ、箱规、仓容、供应商产能、承运商运力都是硬约束；模型只能给建议，约束求解层给结果。
  • 什么是产能挤占？ → 一个 SKU 的超量订单吃掉供应商共享产能，影响其它 20 个 SKU；必须把产能视图放进求解器，按产能全局分配。
  • 缺货了先做什么？ → 先查全网库存做调拨（¥3/件），再考虑加急（¥30/件），最后才放弃（毛利 ¥80/件）。
  • 下单接口超时怎么办？ → 不重试、不落单，转人工核销；重试就是重复下单。
  • 账实不符还能补货吗？ → 不能；冻结该 SKU 自动补货并转人工，先修账再谈补货。
  • 怎么评估补货 Agent？ → 完整策略回放（含安全库存、提前期、约束），不是只回放预测精度；主指标是区间覆盖率、偏置与牛鞭系数。
  • 为什么新品要用分位数铺货？ → 没有历史数据，点估计最不可靠；P50 首批 + P90 追单 + 强制复盘点，把不确定性交给后续决策。
  • 扩容先坏哪里？ → 不是 QPS，是「一个补货窗口内算不计算得完」；要让计划滚动起来。
  • Agent 在这里最大的价值是什么？ → 不是预测更准，是让信号不失真：WAPE 只降 3 个点，牛鞭系数却降 46%。

11.7.1 一句话总结

思考笔记

供应链 Agent 的价值不在预测得更准，而在让信号不失真：把每一级的输入换成终端真相、把每一次不确定性变成显式的分位数与缓冲、把每一个不可撤销的承诺压到约束求解之后——剩下的才算模型能优化的空间。

11.7.2 本章结论

  1. 错单撤不回，所以护栏必须压在承诺之前。决策周期 45 天、货已上路、钱已付、合同已签，本章十个 P0 里有七个是下单之前的检查。这与其它章同源，但位置更极端。
  2. 先算放大倍数，再谈模型。牛鞭 16 倍、产能挤占 1 个错变 20 个错、缺口处置 1 : 10 : 27，这三个数比任何模型指标都更早决定架构成败。
  3. 预测要区间，不要点估计；安全库存要动态，不要常数。SS = z × σ × √L，z 按 ABC 分层、σ 按生命周期分档、L 取分布的 P90。预测误差减半对应库存总成本降 39%，而点估计误差会互相抵消，区间偏差不会。
  4. 模型给建议，约束做决定。MOQ、箱规、仓容、产能、运力都是硬约束，逐 SKU 独立求解是产能挤占的系统性来源。求解器必须读产能视图并按产能全局分配，且三层降级里规则层永远可跑。
  5. 先把账对上，再谈补货。账实、在途、订单三条对账线，订单差异必须为 0。在账实不符被修复之前，任何补货决策都是在给一个假缺口补货。

11.7.3 下一章

这一篇是「AI Agent 系统设计」专题的收尾。全系列十一篇到此走完：从问数与问答的「把自然语言翻译成可信结论」，到客服、营销、电商与文旅的「在有副作用的链路上做受控编排」，再到运维、安全运营、合同审查与办公写作的「在合规与流程约束下推进」，最后落到供应链的「决策周期长、物理约束硬、多方协同」。回看这条路，十一篇的答案可以归结为同一句话：模型负责更优，规则负责不出事；副作用越大，护栏越要压在动作之前。往后的延伸不再是新的一章，而是把这套结构用到你自己的业务上——先算放大倍数，再列不可逆清单，最后才轮到选模型。
