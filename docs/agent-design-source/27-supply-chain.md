## 第二十七章 供应链 AI Agent 系统

> **本章导读**：供应链 AI Agent 把「自然语言经营目标」转化为可预测、可补货、可履约、可处置异常的供给闭环，难点不在模型算得多准，而在「决策周期长、物理约束硬、多方协同」——一次错单会沿供应链放大，货已经在路上。本章围绕需求预测分层、牛鞭效应与信息失真、安全库存与补货约束、多级履约与异常归因展开，整体按「定义 → 矛盾 → 方法论 → 工程护栏 → 端到端案例 → 演进与误区」组织。

### 27.1 核心定义与定位

**定义**：供应链 AI Agent 是面向商品供给与履约链路的智能体系统。它接收自然语言的经营目标（如「华东仓未来 4 周要保证不断货，同时把滞销库存压降 20%，预算 200 万」），完成需求预测、缺口推演、补货与调拨建议生成、供应商评估与询价、多级履约调度、异常处置与根因归因。

它与前面几章的 Agent 有三个根本差别，这三个差别决定了本章的架构：

| 差别 | 具体含义 | 对设计的影响 |
|---|---|---|
| **决策周期长** | 一次补货决策的后果在 **45 天后**才兑现 | 错误不能靠「马上改」补救，必须在**决策前**拦住 |
| **物理约束硬** | 仓容、MOQ、箱规、供应商产能、承运商运力都是硬边界 | 模型输出是**建议**，不是指令；约束求解层不可省 |
| **多方协同** | 供应商、仓库、承运商、门店各有自己的目标与承诺 | Agent 的动作会外溢到别人身上，**必须显式建模承诺与违约** |

> **这三个差别合起来意味着**：供应链 Agent **不能像营销 Agent 那样「先做再熔断」**。营销的错消息能撤回一部分，供应链的错单不行——货已经在路上，钱已经付了，合同已经签了。**所以本章的护栏重心全部压在下单之前。**

**三个能力层次**：

| 层次 | 回答的问题 | 典型输出 | 决策周期 | 难度 |
|---|---|---|---|---|
| **L1 执行** | 补多少、发给谁 | 补货单、调拨单、发货单 | 日 / 周 | 中 |
| **L2 优化** | 怎么摆、怎么调 | 多级库存配置、调拨路径、订单分配 | 周 / 月 | 较高 |
| **L3 决策** | 换供应商还是换渠道、要不要砍 SKU | 寻源建议、组合优化、供应网络方案 | 季 / 年 | 高 |

**典型用户与场景**：

| 用户 | 场景 | 关注点 | 主要风险 |
|---|---|---|---|
| 计划员 | 周度补货、缺货处理 | 建议可解释、约束可满足 | 模型建议无法执行 |
| 采购 | 寻源、议价、MOQ 谈判 | 价格、账期、产能 | 承诺超产能 |
| 仓储 | 仓容、库位、批次分配 | 库容周转、效期 | 积压与断货并存 |
| 物流 | 承运商分配、路径与时效 | 运力、成本、时效 | 承诺时效兑现不了 |
| 管理层 | 缺货风险、库存资金、周转 | 风险敞口、周转天数 | 只看金额不看风险 |

**与相近系统的区别**：

| 系统 | 核心 | 与供应链 Agent 的差异 |
|---|---|---|
| ERP | 记录与执行 | 有账无脑：记录发生了什么，不判断该发生什么 |
| WMS | 仓库作业 | 管库位与批次，不管「该进多少货」 |
| TMS | 运输调度 | 管在途，不管「要不要发这一单」 |
| 传统需求计划（MRP / S&OP） | 参数化补货 | 规则固定、层级逐级、不看异常 |
| 电商 Agent | 面向消费者 | 供应链 Agent 面向**商品与承诺**，一个决策周期以周计 |

**系统边界**：

| 范围内 | 范围外 |
|---|---|
| 需求预测与预测分层 | 商品主数据生产 |
| 库存水位与缺口推演 | 采购合同法律条款 |
| 补货 / 调拨建议生成 | 仓库作业与库位管理 |
| 供应商评估与寻源建议 | 实际下单与合同签署 |
| 履约异常检测与处置建议 | 承运商实际运输 |
| 库存资金与周转分析 | 财务结算 |

**核心指标**：

| 类别 | 指标 |
|---|---|
| 服务 | 缺货率、OTIF（按时足量交付率）、订单满足率、缺货时长 |
| 库存 | 库存周转天数、周转次数、滞销占比、呆滞金额、**安全库存占用** |
| 成本 | 持有成本、缺货成本、加急成本、**单位物流成本** |
| 预测 | WAPE、MAPE、**分位数覆盖率（预测区间命中率）**、偏置（bias） |
| 履约 | 供应商准时交付率、违约次数、承诺兑现率、**产能挤占率** |
| 系统 | 计划生成耗时、重规划次数、建议采纳率、**重复下单数** |

> **两个指标是本章特有的**：**分位数覆盖率**衡量预测区间准不准（供应链决策靠的是区间而不是点估计），**产能挤占率**衡量一个 SKU 的决策吃掉了多少供应商资源（§27.3.10）——**后者是本章最容易被忽略、后果最严重的指标**。

**SLO 示例**：

| 指标 | 目标 |
|---|---|
| 库存与可用量查询 P95 | < 200ms |
| 异常事件检测延迟 | < 5 min |
| 补货计划生成（T+1 批次） | **在下一个补货窗口前完成（8h 内）** |
| 库存准确率 | ≥ 99% |
| 缺货率 | ≤ 1% |
| OTIF | ≥ 98% |
| **重复下单** | **0**（硬约束） |
| **对账差异率** | **≤ 0.01%**（硬约束） |
| **约束违反的建议** | **0**（硬约束） |

> **本章的 SLO 与营销、问数两章形态完全不同**：实时性要求低得多（计划以天为周期），但**准确性、一致性与「不可撤销」三项的硬约束更多**。**这是本章的定位使然——供应链系统的错误不会自己暴露出来，它会安静地在 45 天后变成一批卖不掉的库存。**

**本章专属不可逆决策清单**（做错了要停机迁移 + 数据回填 + 全量对账，不是发个版本就能改）：

| 决策 | 为什么不可逆 | 改动代价 |
|---|---|---|
| **库存成本核算口径与成本元素分层**（移动加权 / 批次 / 在途 / 残次 / 冻结） | 库存金额、毛利、周转、安全库存全部建立在这个口径上 | 历史库存金额全部作废 + 毛利报表口径断层 + 补货模型输入需全量重算 |
| **安全库存公式与服务水平分层口径**（z 值来源、lead time 分布怎么取、需求波动怎么估） | 决定每一次补多少 | 历史建议无法复现 + 在途订单与新建议口径冲突 + 需全量重排 |
| **需求预测的粒度与层级**（SKU × 仓 × 日 的预测表结构与模型版本） | 预测是补货的唯一输入，粒度一变全链路重做 | 全量预测重算 + 特征与缓存全部失效 + 下游决策不可比 |
| **库存的唯一事实源与所有权划分**（WMS 实物 / ERP 账面 / 在途 / 平台库存） | 决定「可售量」怎么算；算错就直接缺货或超卖 | 全量对账 + 渠道可售量口径需重新同步 + 已下单据需人工核销 |
| **供应链主数据的主键与标识体系**（SKU / SPU / 仓 / 供应商 / 批次编码规则） | 所有关联、追溯、对账都靠它 | 全量数据需重新映射 + 历史关联断裂 + 对账无法自动进行 |
| **对上游的订单承诺契约**（承诺量、承诺期、承诺窗口、变更与违约条款的 schema） | 一旦下单就是不可撤销的现金支出与履约义务 | 在途订单无法自动对账 + 违约判定失效 + 需人工核销全部在途 |
| **重规划的触发条件与覆盖范围**（哪些事件触发重算、重算覆盖单仓还是全网） | 决定异常时的反应速度与「计划稳定性」 | 计划频繁重排 → 执行侧无所适从；覆盖范围改动 → 全网重排一次 |

> **对照第一章 §1.4.4**：这七项属单向门，决策时要多评审、做原型、留迁移方案。其余（预测模型选择、求解器选型、服务水平 z 值数值、批量大小、提前期）是双向门，可以快速试错——但 **z 值与服务水平分层的口径属于「可逆但很贵」**：它们改变每一笔补货量，必须伴随离线回测。

### 27.2 核心解读与关键矛盾

**本质**：供应链 Agent 的核心矛盾，是「让每一级都做出最优决策」与「让信息在逐级传递中不失真」之间的冲突。**每一级拿到的都不是真实需求，而是上一级被加工过的订单。** 模型越准，放大的误差越大——因为它更忠实地执行了一个被扭曲的信号。

**六条章级原则**（贯穿全章，冲突时以这六条为准）：

1. **物理约束优先于模型偏好**——模型说补 5,000 件，但仓容只允许 3,000、MOQ 是 1,000、提前期 45 天、供应商月产能 8,000。**约束求解层永远在模型之上**，模型的输出是**建议**，不是指令。
2. **预测越接近终端越好**——逐级预测必然放大。**能直接看终端 POS 数据，就不要看上一级的订单。**
3. **决策周期与数据窗口必须匹配**——日级补货决策不能只用 5 分钟的抖动数据，也不能只用 3 年前的历史。**窗口不对，再准的模型也没用。**
4. **不确定性必须变成显式缓冲，而不是被平均掉**——补货决策要的是**分位数**（P50 / P90 / P95），不是点估计。**点估计 + 固定安全库存 = 把风险藏在了一个拍出来的常数里。**
5. **不可撤销的承诺要分级审批**——下单给供应商 = 现金支出 + 履约义务 + 产能挤占。**金额小、量大、品类敏感**三种风险要分别设阈值。
6. **每次重规划都要能解释「为什么变了」**——补货建议从 5,000 变成 3,000，必须能归因到「销量预测下调」「仓容收紧」「供应商延期」。**不能解释的重规划，执行侧就不敢执行，计划也就废了。**

**三个不等式**：

```
终端需求的小波动  <<  上游订单的大波动    → 牛鞭效应：逐级放大 16 倍
补货决策的周期    >>  纠错能到达的时间    → 货在 45 天后，错误无法撤回
模型能给的最优    >>  物理世界允许的最优  → 约束求解层不可省
```

**三个放大器**（本章最贵的量都藏在这里）：

| 放大器 | 说明 | 后果 | 量化 |
|---|---|---|---|
| **牛鞭放大（信息失真）** | 需求信号沿供应链逐级被加工放大 | 产能、库存、运力全被推到错误的位置 | 终端 ±10% → 原料订单 ±160%，**放大 16 倍**（§27.3.8） |
| **库存资金放大（决策长周期）** | 提前期越长、需求波动越大，安全库存越贵 | 资金占用与缺货风险同时被放大 | 预测误差减半 → 安全库存 736→368 件 → 库存总成本 **降 39%**（§27.3.9） |
| **产能挤占放大** | 一个 SKU 的超量订单吃掉供应商共享产能 | 1 个 SKU 的错误 → 20 个 SKU 延期 | 单次超量到月产能的 125% → 挤占 25% 产能 → 20 个 SKU 延期 3 天（§27.3.10） |

> **本章与前面各章的放大器方向不同**：Feed 是读放大，秒杀是写放大，客服是上下文放大，问数是结果集放大，营销是触达放大。**供应链章的放大器是牛鞭放大**——它是唯一一个「信号本身会变形」的架构：**别的系统错了，是这一级算错；供应链错了，是这一级把上一级的错当成了真相。**

**四类正确性**（必须分开保证）：

| 层次 | 要求 | 保障手段 | 典型漏法 |
|---|---|---|---|
| **预测正确** | 需求分布而非点估计 | 分位数预测 + 区间校准 | MAPE 好看但系统性高估 |
| **可执行正确** | 建议满足全部物理约束 | 约束求解 + 可行性校验 | 模型输出直接变成订单 |
| **账实正确** | 库存数量与金额对得上 | 幂等事件 + 全量对账 | 并发扣减导致超卖 |
| **承诺正确** | 对上游与下游的承诺可兑现 | 承诺契约 + 违约监控 | 承诺了做不到的时间窗 |

**八组关键矛盾**：

| 矛盾 | 典型表现 | 默认策略 | 何时反转 |
|---|---|---|---|
| 服务水平 vs 库存资金 | 备货足则不缺货但压资金 | 按 ABC 分层设服务水平 | 战略品 / 缺货损失高的品类可提高 |
| 集中 vs 分散 | 集中采购有量价优势，集中库存响应慢 | 按 ABC 分层选址 | 快消 / 爆品可分散 |
| 安全 vs 灵活 | 备安全库存但会积压 | 动态安全库存 + 分位数 | 短保质期品类必须收紧 |
| 稳定 vs 响应 | 计划稳定但反应慢 | 稳定计划 + 事件触发重规划 | 大促、断货等异常事件 |
| 自营 vs 外包 | 自营可控但重，外包轻但不可控 | 核心自营 + 边缘外包 | 长尾区域可全外包 |
| 成本 vs 时效 | 海运便宜但慢 | 分层分仓 + 加急兜底 | 高价值商品可空运 |
| 预测 vs 响应 | 预测准但对突发无反应 | 预测 + 事件规则双轨 | 促销、断货等场景靠规则 |
| 全局最优 vs 局部最优 | 单仓最优加起来不是全局最优 | 全网联合求解 | 数据与算力足够时用全局 |

**八类失败模式**：

| 失败 | 表现 | 根因 | 防线 |
|---|---|---|---|
| **牛鞭** | 上游订单波动是终端的数倍 | 逐级预测 + 缺货误读 | 共享终端数据 + 缺货感知 |
| **超量** | 一次下太多，货到后滞销 | 促销前置 + 配给误读 | 促销日历入模 + 缺货率入模 |
| **欠量** | 断货，损失毛利与客户 | 预测偏低 + 安全库存不足 | 分位数预测 + 分层服务水平 |
| **积压** | 库龄超期，减值 | 安全库存固定 + 未按生命周期 | 动态安全库存 + 生命周期特征 |
| **不可执行** | 建议违反 MOQ / 仓容 | 无约束求解层 | 约束求解 + 可行性校验 |
| **账实不符** | 系统有货、实物没有 | 并发扣减 / 未对账 | 幂等事件 + 全量对账 |
| **产能挤占** | 一个爆款吃掉全月产能 | 无产能视图 | 产能分配 + 违约监控 |
| **重复下单** | 同一批货订两次 | 重试无幂等 | 下单幂等键 + 计划版本 |

**信任分级**（补货建议的「输出契约」）：

| 级别 | 条件 | 展示方式 |
|---|---|---|
| 高 | 需求预测已校准 + 约束全满足 + 库存账实一致 + 无产能挤占 | 直接给可执行建议 + 依据 |
| 中 | 预测区间较宽 / 存在库存差异 / 有待确认促销 | 给建议 + 区间 + 风险提示 |
| 低 | 预测未校准 / 数据陈旧 / 账实不符 | 只给数据与风险，**不给补货量** |
| 拒绝 | 约束不可满足 / 产能已满 / 预算超限 | 明确说清哪条约束挡住了 |

> **「不给补货量」也是一种输出**。当库存账实不符时，系统给一个精确的补货数字，等于给了一个精确的错误答案——**执行侧会照单执行，45 天后变成一批错货。**

**成本结构**：

| 成本项 | 占比量级 | 优化手段 |
|---|---|---|
| **库存持有成本** | **最大（常占收入 15–30%）** | 预测精度、安全库存优化、ABC 分层 |
| 缺货成本 | 次之但波动极大 | 服务水平分层、跨仓调拨优先 |
| 采购成本 | 大（尤其量价与账期） | 订单合并、量价优化、寻源 |
| 加急物流成本 | 中 | 调拨替代加急（便宜 10 倍） |
| 模型 / 计算成本 | 小 | 分层预测、离线批处理 |

### 27.3 理论与方法论

#### 27.3.1 S0：七项前置锚点

先落定七件事，它们共同决定**可行域**——不在可行域内的方案不参与讨论。

| # | 锚点 | 本章答案 | 影响 |
|---|---|---|---|
| 1 | **业务目标与成功标准** | 缺货率 ≤ 1%、OTIF ≥ 98%、库存周转 ≥ 6 次 / 年、重复下单 0、约束违反建议 0 | 决定服务水平分层与自动化分级 |
| 2 | **规模量级** | SKU 50 万、仓 200、供应商 300、日销 200 万件、**日补货计划 200 个、补货周期 7 天**、提前期 5–45 天 | 决定求解规模、数据量与计划窗口 |
| 3 | **质量属性优先级** | 不错货 > 不断货 > 不积压 > 不违约 > 库存成本 > 响应速度 | 决定降级顺序与约束优先级 |
| 4 | **硬约束** | 仓容、MOQ、箱规、供应商产能与最小起订量、承运商运力、合同价与账期、效期 | **定义可行域；物理约束不可用算法折抵** |
| 5 | **不可逆决策清单** | 见 §27.1 的本章七项 | 决策流程：多评审 + 原型 + 迁移方案 |
| 6 | **核心路径与事实源** | 核心路径 = 目标 → 预测 → 缺口推演 → 补货 / 调拨 → 下单 → 收货 → 上架 → 销售 → 反馈；事实源 = **库存流水 + 订单 + 主数据 + 供应商履约记录** | 决定缓存与对账对象；预测表与建议表全是投影 |
| 7 | **竞争与协作边界** | ERP / WMS / TMS、供应商门户、承运商 API 在外部；预测、缺口推演、约束求解、异常处置自建 | 决定服务边界与团队成本 |

> **第 2 项为什么改变答案**：本章的规模参数不只是 QPS，还有**「补货周期」与「提前期」**。同样是 SKU 50 万、日销 200 万件，提前期 45 天还是 5 天，安全库存差 3 倍（√45 / √5 ≈ 3）。**不给提前期分布，就没法算安全库存，整个补货模型就无从谈起。**

```
S0 定题（锚点 + 不可逆清单）
   → Scenario 定 SKU 数、仓数、提前期、补货周期、服务水平分层、约束清单
      → Service 定预测、缺口推演、求解、下单、履约、异常处置的边界

```

#### 27.3.5 Storage：数据模型

| 数据 | 存储 | 关键设计 | 是事实源吗 |
|---|---|---|---|
| **库存流水** | 数仓 / 事件库 | 每次出入库一条不可变记录 | **是** |
| **订单与履约记录** | 数仓 | 下单、承诺、收货、取消 | **是** |
| **主数据** | 主数据服务 | SKU / SPU / 仓 / 供应商 / 批次 | **是** |
| **供应商履约记录** | 数仓 | 准时率、违约、短交 | **是** |
| 预测表 | 数仓 | SKU × 仓 × 日 × 分位数 × 模型版本 | 否（可重建） |
| 建议表 | DB | 建议量、约束余量、采纳与否 | 否（可重建） |
| 可用量缓存 | Redis | 短 TTL | 否（**必须可重建**） |
| 求解任务 | 队列 | 批任务 + 版本 | 否 |
| 审计 | 不可篡改存储 | 谁、何时、基于什么预测、给了什么建议 | **是** |

> **库存流水的不可变性是本章的地基**。库存是一个**派生量**：它由一连串出入库事件累加得到。如果库存是「可以被直接改写的当前值」，那么并发扣减、超卖与账实不符都无法复现与追责。**本章的第一条存储原则：库存只能由事件累加得到，任何「直接改库存」的接口都必须被禁止。**

**库存的口径四件套**（每个数字必须说清是哪一种）：

| 口径 | 定义 | 用途 |
|---|---|---|
| 实物库存 | 仓库里实际有多少 | 对账基准 |
| 可用库存 | 实物 − 已分配 − 冻结 − 残次 | **能不能卖** |
| 在途库存 | 已下单未收货 | **补货决策必须扣减它** |
| 可售库存 | 可用 + 在途（按 ETA 计入） | 渠道售卖口径 |

| 维度 | 手段 | 触发条件 |
|---|---|---|
| 预测 | ABC 分层、A 类精细 / C 类类目均值 | 算力或时间不够 |
| 计划 | T+1 批 + 事件驱动增量重规划 | 计划窗口紧张 |
| 求解 | 分区求解、启发式 + 精确混合 | 求解超时 |

#### 27.3.7 需求预测与预测分层

**预测要输出分位数，不是点估计**：

| 输出 | 用途 | 为什么必须有 |
|---|---|---|
| P50 | 常规补货、基线 | 期望值参考 |
| P90 | A 类高服务水平 | 服务水平 99% 对应更高分位 |
| P95 / P99 | 极端场景、加急预案 | 缺货风险的上尾 |

**ABC 分层与预测投入**：

| 分层 | SKU 占比 | 销量占比 | 预测粒度 | 预测窗口 | 方法 |
|---|---|---|---|---|---|
| A | 20% | 80% | SKU × 仓 × 日 | 60 天 | 融合模型 + 促销特征 |
| B | 30% | 15% | SKU × 大区 × 日 | 30 天 | 层级模型 |
| C | 50% | 5% | 类目 × 日 | 14 天 | **类目均值 + 人工兜底** |

> **C 类不做个体预测不是偷懒，是正确的资源分配**：C 类占 50% 的 SKU 但只占 5% 的销量，为它做精细预测会吃掉一半算力，而预测准确率的边际收益接近零。**但 C 类必须给兜底值**——「用类目均值」必须是一个明确写进模型的规则，而不是「预测不出来就填 0」。填 0 会让 C 类全部断货。

**预测必须校准，不只是准**：

| 校准项 | 含义 | 不合格的后果 |
|---|---|---|
| **区间覆盖率** | 实际落进 P90 区间的比例应 ≈ 90% | 区间太宽 → 安全库存虚高；太窄 → 缺货 |
| **偏置（bias）** | 预测均值与实际均值的系统性差 | 系统性高估 → 全网积压；低估 → 全网缺货 |
| 分层误差 | A / B / C 各自的 WAPE | 用总体 WAPE 掩盖了 C 类的离谱误差 |

> **WAPE 好看但区间不校准，是最危险的组合**。点估计误差可以互相抵消，但安全库存是按分位数算的——**点估计准但区间偏了，安全库存就会系统性错**。所以本章的评测主指标是**区间覆盖率 + 偏置**，WAPE 只是辅助。

**特征清单里必须有的四项**（缺一项，牛鞭就会被引入）：

| 特征 | 为什么必须有 |
|---|---|
| **终端 POS / 销售流水** | 直接预测终端需求，而不是预测上游订单 |
| **促销日历** | 促销把未来需求前置，不入模就是超量 |
| **缺货 / 缺货率** | 区分「没下单」与「没货可买」 |
| **生命周期阶段** | 新品爬坡、成熟、衰退的基线完全不同 |

#### 27.3.8 牛鞭效应：信息失真的四类机制

**本节是牛鞭效应的权威版**，§27.3.7、§27.5.5、§27.5.7 只引用。

**现象**：终端需求的小幅波动，沿供应链逐级传递时被放大成越来越大的订单波动。

```
终端需求 ±10%
  → 零售商订单 ±20%    放大 2×
  → 批发商订单 ±40%    放大 4×
  → 制造商订单 ±80%    放大 8×
  → 原料订单 ±160%     放大 16×
```

| 环节 | 终端需求波动 | 该级订单波动 | 放大系数 |
|---|---|---|---|
| 终端（消费者） | ±10% | ±10% | **1.0** |
| 零售商 | ±10% | ±20% | **2.0** |
| 批发商 | ±10% | ±40% | **4.0** |
| 制造商 | ±10% | ±80% | **8.0** |
| 原材料供应商 | ±10% | ±160% | **16.0** |

**四类机制与各自的治本 / 治标手段**：

| 机制 | 根因 | 治本手段 | 治标手段（信息层） |
|---|---|---|---|
| **预测逐级叠加** | 每一级都在**上一级的订单**上做预测 | **共享终端 POS 数据，各级直接预测终端需求** | 特征里**只用终端需求，不用上游订单** |
| **订单批量（batching）** | 小订单成本高，攒批下单 | 量价优化、订单合并与拼单 | 需求信号按**周需求**而非日需求建模；把批次大小显式写入信号 |
| **价格促销** | 促销把未来需求前置 | 促销日历在链上共享 | **促销日历作为特征进入每一级预测** |
| **缺货与配给** | 缺货期客户下单量 **>** 实际需求 | 提高服务水平 | **把缺货率作为预测输入**，区分「没买」与「没货」 |

> **四个机制里，只有「预测逐级叠加」是 Agent 直接放大的。** 批量与促销是商务政策，Agent 改不了，只能在设计里补偿；配给是缺货的后果，Agent 若不能及时感知缺货，就会把「被压抑的需求」误读为「需求激增」，从而加倍下单——**这是最隐蔽的一个方向性错误**。
>
> **所以本章的第一条方法论是：Agent 越聪明，越要确认它的输入是不是终端真相。** 一个用了最先进模型、却只在上一级订单上预测的 Agent，**比一个用移动平均、但直接看终端销售的 Agent 更糟**——因为它会把扭曲的信号忠实地放大 16 倍。

**治牛鞭的四条落地动作**：

| # | 动作 | 作用 |
|---|---|---|
| 1 | 特征层**屏蔽上游订单量**，只保留终端销售 | 直接切断「预测逐级叠加」 |
| 2 | 促销日历进特征 | 消除「促销前置」造成的假峰 |
| 3 | 缺货率进特征，缺货期需求做**还原** | 消除「配给」的方向性错误 |
| 4 | 需求信号按**周**建模而非按日 | 削弱「订单批量」的影响 |

> **第 1 条是最关键也最反直觉的**：它意味着**放弃一部分信息**（上游订单是有用的信号）来换取信号保真。**在逐级预测的架构里，「看得更近」比「看得更多」重要。**

#### 27.3.9 库存策略：再订货点与安全库存

**本节是库存策略的权威版**，§27.3.10、§27.5.1 只引用。

**再订货点（ROP）模型**：

```
ROP = 提前期内的期望需求 + 安全库存
    = d̄ × L + SS
SS  = z × σ_daily × √L
```

| 符号 | 含义 | 本章基准值 |
|---|---|---|
| `d̄` | 日均需求 | 1,000 件 |
| `L` | 提前期（天） | 5 天 |
| `σ_daily` | 日需求标准差 | 200 件（CV = 20%） |
| `z` | 服务水平对应的标准正态分位 | A 类 99% → 2.33；B 类 97% → 1.88；C 类 95% → 1.645 |
| `h` | 单位年持有成本 | ¥15 / 件 / 年 |
| `K` | 单次订货成本 | ¥2,000 |

**经济订货量（EOQ）**：

```
Q* = √(2 × D × K / h)
   = √(2 × 365,000 × 2,000 / 15)
   ≈ 9,865 件
年订货次数 = D / Q* = 365,000 / 9,865 ≈ 37 次
```

**把三个数代进去，看清安全库存值多少钱**：

| 项 | 计算 | 结果 |
|---|---|---|
| 安全库存 SS | 1.645 × 200 × √5 | **736 件** |
| ROP | 1,000 × 5 + 736 | 5,736 件 |
| 提前期需求的标准差 | 200 × √5 | 447 件 |
| 单周期期望缺货量 | 447 × L(z)，L(−1.645) = 0.1854 | 82.9 件 |
| 年缺货量 | 82.9 × 37 | ≈ **3,070 件** |
| 平均库存 | Q*/2 + SS = 4,933 + 736 | 5,669 件 |
| **年持有成本** | 5,669 × ¥15 | **≈ ¥8.5 万** |
| **年缺货成本** | 3,070 × ¥80 | **≈ ¥24.6 万** |
| **年库存总成本** | — | **≈ ¥33.1 万** |

> **注意缺货成本是持有成本的 2.9 倍**。这解释了为什么供应链系统里「服务水平」不是一个可以随便设的数：**它直接决定年成本的几倍量级**。也解释了为什么**跨仓调拨**（§27.3.12）在本章如此重要——它把一次缺货从「¥24.6 万的年化缺货成本」里捞回来。

**Agent 的价值：把预测误差减半**（σ_daily 从 200 降到 100）：

| 项 | σ = 200 | σ = 100 | 变化 |
|---|---|---|---|
| 安全库存 SS | 736 件 | **368 件** | **−50%** |
| 年持有成本 | ¥8.5 万 | ¥8.0 万 | −¥0.6 万 |
| 年缺货量 | 3,070 件 | 1,534 件 | −50% |
| 年缺货成本 | ¥24.6 万 | ¥12.3 万 | −¥12.3 万 |
| **年库存总成本** | **¥33.1 万** | **¥20.2 万** | **−39%（省 ¥12.8 万）** |

> **这条是本章的核心结论**：Agent 的价值**不在「预测得更准」本身**——准是一个手段。它体现在**安全库存减半**，进而**同时省下持有成本与缺货成本**。安全库存减半之所以成立，是因为 `SS ∝ σ`，而 **σ 是与预测精度同向的量**。
>
> **但要注意反向的陷阱**：`SS ∝ √L`。如果为了「响应更快」把提前期从 45 天压到 20 天，安全库存会降到 √(20/45) = 67%，看起来省了 33%——**但提前期的波动也会变，而提前期波动的那一部分不受这个折扣保护**。**缩短提前期是最有效的降库存手段，但它需要动供应链本身，不是模型能替代的。**

**动态安全库存的三个输入**：

| 输入 | 静态取法 | 动态取法 | 影响 |
|---|---|---|---|
| 需求波动 σ | 用历史平均 CV | 按 SKU × 仓 × 生命周期分别估 | 大促期与常态期分开 |
| 提前期 L | 用均值 | 用分布的 P90 | 供应商不稳定时必须用高分位 |
| 服务水平 z | 全局一个值 | 按 ABC 分层 | 高价值品类更高 |

#### 27.3.10 补货决策与约束求解

**补货量不是「缺口」，是「约束下的最优」**：

```
名义缺口 = 目标库存（ROP + Q*/2） − 可售库存（可用 + 在途）
实际补货量 = 在约束下最接近名义缺口且可行的量
```

**约束清单（求解器必须全部满足）**：

| 约束 | 类型 | 违反后果 |
|---|---|---|
| 供应商 MOQ（最小起订量） | 硬 | 供应商拒单 |
| 箱规 / 包装规格 | 硬 | 无法发货 |
| 仓库容量与库位 | 硬 | 货到无处放 |
| 供应商月产能 | 硬（共享） | **挤占其他 SKU** |
| 承运商周运力 | 硬 | 排队或拒运 |
| 合同价与量价阶梯 | 硬 | 违反合同价 |
| 库存持有上限 / 效期 | 软（可带惩罚） | 积压与减值 |
| 预算上限 | 软 | 超支 |
| 服务水平偏差 | 软 | 缺货或积压 |

**产能挤占是本章最容易被忽略的约束**：

```
一次超量下单 10,000 件，供应商月产能 8,000 件
→ 该 SKU 占掉月产能的 125%
→ 挤占另外 25% 的产能
→ 供应商其它 20 个 SKU 平均延期 3 天
→ 缺货成本 = 20 SKU × 3 天 × 日销 × 毛利
```

> **一次错误决策的影响面从 1 个 SKU 变成了 20 个 SKU。** 而且这 20 个 SKU 的延期是**在几天后才暴露的**——当期所有看板都显示正常。**这就是「产能挤占放大」：它是唯一一个会把 1 个错误变成 N 个错误、且延迟暴露的机制。**
>
> **对策不是「更保守」，而是「看得见」**：供应商产能视图必须进入补货求解器，**求解时按产能做全局分配**，而不是每个 SKU 各自算完再汇总。**逐 SKU 独立求解，是产能挤占的系统性来源。**

**求解器的三层策略**：

| 层 | 方法 | 适用 | 特点 |
|---|---|---|---|
| 1 | 规则补货（ROP + EOQ） | 兜底、C 类 SKU | 毫秒级、永远可跑 |
| 2 | 启发式 + 局部调整 | B 类、大部分场景 | 快、可解释 |
| 3 | 精确求解（整数规划 / CP） | A 类、跨仓调拨、新品首发 | 慢，但全局最优 |

> **三层不是「先进替代落后」，而是「先进兜底落后」**。求解器超时、算力不够、数据缺失时，**必须能退回规则层继续出计划**——而不是整个计划失败。**「规则补货是永远可跑的最后一层」是本章的一个硬性架构约束。**

#### 27.3.11 供应商选择与寻源

**供应商评估的五个维度**：

| 维度 | 指标 | 为什么重要 |
|---|---|---|
| 履约 | 准时交付率、短交率、违约次数 | 决定提前期可信度 |
| 质量 | 批次合格率、退货率 | 决定实际可用率 |
| 产能 | 月产能、可用产能窗口 | **决定能不能挤占别人** |
| 商务 | 价格、量价阶梯、账期 | 决定现金流 |
| 集中度 | 该供应商占该品类采购额比 | **过高则单点风险** |

**寻源建议必须给出「替代方案」**：换供应商不是把量全给新供应商，而是**按可替代性分层**：完全可替代 → 转移 80%；部分可替代（认证、模具、包材限制） → 转移 20%；不可替代 → 只能加急或降级供应。

> **「不可替代」这一档的存在，是供应链与其它 Agent 的重要差别**：营销可以随便换一个渠道，供应链的很多物料**换个供应商要 3 个月认证**。**所以「替代方案」不是一个建议，它是一道必须提前回答的问题**——如果主供明天就断，备选是谁、能不能接、多久能接上。

#### 27.3.12 多级履约与调拨

**多级库存的三个决策**：

| 决策 | 问题 | 关键约束 |
|---|---|---|
| 库存配置 | 每层放多少 | 仓容、成本、服务水平 |
| 履约路由 | 从哪个仓发 | 库存可用性、时效、成本 |
| 调拨 | 何时从 A 仓调 B 仓 | 调拨成本 vs 缺货成本 |

**缺货三级处置决策树**（本章最实用的一张图）：

```
缺货发生
  → 第一步：跨仓调拨（¥3/件，1 天到）
  → 第二步：供应商加急空运（¥30/件，5 天到）
  → 第三步：放弃销售（毛利损失 ¥80/件 + 客户流失）
  → 成本比 调拨 : 加急 : 放弃 = 1 : 10 : 27
```

**调拨不是万能的**：它受**调拨仓自身库存**约束（把 A 仓调给 B，B 的销量要靠 C 补上，C 又可能没有——**调拨只是把缺口往后挪，不一定消除它**），而且受**调拨本身的物流成本与时效**约束。**所以调拨决策必须看全网库存，不能只看两个仓。**

> **「先找库存，而不是先找货」是本章的核心操作原则。** 一次 1,000 件的缺口：调拨花 ¥3,000、加急花 ¥30,000、放弃损失 ¥80,000。**调拨比加急便宜 10 倍，比放弃便宜 27 倍。** 大多数系统的默认动作是「催供应商加急」，那是在花 10 倍的钱买 4 天的速度。

#### 27.3.13 异常处置与根因归因

**四类异常与各自的处置方向**：

| 异常 | 检测信号 | 根因方向 | 处置 |
|---|---|---|---|
| 缺货 | 可用库存 < 安全库存 | 预测偏低 / 提前期变长 / 需求突增 | 调拨 → 加急 → 补货计划修正 |
| **延迟** | 供应商未按承诺期到货 | 供应商产能 / 物流 / 清关 | 改承诺期、切备供、通知下游 |
| **超量 / 积压** | 库龄超阈值、库存周转掉档 | 预测偏高 / 促销取消 / 提前期变短 | 停单、去化、跨渠道清货 |
| **质量异常** | 退货率 / 批次不合格率上升 | 批次问题 / 供应商工艺 | 拦截批次、索赔、换供 |

**归因要区分「共同原因」与「责任原因」**：

| 归因方向 | 例子 | 处置 |
|---|---|---|
| 需求侧 | 需求突增、促销拉动 | 补货 |
| 供给侧 | 供应商减产、产能挤占 | 切备供、加急 |
| 物流侧 | 运力紧张、港口拥堵 | 改路由、改承诺期 |
| **数据侧** | **库存账实不符、订单重复** | **先修账，再谈补货** |

> **最后一档是本章特有的高频陷阱**：很多「缺货」其实是账实不符。**在账实不符被修复之前，任何补货决策都是在给一个假缺口补货。** 所以异常处置的第一步永远是**先校验账实，再判断根因**。

**承诺兑现率**是本章特有的过程指标：

```
承诺兑现率 = 按承诺期到货的订单量 / 承诺订单量
```

它同时衡量供应商履约、内部承诺管理与异常响应的质量。**低于阈值时，下游的可售量承诺就不该继续往下游传**——否则缺货会从供应商一路传导到渠道，形成断货的连锁反应。

#### 27.3.14 库存与调拨的对账

**三条对账线**：

| 对账线 | 比什么 | 频率 | 差异容忍 |
|---|---|---|---|
| 账实对账 | 系统库存 vs 实物盘点 | 日 / 周 | ≤ 0.1% |
| **在途对账** | **已下单未收货 vs 供应商在途** | **日** | **≤ 0.01%** |
| 订单对账 | 下单量 vs 供应商确认量 | 日 | 0（必须一致） |

> **在途对账是本章最容易漏掉的一条**。系统里显示「已下单 10,000 件」，如果供应商只确认了 8,000 件，那么**这 2,000 件的缺口从这一刻起就存在，但没有任何看板会显示它**——直到货期到了才发现到不了。**在途库存是补货决策的输入，它错了，缺口推演就全错。**

**对账差异的处理**：差异 > 阈值 → **冻结该 SKU 的自动补货**，转人工核对。**在对账修复前自动补货，只会把一个账面问题变成一批真实的错货。**

#### 27.3.15 评测方法

**离线评测**：

| 指标 | 定义 | 局限 |
|---|---|---|
| WAPE | Σ\|实际−预测\| / Σ实际 | 分母大的 SKU 主导 |
| **区间覆盖率** | 实际落入预测区间的比例 | **只说覆盖不说宽度，需与「区间宽度」一起看** |
| **偏置（bias）** | 预测均值 − 实际均值 | **系统性高估最致命，必须单列** |
| 缺货率回放 | 用历史实际需求回放补货策略 | 需要重放完整策略 |
| **牛鞭系数** | 上游订单波动 / 终端需求波动 | **本层可测，是本章的核心健康指标** |

> **牛鞭系数是可以逐层测的**：把本级订单序列与终端销售序列做相关与波动比。**这个比值应该被当作供应链系统的「体温」**——它比 WAPE 更早、更直接地反映信号失真。

**在线评测**：缺货率、OTIF、库存周转天数、建议采纳率、建议修改率、约束违反数、重复下单数、对账差异率、承诺兑现率。

**离线回测的三条纪律**：

| 纪律 | 为什么 |
|---|---|
| **必须回放完整策略**（含安全库存与提前期） | 只回放预测精度会系统性高估收益 |
| **必须包含促销与缺货期样本** | 否则模型在最重要的样本上没被评测 |
| **必须用当时的库存状态** | 用今天的库存回放历史，会消除缺货本身 |

#### 27.3.16 容量与成本估算

**本节是容量口径的权威版**，§27.5 与 §27.6 只引用。

**假设**：SKU 50 万、仓 200、日销 200 万件 / 80 万单、日补货计划 200 个、每仓候选 SKU 2,000、补货窗口集中在 20:00–22:00（峰值系数 3）、仅 10% 的 SKU 需要 LLM 参与（异常项）、供应商 300 家。

**一、批量轨道（T+1 日批）**

| 指标 | 计算 | 结果 |
|---|---|---|
| 日补货计划数 | 200 仓 × 1 次 | **200** |
| **SKU 级决策点 / 天** | 200 × 2,000 | **40 万** |
| **峰值 SKU 决策 / 秒** | 40 万 ÷ 7,200s × 3 | **≈ 56** |
| 峰值计划并发 | 200 计划 ÷ 7,200s | ≈ 0.03（批任务，同时在跑 ≤ 20） |
| **峰值 LLM 调用** | 4 万次 ÷ 7,200s | **≈ 5.6 QPS** |
| 单计划求解耗时（精确求解） | 2,000 SKU × 整数规划 | 30–120s |

> **这一行是本章的容量特征：QPS 极低，但单次计算很重。** 供应链 Agent 的资源瓶颈是**单个批任务的算力与时间窗口**，不是并发。**因此容量规划的单位是「一个补货窗口内能算完多少个计划」，不是「每秒多少请求」。**

**二、在线轨道**

| 指标 | 计算 | 结果 |
|---|---|---|
| 平均库存查询 QPS | 200 万库存记录 × 20 次 / 天 ÷ 86400 | ≈ 463 |
| **峰值库存查询 QPS** | 463 × 3 | **≈ 1,400** |
| 峰值异常检测 QPS | 事件流驱动 | ≈ 200 |
| 峰值下单 QPS | 200 计划 × 500 SKU ÷ 7,200s | ≈ 14 |

**三、数据量**

| 数据 | 计算 | 结果 |
|---|---|---|
| 库存记录 | 50 万 SKU × 平均 4 仓 | 200 万条（≈ 400 MB） |
| 销售明细 | 200 万行 / 天 × 120B | ≈ 240 MB / 天 |
| 库存流水 | 1,000 万条 / 天 × 80B | ≈ 800 MB / 天 |
| 订单履约 | 80 万单 / 天 × 600B | ≈ 48 MB / 天 |
| **预测记录日增** | A 类 80 万 + B 类 60 万 + C 类 25 万 = 165 万 (SKU×仓) 组合 | ≈ **165 万行 / 天（≈ 165 MB / 天）** |
| 预测记录存量 | 80万×60 + 60万×30 + 25万×14 | ≈ **6,950 万条** |
| 合计日增 | 240 + 800 + 48 + 165 MB | ≈ **1.25 GB / 天** |
| 合计年增 | — | ≈ **0.46 TB / 年** |

**四、成本**

| 成本项 | 年成本量级 | 说明 |
|---|---|---|
| **库存持有成本** | **最大** | 与 §27.3.9 的口径一致（SKU 数 × 均值） |
| 缺货成本 | 次之、波动极大 | 毛利损失 + 加急 + 客户流失 |
| 模型 / 计算成本 | 小 | 峰值 5.6 QPS 的 LLM 调用，月成本通常在千元级 |

**五、结论**

1. **本章的容量单位不是 QPS，是「补货窗口内能算完多少个计划」**——峰值 56 SKU 决策 / 秒看起来很轻，但单个精确求解要 30–120s，**200 个计划不可能串行跑完**。必须并行 + 分层降级。
2. **预测数据年增约 60 GB（存量 6,950 万条），比流水小一个量级**——分层预测的价值正在于此：C 类不做个体预测，直接省掉了大头。
3. **在线轨道只有 1,400 QPS，是全书最轻的 Agent 链路之一**——**本章的工程量在离线批处理与数据质量，不在实时服务**。
4. **必须先量提前期分布与需求波动**——它们决定安全库存，进而决定年持有成本（§27.3.9）。
5. **成本大头在库存持有，不在模型**——**优化预测精度的收益要通过「减少安全库存」这条路径兑现**，而不是直接体现在账单上。

#### 27.3.17 成本模型

| 成本项 | 量级 | 优化手段 | 本章收益量级 |
|---|---|---|---|
| **库存持有成本** | **最大** | 分位数预测、分层服务水平、缩短提前期 | **安全库存减半 → 总库存成本降 39%** |
| 缺货成本 | 次之但波动大 | **跨仓调拨优先于加急** | 单次缺口成本降 27 倍 |
| 采购成本 | 大 | 订单合并、量价阶梯、寻源 | 量价优化 |
| 加急物流成本 | 中 | 调拨替代、仓网布局 | 比加急便宜 10 倍 |
| 滞销与减值 | 隐性但会突然出现 | 生命周期特征、动态安全库存、停单规则 | — |
| 模型 / 计算成本 | 小 | 分层预测、离线批处理 | 可忽略 |

> **本章成本优化的杠杆排序与其他章完全不同**：库存持有与缺货占了绝大部分，而它们都由**同一件事**驱动——**需求波动 σ 与提前期 L**。所以本章最有效的两招是：**① 把预测做准（降 σ）；② 把供应链缩短（降 L）**。第二招收益更大但周期更长，也更不在软件团队手里。

### 27.4 工程落地与规则护栏

#### 27.4.1 端到端链路

```
自然语言经营目标
  → Goal Parser（结构化 + 追问 + 人均/服务水平提示）
  → Forecast Service（T+1 批：ABC 分层 + 分位数预测 + 区间校准）
  → Inventory Service（可用 / 在途 / 账实 / 安全库存，口径统一）
  → Gap Engine（缺口推演：ROP + SS − 可售）
  → Constraint Solver（MOQ / 箱规 / 仓容 / 产能 / 运力 / 预算）
  → Sourcing & Commitment（供应商比选 → 承诺契约 → 下单，幂等）
  → Fulfilment（多级路由、批次分配、效期先出）
  → Exception Service（缺货 / 延迟 / 超量 / 质量 → 局部重规划）
  → Reconcile Service（账实对账 + 在途对账 + 订单对账）
  → Audit & Calibration（决策留痕 + 牛鞭系数监控 + 模型回放）
```

**两条轨道**：

```
T+1 批量轨道
  → 数据清洗 → 特征 → 分位数预测 → 缺口推演 → 约束求解 → 审批
  → 8h 内必须完成，否则错过下一个补货窗口

在线轨道
  → 库存查询 / 异常检测 / 下单写入 / 承诺下发（毫秒级）
  → 决策 P95 < 200ms

事件驱动重规划
  → 缺货 / 延迟 / 超量 / 质量异常 → 只重算受影响的 SKU × 仓
  → 全网重排会让执行侧无所适从

规则兜底层
  → ROP + EOQ 规则补货：永远可跑，求解器超时也出得了计划
```

> **这张图里有三条「不可省」的线**：**约束求解**（模型只是建议）、**规则兜底层**（永远能出计划）、**对账**（账实不符时不能补货）。前两条决定系统能不能跑，第三条决定它跑出来的东西是不是真的。

#### 27.4.2 目标解析护栏

- 输出结构化 JSON，字段缺失必须追问。
- **必须显式确认：服务水平目标、预算上限、约束清单、可接受的提前期、不可动的物料（认证 / 模具限制）。**
- **必须解析出「缺口口径」**：按可售库存还是按实物库存？按本级需求还是终端需求？**口径不问清，后面所有数字都是空的。**
- 高风险目标（全网大额、动认证物料、单一供应商超集中）强制审批。
- 解析结果可回放、可审计。

#### 27.4.3 预测护栏

| 护栏 | 说明 |
|---|---|
| **分层强制** | A / B / C 三层各自的粒度与窗口不可混用；C 类必须给类目均值兜底值 |
| **区间校准** | 区间覆盖率与偏置必须独立监控，WAPE 只作辅助 |
| **特征禁令** | **禁止把上游订单量作为预测特征**（切断牛鞭的第一机制） |
| **必备特征** | 终端 POS、促销日历、缺货率、生命周期阶段，缺一即降级并标注 |
| **陈旧标记** | 数据超过窗口即标记陈旧，降低信任级别 |
| **版本绑定** | 每条预测绑定模型版本；建议必须引用具体预测版本 |
| **异常值钳制** | 单日需求超出历史 P99 时不直接入模，转人工复核 |

> **「禁止把上游订单量作为预测特征」是本章最反直觉也最重要的一条护栏**。它要求**主动放弃信息**。在一个「上游订单是最丰富特征」的直觉下，这条护栏看起来像自缚手脚——但它正是牛鞭效应的第一机制。**在逐级预测的架构里，看得更近比看得更多重要。**

#### 27.4.4 补货与约束护栏

| 领域 | 护栏 | 优先级 |
|---|---|---|
| **约束不可违反** | MOQ / 箱规 / 仓容 / 产能 / 运力 / 合同价，违反数为 **0** | **P0** |
| **产能可见** | 求解器必须读供应商产能视图，**禁止逐 SKU 独立求解后汇总** | **P0** |
| **不可逆承诺审批** | 下单按金额 / 量 / 品类敏感度分级审批 | **P0** |
| **重复下单为 0** | 计划版本 + 幂等键；下单写入失败**不重试不落单** | **P0** |
| **上限护栏** | 单 SKU / 单供应商 / 单仓的补货量上限与库存持有上限 | **P0** |
| **生效范围** | 补货量不得超过该 SKU 的最大仓容与最大库龄 | **P0** |
| 求解器降级 | 精确 → 启发式 → 规则，三级自动降级并标注 | P1 |
| 建议可解释 | 每条建议附预测、约束余量、依据与置信 | P1 |
| 效期先出 | 同 SKU 多批次按效期先出（FEFO） | P1 |
| 跨仓调拨优先 | 缺口处置顺序固定为调拨 → 加急 → 放弃 | P1 |

#### 27.4.5 履约与异常护栏

- 下发前复核承诺参数：**量、期、价、批次**四项锁定，不允许静默改动。
- 承运商运力与时效承诺必须来自合同能力声明，不来自模型估计。
- **承诺兑现率是过程指标**，低于阈值时停止向下游继续承诺。
- 异常检测必须区分「需求侧 / 供给侧 / 物流侧 / **数据侧**」。
- **数据侧异常（账实不符）必须先修账再谈补货。**
- 事件驱动重规划**只覆盖受影响的 SKU × 仓**，全网重排需人工批准。
- 重规划必须输出「变了什么、为什么变」，并保留上一版以供对比。

#### 27.4.6 审计与对账护栏

| 对账线 | 频率 | 差异容忍 | 超阈值动作 |
|---|---|---|---|
| 账实对账 | 日 / 周 | ≤ 0.1% | 冻结该仓自动补货 |
| **在途对账** | **日** | **≤ 0.01%** | **冻结该供应商自动补货** |
| 订单对账 | 日 | **0** | 转人工，**禁止重试下单** |

> **「订单对账差异必须为 0」比其它两条严得多**，因为它直接对应「重复下单」——而重复下单是本章唯一会立刻造成现金损失的失败（货订两次，钱付两次，货到两次）。

**审计必录字段**：谁、基于哪个预测版本、建议量、约束余量、审批人、是否被采纳、采纳后是否修改、改成多少、最终下单量与建议量的差异。

> **「建议被采纳后改了多少」是本章最有价值的一个审计字段**——它衡量的是**模型与计划员的真实分歧**。长期分歧大，说明要么模型不准、要么约束口径没对齐，**两者都需要修**，而不是让计划员每次手工覆盖。

#### 27.4.7 降级矩阵（Fail-Open / Fail-Closed）

**本节是降级的权威版**，§27.5.6 只引用。

判据：**依赖失效时，失效的后果是「少补一点」还是「多买一批 / 少卖一单」？**

| 依赖 / 环节 | 典型故障 | 策略 | 降级动作 |
|---|---|---|---|
| **库存账实数据** | 超时 / 差异超阈值 | **Fail-Closed** | 冻结该 SKU 自动补货，转人工核对 |
| **在途确认** | 超时 / 与供应商不一致 | **Fail-Closed** | 冻结该供应商自动补货（否则会重复下单） |
| **供应商主数据 / 价格** | 超时 | **Fail-Closed** | 不下单（不知道 MOQ 与合同价） |
| **供应商产能视图** | 超时 | **Fail-Closed（保守）** | 按上次已知产能打折 50% 分配 |
| **ERP / WMS 写入** | 超时 / 冲突 | **Fail-Closed** | **不重试不落单**；错误码返回，人工核销 |
| **主数据映射缺失** | SKU 未映射 | **Fail-Closed** | 跳过该 SKU，**绝不猜映射** |
| **需求预测** | 模型失败 / 超时 | 降级 | 退回类目均值 + 移动平均，**计划照出**，标注低置信 |
| **约束求解器** | 超时 | 降级 | 精确 → 启发式 → **规则补货** |
| **承运商运力** | 超时 | 降级 | 按历史均值估算，**并下调时效承诺** |
| **促销日历** | 数据缺失 | 降级 | 按无促销预测，**该批次标记高风险** |

**治理要点**：

- 每次降级打标 `degraded` + `fallback_mode` + `reason_code`，避免把降级效果误算成模型效果。
- 高频抖动依赖配置熔断器，触发后快速失败。
- 降级比例、原因码分布进入监控与告警。
- **「不重试不落单」是本章降级矩阵的第一原则**——重试一次下单，就是多买一批货。

#### 27.4.8 延迟预算与超时降级

**本表是唯一的延迟口径来源**，其他小节只引用。

**在线轨道（毫秒级）**：

| 阶段 | 预算（目标） | 超时上限（硬限） | 超时后的降级 |
|---|---|---|---|
| 库存与可用量查询 | 80ms | 300ms | 读缓存快照；快照过期则拒答 |
| 异常事件检测 | 200ms | 1s | 跳过该事件，转入批量扫描 |
| 供应商与产能查询 | 100ms | 400ms | 用 T−1 产能快照，**标记为陈旧** |
| 运力查询 | 100ms | 400ms | 按历史均值估算，降低置信度 |
| **下单写入 ERP** | **300ms** | **2s** | **Fail-Closed：不重试不落单** |
| 承诺下发 | 150ms | 600ms | 重试一次，仍失败转人工 |
| 在途确认对账 | — | 30min | 冻结该供应商的自动补货 |

**批量轨道（T+1）**：

| 阶段 | 预算（目标） | 超时上限（硬限） | 超时后的降级 |
|---|---|---|---|
| 数据拉取与清洗 | 1h | 2h | 用上一版数据，**标注陈旧** |
| 特征与分位数预测 | 1h | 2h | 退回类目均值 / 移动平均 |
| 缺口推演 | 10min | 30min | 用简化安全库存口径 |
| **约束求解（精确）** | **30min** | **60min** | **降级到启发式 → 规则补货** |
| 审批与下发 | 2h | 4h | 顺延到下一个窗口并告警 |
| **全链路合计** | — | **8h** | **必须早于下一个补货窗口** |

> **本章的延迟预算与前面所有章都不同：它有两条轨道，而且批量轨道有一条硬约束——「8h 内必须完成，否则错过下一个补货窗口」。** 这条约束决定了两件事：**一是求解必须分层降级**（精确求解跑不完就降级，不能等），**二是审批必须在预算内**（审批超时要顺延到下一个窗口，而不是无限等）。**别的系统超时是「慢一点」，本章超时是「这一轮计划废了」。**

#### 27.4.9 观测与压测

**观测**：

| 类别 | 指标 |
|---|---|
| 预测 | WAPE、**区间覆盖率**、**偏置**、分位数分层的 P90 命中率 |
| **信号保真** | **牛鞭系数（订单波动 / 终端需求波动）**、缺货期下单比 |
| 库存 | 周转天数、滞销占比、呆滞金额、安全库存占用 |
| 服务 | 缺货率、OTIF、缺货时长、承诺兑现率 |
| 产能 | **产能挤占率**、单供应商集中度、延期 SKU 数 |
| 决策 | 计划生成耗时、**建议采纳率**、**建议修改率**、约束违反数、重复下单数 |
| 对账 | 账实差异率、在途差异率、订单差异数 |
| 降级 | 降级比例、原因码分布、规则补货占比 |

> **「牛鞭系数」是本章的体温计**：它比 WAPE 更早、更直接地反映信号失真。**WAPE 变差说明模型不准了；牛鞭系数变差说明架构里某处的信息在失真**——后者是架构问题，改模型没用。

**压测**：

- **单个补货窗口内 200 个计划并发**（验证求解资源与降级路径）。
- 单计划 2,000 SKU 的精确求解超时（验证降级到规则）。
- 提前期从 45 天跳到 90 天（验证安全库存重算与在途暴露）。
- 供应商产能骤降 50%（验证产能挤占保护与违约监控）。
- 库存流水重复事件（验证幂等与账实一致性）。
- 在途确认接口超时（验证 Fail-Closed 与重复下单防护）。
- ERP 写入超时（验证**不重试不落单**）。
- 促销日历缺失（验证降级标记与高风险批次）。
- 大促流量（预测与缺货同时爆发）。

#### 27.4.10 规则护栏清单

| 领域 | 护栏 | 优先级 |
|---|---|---|
| **约束不可违反** | MOQ / 箱规 / 仓容 / 产能 / 运力 / 合同价，违反数为 0 | **P0** |
| **重复下单为 0** | 计划版本 + 幂等键；**下单失败绝不重试** | **P0** |
| **库存只能由事件累加** | 禁止任何直接改写库存的接口 | **P0** |
| **账实与在途对账** | 差异超阈值即冻结对应范围的自动补货 | **P0** |
| **不可逆承诺分级审批** | 金额 / 量 / 品类敏感度三档阈值 | **P0** |
| **产能可见** | 求解器必须读产能视图，禁止逐 SKU 独立汇总 | **P0** |
| **账实不符不给建议** | 信任级别降为「低」，只给数据不给补货量 | **P0** |
| **建议可解释** | 每条建议附预测版本、约束余量、依据与置信 | **P0** |
| **审计不可篡改** | 含「建议被采纳后改了多少」 | **P0** |
| **规则兜底永远可跑** | 求解器 / 模型全挂时仍能出计划 | **P0** |
| 特征禁令 | 禁止把上游订单量作为预测特征 | P1 |
| 分层与校准 | ABC 分层强制；区间覆盖率与偏置独立监控 | P1 |
| 重规划范围 | 只重算受影响的 SKU × 仓 | P1 |
| 调拨优先 | 缺口处置顺序：调拨 → 加急 → 放弃 | P1 |
| 承诺兑现监控 | 低于阈值即停止向下游继续承诺 | P1 |
| 牛鞭系数监控 | 逐层测量，作为架构健康信号 | P1 |
| 回放纪律 | 回放完整策略、含促销与缺货期、用当时库存 | P2 |
| 成本 | 持有成本 / 缺货成本 / 加急成本看板 | P2 |

> **本章的十个 P0 里有七个是「下单之前」的检查**。原因与营销章一样，但更极端：**营销发错的消息能撤回一部分，供应链发错的订单撤不回**——货已经在路上，钱已经付了，合同已经签了，供应商产能已经被占。**所以本章的 P0 几乎全部集中在「承诺之前」这一个位置上。**

#### 27.4.11 上线检查（10 问）

1. 目标解析是否结构化并可确认？**缺口口径（可售 vs 实物、本级需求 vs 终端需求）是否已明确？**
2. **预测特征里是否有上游订单量？** 若有，是否已按牛鞭机制评估过其影响？
3. 预测是否输出**分位数**？区间覆盖率与偏置是否独立监控，而不是只看 WAPE？
4. **安全库存口径是否全网统一**（z 值分层、提前期取均值还是 P90、σ 怎么估）？
5. 约束求解器是否读**供应商产能视图**？是否仍存在逐 SKU 独立求解后汇总的路径？
6. 建议发出前是否通过**可行性校验**（MOQ / 箱规 / 仓容 / 运力 / 合同价）？违反数是否为 0？
7. **下单是否幂等？写入失败是否「不重试不落单」？** 是否有任何路径会重复下单？
8. 账实 / 在途 / 订单三条对账线是否都已上线？**差异超阈值是否真的会冻结自动补货？**
9. 降级矩阵是否演练过？**求解器超时是否能退回规则层出计划？** 降级是否打了 `degraded` + 原因码？
10. **牛鞭系数是否被逐层测量并监控？** 建议采纳率与修改率是否有看板？

### 27.5 典型案例与端到端解决

#### 27.5.1 案例：华东仓断货风险与滞销压降

**目标**：「华东仓未来 4 周要保证不断货，同时把滞销库存压降 20%，预算 200 万。」

**S0 落锚点**：

| # | 锚点 | 本案例答案 |
|---|---|---|
| 1 | 成功标准 | 断货 SKU 数 0、A 类缺货率 ≤ 1%、滞销金额降 20%、OTIF ≥ 98% |
| 2 | 规模 | 华东 3 仓、A 类 SKU 4,000 个、风险 SKU 120 个、滞销 SKU 860 个 |
| 3 | 质量优先级 | 不断货 > 不积压 > 不违约 > 资金成本 > 响应速度 |
| 4 | 硬约束 | 仓容 12,000 m³、主供商本月产能已用 62%、预算 ¥200 万、MOQ 与箱规 |
| 5 | 不可逆清单 | 库存成本口径、安全库存口径、预测粒度、账实归属、主数据标识、承诺契约、重规划范围 |
| 6 | 事实源 | 库存流水 + 订单 + 主数据 + 供应商履约记录 |
| 7 | 边界 | ERP / WMS / TMS 与供应商门户在外部；预测、缺口推演、求解、异常处置自建 |

**链路**：

1. **目标解析**：确认**缺口口径 = P90 需求（4 周）− 可售库存（可用 + 在途，按 ETA 计入）**，服务水平 A 类 99%；「滞销」定义为库龄 > 90 天且近 8 周无动销。**系统主动追问「在途是否计入」**——这一条决定了后面 18,600 件里有多少是真实缺口。
2. **预测**（T+1 批）：A 类 SKU × 仓 × 日 × P50/P90/P95；**特征 = 终端 POS + 促销日历 + 缺货率 + 生命周期，不含上游订单量**。
3. **缺口推演**：120 个风险 SKU，合计缺口 **18,600 件**；按提前期分组：陆运 7 天 7,200 件、海运 45 天 11,400 件。
4. **约束求解**（精确 + 产能视图）：受 MOQ / 箱规 / 仓容 / **主供商剩余产能 38%** / 预算约束，**直接补货只能覆盖 76 个 SKU、13,200 件**。
5. **调拨**：华东三仓互调 + 相邻华中仓调入，覆盖 **31 个 SKU、4,100 件**，物流 ¥3/件 = **¥12,300**。
6. **加急与取舍**：剩余 9 个 SKU 走空运加急（1,000 件，¥30/件 = **¥30,000**）；4 个 SKU、300 件因毛利低于加急成本而**主动接受缺货**。
7. **采购与预算**：18,300 件 × ¥60 采购成本 = **¥109.8 万** < ¥200 万预算，余额 ¥90.2 万。
8. **滞销压降**：860 个 SKU、占用资金 ¥3,600 万；压降 20% = **释放 ¥720 万**——**比补货预算还多 3.6 倍**。
9. **下单**：带计划版本与幂等键写入 ERP，落承诺契约（量 / 期 / 价 / 批次四项锁定）。
10. **对账**：日账实 + 日在途；差异超阈值即冻结对应范围自动补货。

**本案例最重要的一个数字**：

```
滞销压降释放资金 ¥720 万  ≫  补货预算 ¥200 万
```

> **「砍库存」和「补库存」是同一笔钱的两个方向。** 一个只看补货需求的系统，会把「缺货」和「积压」当成两个独立问题分别要预算；**真正有效的做法是先算「滞销释放的资金」，再决定补货能力**。本章的「压降 20%」不是需求侧的附属指标，**它就是补货预算的来源**。

**牛鞭验证（本案例的核心实测）**：

| 方案 | 预测 WAPE | **牛鞭系数** | 结论 |
|---|---|---|---|
| 用上游订单量做特征 | 18% | **2.4** | 信号被放大，产能与库存被推到错误位置 |
| **用终端 POS + 促销日历 + 缺货率** | 15% | **1.3** | 信号基本保真 |

> **WAPE 只降了 3 个点，牛鞭系数却降了 46%。** 这个对比是本章论点的最好证明：**Agent 的价值不在「预测得更准」，而在「让信号不失真」。** 如果只看 WAPE，会得出「提升有限、不值得投」的结论；**但真正该看的指标是牛鞭系数**——它从 2.4 降到 1.3，意味着上游订单的波动从「终端的 2.4 倍」回到「终端的 1.3 倍」，**产能、库存、运力不再被推到错误的位置上**。

#### 27.5.2 变体 A：常规周度补货

**特点**：周期 7 天、SKU 多、量大、时效宽松。

**额外护栏**：

- 走**规则补货层**为主（ROP + EOQ），只对异常 SKU 走模型层。
- 计划在补货窗口前 **8h** 完成；求解超时自动降级到规则层。
- 建议必须附**约束余量**（离 MOQ、离仓容、离产能各还有多少）。
- 建议采纳率与修改率进看板——**分歧大说明模型或口径要修，不是让计划员每次手工覆盖**。

#### 27.5.3 变体 B：新品首发铺货

**特点**：无历史数据、预测最不可靠、错误成本高（首批压太多就滞销，压太少就断货）。

**额外护栏**：

- **不做点估计，只做分位数铺货**：首批 = P50，试销期再按 P90 追单。
- 必须有人工审批（新品是决策，不是执行）。
- **首单必须考虑供应商 MOQ 与最小起订量**——很多新品的合理首批量就是 MOQ，此时「多备一点」不是失误而是约束。
- 试销期设**强制复盘点**：上市后第 7 / 14 / 30 天各复核一次销量曲线，偏差超阈值即调整追单。

> **新品是本章唯一一个「模型主动说不知道」的合法场景**。此时正确的输出不是「建议铺 1,000 件」，而是「**P50 铺 600 件、P90 追 1,400 件，首批受 MOQ 约束取 1,000 件；7 天后按实际曲线决定是否追单**」——**把不确定性显式地交给后续决策，而不是藏在一个点估计里。**

#### 27.5.4 变体 C：供应商延迟与违约处置

**特点**：标的时效强，承诺不可兑现。

**额外护栏**：

- 下发前复核承诺参数：量、期、价、批次四项锁定。
- **承诺兑现率低于阈值时，停止向下游继续承诺**（否则缺货会沿链传导）。
- 供应商评估五维中，**产能维度必须进补货求解器**——否则下一个超量订单会挤占产能。
- 违约处置走**分级切换**：延迟 → 改承诺期 → 部分切备供 → 全切备供。
- **不可替代物料必须提前登记**，其主供中断时直接进入「加急 / 降级供应」路径，而不是走常规寻源（认证要 3 个月，来不及）。

#### 27.5.5 变体 D：跨仓调拨替代补货

**场景**：华南某 A 类 SKU 缺 1,000 件，5 天后断货。

**三级处置对比**：

| 方案 | 单价 | 到货 | 成本 | 备注 |
|---|---|---|---|---|
| **跨仓调拨** | ¥3 / 件 | 1 天 | **¥3,000** | **最优先** |
| 供应商加急空运 | ¥30 / 件 | 5 天 | ¥30,000 | 比调拨贵 10 倍 |
| 放弃销售 | 毛利损失 ¥80 / 件 | — | ¥80,000 | 比调拨贵 27 倍 |

**调拨的决策顺序**：

```
1. 查全网可用库存（含相邻大区）——不是只看相邻两仓
2. 评估调出仓的代价：调走后它自己的缺口由谁补？
3. 比对物流时效与成本（调拨也可能来不及）
4. 都不行才加急；加急仍不划算才接受缺货
```

> **调拨的隐性成本必须算进去**：调走 A 仓的 1,000 件，A 仓自己的缺口只能靠下一轮补货填上。**所以调拨的真实成本 = 物流成本（¥3,000）+ 下一轮补货量的增加**。很多系统只比了物流成本，就以为调拨「免费」——**它其实是把缺口从这一轮挪到了下一轮**。
>
> **但即便如此，它通常仍然划算**：因为下一轮的补货是**计划内的**（可以被提前安排、可以和其它 SKU 合并下单、可以用海运），而这一轮的缺货是**计划外的**（只能加急、只能放弃）。**「计划外的贵 vs 计划内的便宜」是本章的核心成本直觉。**

#### 27.5.6 故障与兜底

降级矩阵以 §27.4.7 为准，本例补充两条：

| 故障 | 影响 | 兜底 |
|---|---|---|
| **下单接口超时** | **不知是否已落单** | **不重试、不落单，转人工核销**——重试即重复下单 |
| **预测结果与人工判断冲突** | 建议被大面积覆盖 | **不视为模型失败，但必须记录修改量并回流**——长期分歧大说明口径或模型有问题 |

#### 27.5.7 扩容 10 倍，哪里先坏？

以 §27.3.16 的基准扩容（SKU ×4 → 200 万、仓 ×10 → 2,000、日销 ×4 → 800 万件、日补货计划 200 → 2,000 个）：

| 顺序 | 先坏的点 | 现象 | 触发指标 | 对策 |
|---|---|---|---|---|
| 1 | **批量轨道的求解窗口** | 计划跑不完，错过补货窗口 | 单计划求解 > 30min，或 2,000 计划未在 8h 内完成 | 求解分区并行；A 类精确 / B、C 走规则；**滚动计算**（提前算下一窗口） |
| 2 | **预测计算** | 预测任务积压 | 预测完成时间 > 2h | C 类不上模型；增量特征；特征缓存 |
| 3 | **库存查询** | P99 上升 | 峰值 > 1,400 QPS | 读缓存、物化可用量视图、分区 |
| 4 | **在途对账** | 对账窗口放不下 | 对账耗时 > 30min | 按供应商并行；增量对账 |
| 5 | **供应商产能视图** | 产能分配变慢 | 分配耗时 > 60s | 产能离线预分配、增量更新 |
| 6 | 事件链路 | 积压 | lag > 100 万 | 扩分区、批量 |
| 7 | **库存持有成本（非线性）** | 持有成本随 SKU 数增长 | 持有成本 > 预算 | **先收紧长尾的服务水平，而不是全线提高** |

> **第 1 位是本章特有的**：别的系统扩容先坏的是 QPS 与存储，**供应链 Agent 扩容先坏的是「一个补货窗口内算不计算得完」**。因为它的 QPS 峰值只有 1,400（很轻），但每个计划是一个 30–120s 的精确求解，2,000 个计划挤在同一个窗口里。**扩容供应链 Agent 的第一件事是「让计划滚动起来」，而不是加机器。**
>
> **第 7 位也值得单独记**：新增的 SKU 多半是长尾，**给长尾提高服务水平的边际毛利，小于它带来的持有成本**。所以扩容时第一个该动的不是「预测做得更好」，而是**收紧长尾的服务水平**——这是本章少见的「扩容要往回收」的 counterintuitive 结论。

#### 27.5.8 取舍复盘

| 决策 | 代价 | 收益 | 重新评估条件 |
|---|---|---|---|
| **终端数据优先于上游订单** | 放弃上游订单这个特征 | 牛鞭系数 2.4 → 1.3 | 架构改为单层预测时可放开 |
| **调拨优先于加急** | 占用调出仓额度 | 缺口成本降 27 倍 | 全网库存紧张时 |
| 精确求解优先 | 算力成本 | A 类全局最优 | 算力充足时扩大覆盖 |
| **规则兜底常备** | 建议质量下降 | 永远出得了计划 | —— |
| 账实不符冻结补货 | 少补货 | 不买错货 | 对账能力提升后缩短冻结窗口 |
| 分层服务水平 | 长尾服务差 | 资金用在刀刃上 | 缺货损失结构变化时 |
| 事件驱动重规划 | 计划不稳定 | 响应快 | 波动小时降频 |
| **模型给建议不给指令** | 采纳率受限 | 约束不被绕过 | 计划员高度信任模型后可放宽 |
| **滞销与补货同账核算** | 需要打通资金与库存口径 | 释放资金反哺补货 | 口径统一后可进一步合并 |

### 27.6 闭环演进与常见误区

#### 27.6.1 演进路线

| 阶段 | 形态 | 触发条件 | 关键改造 |
|---|---|---|---|
| L0 | 人工 + Excel 补货 | 起步 | 经验规则 |
| L1 | MRP / 固定参数补货 | SKU 变多 | 批量计算、ROP + EOQ |
| L2 | 统计预测 + 分层服务水平 | 精度要求 | ABC 分层、动态安全库存 |
| L3 | 约束求解 + 产能可见 | 约束冲突频发 | 求解器、产能视图、可行性校验 |
| **L4** | **信号保真（牛鞭治理）** | **上游波动大、缺货与积压并存** | **终端数据直连、特征禁令、缺货率入模** |
| L5 | 供应网络联合决策 | 成熟 | 多级库存、寻源、跨仓联合求解、跨期优化 |

> **L4 是本章最容易被跳过、也最不该跳过的一层**。很多系统从 L1 直接跳到 L3（上了求解器和预测模型），但**只要信息还在逐级失真，求解器越精确，放大的误差就越大**——**它会把「算得更准」变成「把错的算得更精确」**。L4 的关键是数据链路，不是模型。

#### 27.6.2 指标体系

| 层级 | 指标 | 用途 |
|---|---|---|
| 预测 | WAPE、**区间覆盖率**、**偏置** | 判断预测质量 |
| **信号** | **牛鞭系数**、缺货期下单比 | **判断架构是否失真** |
| 库存 | 周转天数、滞销占比、呆滞金额、**安全库存占用** | 判断资金效率 |
| 服务 | 缺货率、OTIF、缺货时长、承诺兑现率 | 判断服务水平 |
| 产能 | **产能挤占率**、供应商集中度、延期 SKU 数 | 判断供应风险 |
| 决策 | 计划生成耗时、建议采纳率、**建议修改率**、约束违反数、重复下单数 | 判断系统可用性 |
| 对账 | 账实差异率、在途差异率、订单差异数 | 判断账目健康 |
| 成本 | 持有成本、缺货成本、加急成本 | 判断可持续 |

#### 27.6.3 评测与回归

**回放三纪律**（本章最容易作弊的地方）：

| 纪律 | 不遵守的后果 |
|---|---|
| 回放**完整策略**（含安全库存、提前期、MOQ 约束） | **系统性高估收益**——只回放预测精度，会算出「预测准了就能省钱」的假结论 |
| 包含**促销期与缺货期**样本 | 模型在最重要的样本上从未被评测 |
| 使用**当时的库存状态** | 用今天的库存回放历史，缺货本身被消除，结论失真 |

**变更与回归**：

| 变更类型 | 必须回归什么 |
|---|---|
| 预测模型 / 特征变更 | 区间覆盖率、偏置、**牛鞭系数** |
| 安全库存口径变更 | 全量 SKU 的补货量、库存金额、缺货率回放 |
| 约束规则变更 | 求解可行性、产能占用、计划稳定性 |
| 主数据 / 映射变更 | 对账、异常率 |
| 求解器或算法变更 | 建议采纳率、建议修改率 |

> **建议修改率是变更回归里最灵敏的指标**：模型换了一版，如果计划员的修改率从 5% 涨到 20%，说明**新模型与人的判断分歧变大了**——即使所有离线指标都变好了。**因为离线指标衡量的只是「预测准不准」，而修改率衡量的是「这个建议能不能被执行」。**

#### 27.6.4 成本优化

**按杠杆排序**（不是按实现难度）：

| 顺序 | 手段 | 收益量级 | 说明 |
|---|---|---|---|
| 1 | **把预测做准（降 σ）** | **安全库存减半 → 库存总成本降 39%** | **本章最大杠杆** |
| 2 | **缩短提前期（降 L）** | 安全库存 ∝ √L，L 降一半 → 降 29% | 收益更大但周期更长，**不靠软件** |
| 3 | **缺口处置先调拨后加急** | 单次缺口成本降 27 倍 | 运营与仓网布局 |
| 4 | **分层服务水平** | 资金从长尾挪到高价值品类 | 与「全线提高」相反 |
| 5 | 滞销与补货同账核算 | 释放资金反哺补货 | §27.5.1 |
| 6 | 求解器分层（精确 / 启发式 / 规则） | 算力成本降 | 质量略降 |

> **第 1、2 两条都作用在同一个公式上**：`SS ∝ σ × √L`。**这两个变量是本章的全部杠杆**——预测精度是软件能做的，提前期是供应链本身能做的。**其余手段（模型更复杂、求解更精确）都不在这两个变量上，天花板很低。**

#### 27.6.5 产品对比

| 场景 | 核心矛盾 | 关键护栏 |
|---|---|---|
| 快消品补货 | 高频小批量 vs 提前期长 | MOQ、箱规、多级库存 |
| 电商大促备货 | 预测难、峰值高、时效紧 | 促销日历、提前锁定产能、分批 |
| 生鲜 | 保质期短、损耗高 | FEFO、安全库存压到极低 |

| 跨境电商 | 多币种、多税、时效不稳 | 承诺期保守、在途对账 |

#### 27.6.6 常见误区

| 误区 | 问题 | 正确做法 |
|---|---|---|
| **用上游订单做预测特征** | **放大牛鞭，越准越糟** | **终端数据直连 + 特征禁令** |
| 只看 WAPE | 区间偏了照样错 | 区间覆盖率 + 偏置独立看 |
| 安全库存用固定值 | 波动变化时全错 | 动态 SS：σ × √L × z |
| 模型输出直接变订单 | 违反 MOQ / 仓容 / 产能 | 约束求解层 + 可行性校验 |
| **逐 SKU 独立求解后汇总** | **产能挤占，1 个错变 20 个错** | **按产能做全局分配** |
| 用点估计补货 | 不确定性被平均掉 | 分位数预测 + 显式安全库存 |
| 下单失败重试 | **重复下单 = 超买** | **不重试不落单，转人工核销** |
| 只对账实物，不对在途 | 缺口被隐藏 | 三条对账线，订单差异必须为 0 |
| 缺货一律加急 | 花 10 倍的钱买 4 天 | **调拨 → 加急 → 放弃** |
| 忽略上游波动 | 产能与库存被推到错位置 | 逐层测牛鞭系数 |
| 新品也用点估计 | 首批压错就滞销 | 新品用分位数铺货 + 人工审批 |
| 扩容只看 QPS 与存储 | 算不完计划，窗口错过 | 看「一个窗口内能算完多少计划」 |
| 忽略调拨的隐性成本 | 把缺口挪到下一轮 | 把下一轮补货量算进调拨成本 |
| **把模型建议当指令** | 绕过约束，错误被放大 | **模型给建议，约束做决定** |

#### 27.6.7 高频追问

- **为什么用上游订单做预测特征是错的？** → 那是逐级预测，误差逐级叠加，放大 16 倍；**预测越准，放大越狠**。要用终端 POS。
- **牛鞭效应的四个机制是什么？** → 预测逐级叠加、订单批量、价格促销、缺货配给；**只有第一个是 Agent 直接放大的**。
- **怎么定安全库存？** → `SS = z × σ_daily × √L`；z 按 ABC 分层，σ 按生命周期分档，L 取分布的 P90 而非均值。
- **为什么模型不能直接输出补货量？** → MOQ、箱规、仓容、供应商产能、承运商运力都是硬约束；**模型只能给建议，约束求解层给结果**。
- **什么是产能挤占？** → 一个 SKU 的超量订单吃掉供应商共享产能，**影响其它 20 个 SKU**；必须把产能视图放进求解器，按产能全局分配。
- **缺货了先做什么？** → **先查全网库存做调拨**（¥3/件），再考虑加急（¥30/件），最后才放弃（毛利 ¥80/件）。
- **下单接口超时怎么办？** → **不重试、不落单**，转人工核销；重试就是重复下单。
- **账实不符还能补货吗？** → **不能**；冻结该 SKU 自动补货并转人工，先修账再谈补货。
- **怎么评估补货 Agent？** → 完整策略回放（含安全库存、提前期、约束），**不是只回放预测精度**；主指标是区间覆盖率、偏置与牛鞭系数。
- **为什么新品要用分位数铺货？** → 没有历史数据，点估计最不可靠；P50 首批 + P90 追单 + 强制复盘点，把不确定性交给后续决策。
- **扩容先坏哪里？** → **不是 QPS，是「一个补货窗口内算不计算得完」**；要让计划滚动起来。
- **Agent 在这里最大的价值是什么？** → **不是预测更准，是让信号不失真**：WAPE 只降 3 个点，牛鞭系数却降 46%。
