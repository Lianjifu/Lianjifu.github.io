## 第三十章 安全运营 AI Agent（SecOps / SOC Agent）

> **本章导读**：安全运营 Agent 面对的是会主动对抗、会隐藏、会利用你自身工具的攻击者，核心不是「多接几个告警源」，而是「在假设已失陷的前提下，先把跨源证据拼成攻击链，再用最小、可逆、可审计的遏制动作止损」。本章围绕告警关联与 ATT&CK 映射、威胁情报与证据时间线、遏制风险分级与爆炸半径、审计留痕展开，整体按「定义 → 矛盾 → 方法论 → 工程护栏 → 端到端案例 → 演进与误区」组织。

### 30.1 核心定义与定位

**定义**：安全运营 AI Agent（SecOps / SOC Agent）是在安全告警接入、威胁研判、受控遏制、证据保全与合规复盘全链路中，理解多源安全遥测与攻击者行为、调用安全工具、执行受控动作并对结果负责的智能体系统。

**核心目标**（原文保留）：在保障业务连续性与合规底线的前提下，把「安全告警/威胁事件」转化为可降噪归并、可跨源溯源、可受控遏制、可审计复盘的生产级安全处置闭环。

**五类核心能力**：

| 能力 | 典型任务 | 主要风险 | 关键护栏 |
|---|---|---|---|
| 告警分诊 | 归并、降噪、严重度分流 | 噪音淹没、漏报 | 实体关联 + 资产富化 |
| 威胁研判 | 跨源取证、ATT&CK 阶段判断 | 误判、证据链断裂 | IOC/IOA + 时间线 |
| 受控遏制 | 隔离、封禁、禁用、撤销凭证 | 误杀核心资产 | 爆炸半径 + 审批 + TTL |
| 威胁狩猎 | 假设驱动的主动检索 | 无的放矢、查询过载 | 假设登记 + 查询配额 |
| 复盘沉淀 | 误报/误杀分析、Playbook | 经验流失 | 不可篡改审计 + 样本回流 |

**典型用户**：

| 用户 | 诉求 | 关注点 |
|---|---|---|
| SOC L1 分析师 | 快速分诊、少误报 | 告警准、上下文全 |
| SOC L2/L3 与 IR | 攻击链还原、遏制决策 | 证据链、影响面 |
| 安全负责人 | MTTD/MTTC、误杀率 | 风险与业务平衡 |
| 合规与审计 | 处置可追溯 | 审计完整、权限合规 |

**与通用问答/常规运维 Agent 的差异**：

| 维度 | 常规运维 Agent | 安全运营 Agent |
|---|---|---|
| 对手 | 无主动对手 | 攻击者会对抗、会隐藏 |
| 输入 | 遥测与变更 | 遥测 + 恶意载荷 + 情报 |
| 证据 | 指标/日志/Trace | 跨身份、终端、网络、云 |
| 动作 | 重启、扩容、回滚 | 隔离、封禁、禁用、撤凭证 |
| 误判后果 | 服务抖动 | 业务中断、证据破坏、合规事件 |
| 审计 | 操作留痕 | 不可篡改、可举证 |

原文四条差异（保留）：

1. **直面潜在恶意行为与对抗性输入**：日志、邮件、命令行、HTTP 载荷都可能包含攻击者构造的 Prompt Injection。
2. **隐蔽的多阶段攻击链**：单条告警往往只是冰山一角，需要跨身份、终端、网络、云审计关联。
3. **遏制动作的误杀代价极高**：封禁共享出口、隔离核心主机、禁用特权账号可能直接中断业务。
4. **强审计与合规要求**：谁在何时基于什么证据执行了什么动作，必须可追溯、不可篡改。

**系统边界**：

| 范围内 | 范围外 |
|---|---|
| 告警归并、实体关联、富化 | 检测规则引擎与特征生产 |
| 威胁研判与攻击链还原 | EDR/WAF 探针实现 |
| 遏制动作编排与审批 | 身份系统与网络设备内部 |
| 证据保全与审计 | 法务取证与执法协作 |
| Playbook 与复盘沉淀 | 组织级安全治理流程 |

**核心指标**：

| 类别 | 指标 |
|---|---|
| 检测 | 准确率、召回率、误报率、漏报率、MTTD |
| 研判 | 攻击阶段准确率、IOC 精确率、证据覆盖率、MTTA |
| 遏制 | MTTC、自动遏制成功率、误杀率、回滚率 |
| 安全 | 未授权遏制数、核心资产误伤数、TTL 清理率 |
| 合规 | 审计完整率、审批合规率、证据可举证率 |

**SLO 示例**：

| 指标 | 目标 |
|---|---|
| 告警归并 P95 | 小于 30s |
| 事件初筛 P95 | 小于 60s |
| 调查摘要生成 P95 | 小于 3min |
| 遏制动作执行 P99 | 小于 5s |
| 未授权遏制 | 0（硬约束） |
| 核心资产误伤 | 0（硬约束） |
| 审计写入成功率 | 100% |

### 30.2 核心解读与关键矛盾

**本质**：安全运营 Agent 的核心矛盾，是「攻击者的不确定性与对抗性」与「防御动作必须确定、可解释、可回滚」之间的冲突。模型可以提出「可能已失陷」的假设，但不能凭假设隔离核心生产主机。

**三个放大器**：

| 放大器 | 说明 | 后果 |
|---|---|---|
| 身份放大 | 一个高权限账号可横跨全部系统 | 单点失陷变全域失陷 |
| 资产放大 | 核心主机/共享出口承载大量业务 | 误杀即大面积中断 |
| 合规放大 | 处置过程需要可举证 | 审计缺失即合规事件 |

**八组关键矛盾**：

| 矛盾 | 典型表现 | 默认策略 | 何时反转 |
|---|---|---|---|
| 快速遏制 vs 业务连续 | 先封再说会误杀 | 证据充分再遏制、先隔离后清除 | 勒索/外传进行中可加速 |
| 自动化 vs 误杀 | 自动封禁风险高 | 风险分级 + 审批 + TTL | 低风险可逆动作可自动 |
| 广谱检测 vs 噪音 | 规则宽则告警多 | 实体关联 + 资产富化 | 重大活动期可加严 |
| 证据保全 vs 快速恢复 | 重装会毁证据 | 先快照/取证再恢复 | 业务不可等待时最小保全 |
| 假设失陷 vs 最小权限 | 全面排查成本高 | 按攻击链关键节点取证 | 高危信号可全域排查 |
| 情报依赖 vs 情报不可用 | 情报超时无法封禁 | 标记未确认，不单独作为依据 | 有本地行为证据可处置 |
| 长攻击链 vs 上下文窗口 | 跨天链路塞不下 | 槽位 + 摘要 + 证据索引 | 疑难案件可拉长窗口 |
| 审计完整 vs 敏感保护 | 日志含凭证与个人信息 | 脱敏后留存、分级访问 | 合规要求更严格 |

**四类正确性**：

| 层次 | 要求 | 保障手段 |
|---|---|---|
| 检测正确 | 不漏关键攻击、噪音可控 | 实体关联 + ATT&CK 覆盖 |
| 研判正确 | 阶段判断有证据、可复核 | 证据时间线 + 假设登记 |
| 遏制正确 | 目标、范围、时长正确 | 资产关键度 + 爆炸半径 + TTL |
| 审计正确 | 全程可追溯、不可篡改 | WORM + 哈希链 + 审批分离 |

**八类失败模式**：

| 失败 | 表现 | 根因 | 防线 |
|---|---|---|---|
| 噪音淹没 | 真攻击被埋 | 无实体归并 | 实体 + 时间窗聚合 |
| 单点误判 | 把运维脚本当攻击 | 只看单条告警 | 跨源取证 + 基线 |
| 误杀核心资产 | 业务中断 | 未评估关键度 | 资产画像 + 审批 |
| 封禁共享出口 | 整层楼/VPC 断网 | 未识别 NAT/网关 | 出口识别 + 白名单 |
| 证据破坏 | 无法复盘/举证 | 先重装后取证 | 先快照再清除 |
| 遏制不彻底 | 攻击者换 IP 继续 | 只封单点 | 封域名/行为/凭证 |
| 注入越权 | 载荷诱导执行 | 不可信数据入指令区 | 数据隔离 + 策略引擎 |
| 审计缺失 | 无法追责 | 审计非强制 | 审计不可用禁止高危写 |

**六条设计原则**（原文保留）：

- **假设已失陷**：先按最坏情况收集证据，不因「看起来像误报」而跳过关键检查。
- **证据先行**：先只读取证，再决定是否遏制；模型输出只是假设，不是结论。
- **最小遏制、可逆优先**：优先单会话、单终端、单 IP；核心资产与全站策略必须审批。
- **TTL 与回滚**：临时封禁/隔离默认带过期时间与撤销接口。
- **不可信输入零信任**：所有外部载荷只当数据，不当指令。
- **审计不可用则禁止高危写操作**：没有留痕就不执行。

**威胁模型**（以攻击者视角）：

| 威胁 | 路径 | 防线 |
|---|---|---|
| Prompt 注入 | 邮件/日志/命令行含指令 | 数据隔离 + 策略引擎 |
| 凭证窃取 | 钓鱼、MFA 绕过 | 会话吊销 + 强制轮换 |
| 横向移动 | 复用凭据、远程执行 | 实体关联 + 分段 |
| 供应链 | 第三方组件/账号 | 依赖审计 + 最小权限 |
| 内部人员 | 越权访问、数据外传 | 行为基线 + 双人审批 |
| Agent 工具滥用 | 诱导高危动作 | 白名单 + 参数校验 |
| 审计篡改 | 删除/伪造记录 | WORM + 哈希链 |

**成本结构**：

| 成本项 | 占比量级 | 优化手段 |
|---|---|---|
| SIEM 查询/存储 | 最大 | 时间窗收敛、热冷分层 |
| LLM | 次之 | 模型分级、证据裁剪、缓存 |
| 威胁情报 | 中 | 按需查询、本地缓存 |
| 分析师复核 | 视风险 | 阈值优化、低风险自动化 |

#### 30.3.7 告警接入与实体关联

**核心挑战**：单一攻击会触发多条关联告警（异常登录、可疑进程、横向移动、外连 C2），日常扫描与良性运维脚本又会产生大量背景噪音；原始日志、命令行与流量载荷体积大、字段杂乱。

**实体与时间窗关联**（原文保留）：

- 核心实体：`src_ip`、`user_identity`、`host_id`、`process_tree`、`domain/hash`、云资源 ID。
- 围绕实体与时间窗归并告警，形成统一 `case_id`。
- 早期富化资产标签：生产/测试、核心/普通、业务归属、数据密级、暴露面。

**补充**：

- 实体归一化：同一账号的 UPN/邮箱/别名要归并为一个实体 ID。
- 关联窗口按攻击类型配置：钓鱼分钟级、横向移动小时级、数据外传天级。
- 保留原始告警与富化结果，便于复盘与规则调优。
- 降噪不能只靠规则数量，要看实体关联后的「故事完整度」。

#### 30.3.8 ATT&CK 阶段映射

把告警映射到 ATT&CK 阶段：初始访问、执行、持久化、权限提升、防御规避、凭证访问、发现、横向移动、收集、外传、影响。

| 阶段 | 典型信号 | 调查重点 |
|---|---|---|
| 初始访问 | 钓鱼、暴露面扫描、弱口令 | 入口与投递方式 |
| 执行 | PowerShell、脚本、宏 | 父进程与命令行 |
| 持久化 | 计划任务、服务、启动项 | 落地文件与注册表 |
| 权限提升 | 提权漏洞、sudo 滥用 | 提权前后账号 |
| 防御规避 | 关闭日志、混淆、白利用 | 安全产品状态 |
| 凭证访问 | LSASS、凭据文件 | 凭据是否外泄 |
| 发现 | 内网扫描、枚举 | 影响范围 |
| 横向移动 | 远程登录、SMB/WinRM | 已失陷主机集合 |
| 收集 | 打包、压缩 | 目标数据 |
| 外传 | 稀有域名、大流量上传 | 外传通道与数据量 |
| 影响 | 加密、删除、篡改 | 业务与备份 |

**判断当前处于「单点异常」还是「多阶段链路」，决定调查深度与遏制紧迫度。** IOC（IP/域名/哈希）与 IOA（行为模式）结合，避免只靠静态指标。

#### 30.3.9 威胁情报与 IOC/IOA

| 类型 | 说明 | 使用方式 |
|---|---|---|
| IOC | IP、域名、哈希、URL | 匹配已知恶意指标 |
| IOA | 行为模式、进程链、异常序列 | 识别未知变种 |
| 情报置信度 | 来源、时效、命中次数 | 决定是否作为封禁依据 |

**要求**：情报命中只作为线索，需结合本地行为证据；情报超时或未确认时不得单独驱动封禁。

#### 30.3.10 结构化事实槽位

| 槽位 | 作用 |
|---|---|
| `case_id` | 单一调查上下文 |
| `key_entities` | 账号、主机、IP、进程、域名/哈希 |
| `time_window` | 攻击时间窗与基线 |
| `attack_stage_hypothesis` | ATT&CK 阶段假设与置信度 |
| `confirmed_indicators` | 已确认 IOC/IOA 与证据来源 |
| `ruled_out_signals` | 已排除线索，避免重复查询 |
| `executed_containment` | 已执行遏制动作与 TTL/回滚状态 |

**使用要求**：槽位是唯一事实来源；排除线索要写依据；遏制后立即更新 TTL 与回滚状态。

#### 30.3.11 证据标准与时间线

**证据标准**（原文保留）：每条结论记录「证据类型、来源系统、采集时间、置信度、关联实体」，形成可复核时间线。

| 字段 | 说明 |
|---|---|
| `evidence_type` | 登录、进程、网络、云审计、情报 |
| `source` | 系统与查询语句 |
| `collected_at` | 采集时间 |
| `confidence` | 置信度与依据 |
| `entities` | 关联账号/主机/IP |
| `hash` | 原始证据哈希 |

**要求**：证据与结论分离存储；证据优先保全，清除动作放在取证之后；时间线要能回答「先发生了什么」。

#### 30.3.12 多工具 DAG 调查与 Wave

**核心挑战**：研判需要跨 EDR、IAM、网络防火墙/WAF、云审计与威胁情报交叉取证；遏制动作若误杀核心业务节点、共享网关/NAT 出口、高管或值班账号，会直接导致业务中断。

**先查后遏、分批执行**（原文保留）：

1. **只读取证波次**：并发查身份登录历史、EDR 进程父子链与外连、云审计、WAF 拦截、威胁情报、资产角色。
2. **证据汇总**：确认攻击阶段、受影响实体与已排除线索。
3. **遏制必要性判断**：若为良性运维、已知扫描或已被上游自动阻断，跳过遏制并记原因码。
4. **爆炸半径校验**：资产关键度、共享出口、服务账号、特权身份、影响用户数。
5. **执行与观察**：低风险动作带幂等键与 TTL 执行；高风险动作挂起 `WAITING_FOR_HUMAN`。
6. **验证与回滚**：确认异常收敛且业务未受损；误杀则立即撤销并复盘。

**只读取证工具**：

| 工具 | 用途 |
|---|---|
| `query_identity_logs` | 登录、MFA、权限变更 |
| `query_edr` | 进程树、命令行、文件与网络行为 |
| `query_network` | 连接、DNS、流量与出口 |
| `query_cloud_audit` | 云 API 调用与密钥使用 |
| `query_waf` | 拦截、攻击载荷与来源 |
| `query_threat_intel` | IOC/IOA 与置信度 |
| `get_asset_profile` | 资产关键度、归属、暴露面 |
| `snapshot_evidence` | 内存/磁盘/日志快照 |

#### 30.3.13 遏制风险分级

| 风险级别 | 示例 | 处理方式 |
|---|---|---|
| 低风险/可逆 | 吊销单一可疑会话、隔离非核心终端、封禁明确恶意外部 IP（严格白名单） | 爆炸半径与频控内自动执行，带 TTL |
| 中风险 | 隔离一般业务主机、禁用非特权账号、临时阻断恶意域名 | 规则校验 + 观察窗口 + 可回滚 |
| 高风险/大影响面 | 隔离核心生产主机、禁用特权/高管/服务账号、修改全站 WAF/防火墙、撤销生产凭证 | 强制 `WAITING_FOR_HUMAN`，必要时双人审批 |

#### 30.3.14 爆炸半径评估

**爆炸半径关键因素**（原文保留）：

- 资产是否核心生产、是否有冗余、是否承载共享服务。
- IP 是否为 NAT/网关/代理出口，封禁会否影响整栋楼或整个 VPC。
- 账号是否为服务账号、共享账号、值班账号或高权限管理员。
- 动作是否可逆、TTL 多长、回滚需要多久。

**评估输出**：受影响用户数、业务链路、是否跨区域、是否需要业务方确认。

#### 30.3.15 幂等、TTL 与回滚

- 所有遏制工具带 `idempotency_key` 与资源锁/版本号。
- 临时封禁/隔离默认配置 TTL 与撤销接口，到期自动解除或提醒复核。
- 保留 break-glass 流程：紧急情况下可快速解除误杀，但必须留审计。
- **遏制不等于根除**：先隔离保全证据，再清除持久化、轮换凭证、恢复业务。

**幂等键示例**：

| 层 | 方案 |
|---|---|
| 会话吊销 | `revoke_session:{user_id}:{session_id}` |
| 终端隔离 | `isolate:{host_id}:{request_id}` |
| IP 封禁 | `block_ip:{ip}:{ttl}:{request_id}` |
| 域名封禁 | `block_domain:{domain}:{ttl}` |
| 账号禁用 | `disable_user:{user_id}:{approval_id}` |

#### 30.3.16 上下文治理

- 工具层先按时间窗、关键实体与异常字段截断日志/堆栈。
- `assistant(tool_calls)` 与 `role="tool"` 作为原子组整进整出，校验 `tool_call_id` 配对。
- 槽位锁定关键实体、已确认证据与已执行遏制；增量摘要承接长链条脉络。
- 敏感字段（密码、Token、密钥）在进入上下文前脱敏。

#### 30.3.17 抗 Prompt Injection

**核心挑战**：安全告警、HTTP 请求、邮件头/正文、进程命令行、恶意脚本或外部情报描述中，天然可能包含攻击者精心构造的对抗性指令。

**隔离原则**（原文保留）：

- 日志原文、Payload、命令行、邮件内容作为纯数据字段结构化包裹，明确标记不可信。
- 不执行载荷中的任何「指令」，只做解析、摘要与证据引用。
- 遏制动作准入与风险判定由确定性策略引擎独立执行，不依赖 LLM 自我约束。
- 对疑似注入内容打标、留样，进入红队测试集。

#### 30.3.18 异常降级矩阵

| 依赖/环节 | 典型故障 | 策略 | 降级动作 |
|---|---|---|---|
| SIEM/EDR/日志 | 查询超时 | 降级读 | 输出已有证据、待查项与建议，保障值班响应 |
| CMDB/资产画像 | 超时 | 降级读 | 用缓存资产标签并标注可能过期，禁止据此自动遏制 |
| 威胁情报 | 超时 | 降级读 | 标记「情报未确认」，不单独作为封禁依据 |
| 策略/审批/身份 | 不可用 | **Fail-Closed** | 拦截遏制动作，转人工 |
| 遏制执行接口 | 超时、结果未知 | **Fail-Closed** | 先查资源状态，禁止盲目重试 |
| 审计日志 | 不可写 | **Fail-Closed** | 禁止高危写操作，恢复审计后再执行 |
| 决策模型 | 超时 | 规则兜底 | 切确定性 Playbook 或转人工 |
| LLM 服务 | 超时/限流 | 模型降级 | 切备用模型，仍失败输出调查摘要 |
| EDR/防火墙控制面 | 不可达 | **Fail-Closed** | 不执行遏制，转人工 |
| 工单/通知 | 失败 | 重试/排队 | 记录待发送，避免案件被静默丢弃 |

**治理要点**：降级打标 `degraded=true` 与 `reason_code`；遏制、审批、审计默认 Fail-Closed；读路径可降级并明确标注证据缺失。

#### 30.3.19 事件、原因码与审计

**统一事件 Envelope**：

```
trace_id, case_id, alert_id, session_id, turn_id,
entity_id, host_id, user_id, src_ip, severity,
tool_name, tool_call_id, idempotency_key,
action, target, approval_id, ttl,
evidence_refs, decision_meta, reason_code, degraded
```

**核心事件**：

| 阶段 | 事件示例 |
|---|---|
| 接入归并 | `alert.received`、`case.merged`、`entity.linked` |
| 调查 | `case.triaged`、`tool.called`、`evidence.collected`、`attack_stage.assessed` |
| 遏制 | `containment.requested`、`approval.requested`、`containment.executed`、`containment.revoked` |
| 闭环 | `case.recovered`、`postmortem.created`、`playbook.updated` |

**统一原因码**（原文保留并扩展）：

- `CANCEL_ALREADY_CONTAINED`：已被上游/其他系统遏制。
- `SAFE_CRITICAL_ASSET_PROTECTED`：核心资产保护策略拦截。
- `POL_APPROVAL_REQUIRED`：需要人工审批。
- `DEC_BENIGN_NOISE`：判定为良性噪音。
- `SYS_TELEMETRY_TIMEOUT`：遥测查询超时。
- `POL_DUAL_APPROVAL_REQUIRED`：需要双人审批。
- `AUTH_PERMISSION_DENIED`：权限不足。
- `TOOL_RESULT_UNKNOWN`：遏制结果未知。
- `SAFE_TTL_EXPIRED`：临时遏制已到期解除。

**审计要求**（原文保留）：

- 追加写/WORM 存储、哈希链或签名，防篡改。
- 记录操作者（人或 Agent）、审批人、证据、工具参数、执行结果与回滚状态。
- 审计日志访问受控，保留周期满足合规要求。
- 复盘统计误报、漏报、审批驳回与误杀回滚，回流规则、模型与资产画像。

#### 30.3.20 评测闭环

**检测与研判指标**：

- 告警准确率/召回率、误报率、漏报率、平均检测时间（MTTD）、平均确认时间（MTTA）。
- 根因/攻击阶段判断准确率、IOC 精确率、证据覆盖率。

**遏制与业务指标**：

- 平均遏制时间（MTTC）、自动遏制成功率、误杀率、回滚率。
- 未授权遏制动作数（应为 0）、核心资产误伤数（应为 0）、TTL 到期清理率。
- 业务中断时长、客诉与合规事件数。

**评测方法**：

- 历史安全事件回放：给定告警与遥测，评估研判结论与遏制建议。
- 红队/攻击模拟：覆盖钓鱼、横向移动、C2、权限提升等链路。
- Prompt Injection 红队：恶意邮件、命令行、Webhook、日志注入。
- 在线 A/B：分析师采纳率、自动化处置比例、升级准确率。

**闭环**：误报、漏报、审批驳回、误杀回滚样本回流规则、模型与资产画像；高质量处置沉淀为 Playbook，高风险步骤保留人工闸门。

#### 30.3.21 容量估算

**假设**：安全告警 100 万条/天，峰值 10 倍；归并后 1 万案件/天；40% 进入 Agent 调查；平均 8 轮、12 次工具调用；单轮 8000 输入 + 800 输出 token。

| 指标 | 计算 | 结果 |
|---|---|---|
| 平均告警 QPS | 100 万 ÷ 86400 | ≈ 11.6 |
| 峰值告警 QPS | 11.6 × 10 | ≈ 116 |
| 平均案件 QPS | 1 万 ÷ 86400 | ≈ 0.116 |
| 峰值案件 QPS | 0.116 × 10 | ≈ 1.16 |
| Agent 调查峰值 | 0.46 案件/秒 | ≈ 0.46 |
| 工具调用峰值 | 0.46 × 12 | ≈ 5.5 QPS |
| LLM 调用峰值 | 0.46 × 8 | ≈ 3.7 QPS |
| Token/天 | 4000 × 8 × 8800 | ≈ 2.8 亿 |
| 证据存储 | 4000 × 200KB | ≈ 800MB/天 |
| 遥测查询/天 | 4000 × 12 | 4.8 万次 |

**结论**：瓶颈在 SIEM 查询与日志存储，而非 LLM；遏制量不大但每一次都必须可审计、可回滚。

### 30.4 工程落地与规则护栏

#### 30.4.1 端到端链路

```
告警 / 情报命中 / 云审计事件
  → Telemetry Gateway（归一化、限流）
  → Case Service（实体关联、资产富化、严重度）
  → 门控（扫描快筛 / 自动或人工）
  → Investigation Orchestrator
      ├→ 只读取证波次（身份/EDR/网络/云审计/情报）
      ├→ 证据时间线与攻击阶段判断
      ├→ 遏制决策
      └→ 策略引擎校验 → 审批（高风险）
  → Containment Gateway（幂等、TTL、资产锁）
  → 验证与回滚（异常收敛 + 业务未受损）
  → 审计、复盘、Playbook 回流
```

#### 30.4.2 门控与路由护栏

- 已知扫描、自动化运维、重复实体告警直接抑制并记录原因。
- 严重度按资产关键度、数据密级、攻击阶段与传播速度定级。
- 高危信号（勒索、外传、特权账号异常）直通人工并提升优先级。
- 每案件只允许一个主调查 Agent，避免重复取证与遏制冲突。
- 门控判定可回放、可解释。

#### 30.4.3 只读取证工具契约

| 项 | 要求 |
|---|---|
| 描述 | 用途、参数、时间窗、返回字段 |
| Schema | 类型、范围、枚举、必填 |
| 超时 | 独立超时与降级策略 |
| 限流 | 单案件查询配额，防打爆 SIEM |
| 证据 | 返回 `source`、`collected_at`、`query`、`hash` |
| 权限 | 按数据域与密级鉴权 |
| 脱敏 | 凭证与个人信息按策略脱敏 |
| 审计 | 参数、结果摘要、耗时 |

#### 30.4.4 遏制动作护栏

- 白名单：只允许注册过的遏制动作，禁止任意命令。
- 参数校验：目标、范围、TTL、方向必须在允许范围。
- 资产关键度校验：核心资产默认禁止自动遏制。
- 共享出口识别：NAT/网关/代理出口需人工确认。
- 爆炸半径上限：单次影响用户数/主机数设阈值。
- TTL 强制：临时动作必须有到期时间与撤销接口。
- 频控：同一实体单位时间动作次数上限。
- 审计前置：审计不可写则拒绝执行。

#### 30.4.5 审批、双人复核与 break-glass

- 高风险遏制强制 `WAITING_FOR_HUMAN`，必要时双人审批。
- 审批请求附带证据、拟执行动作、影响面、TTL 与回滚方案。
- 审批与执行分离，执行者不能自批。
- break-glass 用于紧急解除误杀：快速放行但强制留痕、事后复盘。
- 审批超时升级，不允许自动放行。

#### 30.4.6 上下文与敏感信息护栏

- 证据带来源、查询语句、采集时间与哈希。
- 载荷与命令行结构化包裹，标记不可信。
- 凭证、Token、密钥进入上下文前脱敏。
- 已排除线索写入槽位，防止重复调查。
- 原子组裁剪 + 配对校验。

#### 30.4.7 降级与熔断

- 遥测读：降级并标注缺失，不阻塞值班。
- 遏制、审批、审计：Fail-Closed。
- 决策模型：切确定性 Playbook。
- 通知/工单：排队重试，不静默丢弃。
- 高频抖动依赖：熔断器 + 本地缓存。

#### 30.4.8 观测、压测与红队

**观测**：

| 类别 | 指标 |
|---|---|
| 接入 | 告警量、实体归并率、抑制率 |
| 调查 | 轮次、工具成功率、证据覆盖率 |
| 遏制 | 动作成功率、TTL 清理率、回滚率 |
| 安全 | 未授权遏制、注入拦截、审计完整性 |
| 成本 | 单案件 token、SIEM 查询量 |

**压测与演练**：

- 告警风暴（10 倍、50 倍）。
- 勒索软件横向传播。
- 云 AK 泄露批量调用。
- 共享出口误封演练。
- 审计服务不可用。
- LLM 限流与情报超时。

#### 30.4.9 上线检查

1. 告警是否先按实体归并成案件？
2. 攻击阶段结论是否绑定证据与时间线？
3. 遏制前是否完成资产关键度与爆炸半径校验？
4. 高风险动作是否强制审批、必要时双人复核？
5. 所有遏制动作是否带幂等键、TTL 与撤销接口？
6. 审计不可写时是否禁止高危写操作？
7. 共享出口/NAT/特权账号是否有专门保护？
8. 载荷与命令行是否按不可信数据隔离？
9. 降级是否按读降级、写 Fail-Closed 分级？
10. 红队与历史回放是否覆盖注入、误杀与绕过？

### 30.5 典型案例与端到端解决

#### 30.5.1 案例：异常身份登录 + 可疑横向/外连

1. **告警关联与富化**：同一账号/源 IP/主机的异常登录、可疑 PowerShell、外连稀有域名按 10 分钟窗口归并为单一 `case_id`；富化资产为「研发笔记本、可访问生产、非核心服务器」。
2. **门控初筛**：排除已知扫描与自动化运维；账号近期无出差记录，判定为可疑高危。
3. **只读取证**：身份日志发现异地登录且 MFA 异常；EDR 显示 PowerShell 由邮件客户端拉起并执行编码命令；网络显示外连威胁情报标记的 C2 域名。
4. **攻击链判断**：初始访问（钓鱼邮件）→ 执行（PowerShell）→ C2 外连；尚未发现横向移动，但该账号拥有生产访问权限。
5. **遏制评估**：
   - 低风险：吊销该用户全部会话、封禁 C2 域名、隔离研发笔记本（非核心资产）。
   - 高风险：禁用账号或撤销生产凭证会影响值班，需负责人审批；先吊销会话并隔离终端，审批后再决定是否禁用。
6. **执行与验证**：带幂等键与 TTL 执行隔离/封禁，观察是否仍有新外连；确认业务未受影响。
7. **根除与恢复**：轮换凭证、清除持久化、重装终端、加强 MFA；复盘钓鱼入口并更新检测规则与 Playbook。

**常见失败**：封禁 NAT 出口导致整层楼断网；未保全证据就重装；把服务账号当普通账号禁用；只封 IP 不封域名导致攻击者换 IP 继续。

#### 30.5.2 变体 A：勒索软件

- 症状：批量文件加密、卷影副本删除、横向 SMB 传播。
- 诊断：进程树、加密文件扩展名、备份系统状态、横向登录。
- 处置：立即隔离受影响主机、阻断横向端口、保护备份、暂停相关账号。
- 护栏：隔离核心主机需审批；清除前先快照；优先保业务与备份。

#### 30.5.3 变体 B：云 AK 泄露

- 症状：异常地域 API 调用、批量创建资源、对象存储访问激增。
- 诊断：云审计调用链、AK 使用来源、权限范围。
- 处置：禁用/轮换 AK、吊销会话、限制策略、封禁来源 IP。
- 护栏：禁用生产 AK 影响面大，需审批；先最小权限收敛再轮换。

#### 30.5.4 变体 C：内部人员数据外传

- 症状：非工作时段批量下载、异常压缩、外发通道。
- 诊断：数据访问基线、DLP 告警、外发目标。
- 处置：限制访问、保留证据、通知合规与法务；避免打草惊蛇。
- 护栏：涉及员工隐私与法务流程，自动动作只做低风险限制。

#### 30.5.5 变体 D：钓鱼邮件批量投递

- 症状：多用户收到同源邮件、点击后异常登录。
- 诊断：邮件头、URL/附件哈希、点击与登录时间线。
- 处置：隔离邮件、封禁域名、重置受影响账号、加强 MFA。
- 护栏：批量重置需分批并通知，避免服务台被打爆。

#### 30.5.6 故障与兜底

| 故障 | 影响 | 兜底 |
|---|---|---|
| SIEM 超时 | 证据不全 | 降级读，输出已有证据与待查项 |
| 资产画像过期 | 关键度误判 | 禁止自动遏制，转人工确认 |
| 情报不可用 | 无法确认 IOC | 标记未确认，不单独封禁 |
| 审批不可用 | 高危阻塞 | 拦截遏制，转人工 |
| 遏制接口超时 | 结果未知 | 先查资源状态，不盲目重试 |
| 审计不可写 | 无法留痕 | 禁止高危写操作 |
| LLM 限流 | 无法生成结论 | Playbook 兜底 / 人工 |
| EDR 控制面不可达 | 无法隔离 | 转人工网络侧处置 |

#### 30.5.7 扩容 10 倍，哪里先坏？

| 顺序 | 先坏的点 | 现象 | 对策 |
|---|---|---|---|
| 1 | SIEM 查询 | 超时、限流 | 时间窗收敛、缓存、采样 |
| 2 | 告警接入/归并 | 积压、重复案件 | 分区、批量、实体缓存 |
| 3 | 实体图查询 | 大图慢查询 | 分片、预计算、缓存 |
| 4 | 证据存储 | 写入与成本 | 冷热分层、摘要索引 |
| 5 | LLM 配额 | 429 | 模型分级、证据裁剪 |
| 6 | 审批人力 | 排队 | 阈值优化、低风险自动化 |

#### 30.5.8 取舍复盘

| 决策 | 代价 | 收益 | 重新评估条件 |
|---|---|---|---|
| 假设已失陷 | 取证成本高 | 不漏关键链路 | 低风险场景可裁剪 |
| 证据先行 | 遏制稍慢 | 可举证、可复盘 | 勒索进行中可加速 |
| 最小遏制 | 可能不彻底 | 业务不中断 | 确认根除后再扩大 |
| TTL 强制 | 需复核 | 自动解除误杀 | 长期封禁走正式流程 |
| 审计前置 | 少自动化 | 合规可追溯 | 审计高可用可放宽 |
| 高风险审批 | 人工成本 | 防误杀 | 风控成熟可降级 |

### 30.6 闭环演进与常见误区

#### 30.6.1 演进路线

| 阶段 | 形态 | 触发条件 | 关键改造 |
|---|---|---|---|
| L0 | SIEM 告警 + 人工处置 | 起步 | 告警分级、值班 |
| L1 | 告警归并与资产富化 | 噪音大 | 实体关联、资产画像 |
| L2 | 只读研判助手 | 调查耗时 | 跨源取证、时间线 |
| L3 | 受控遏制（SOAR） | 标准动作多 | 风险分级、TTL、审批 |
| L4 | 自动调查 + 建议 | 案件量大 | DAG、槽位、ATT&CK |
| L5 | 闭环自治 | 成熟 | 低风险自动遏制、Playbook 回流 |

#### 30.6.2 指标体系

| 层级 | 指标 | 用途 |
|---|---|---|
| 检测 | 准确率、召回率、误报率、MTTD | 判断检测质量 |
| 研判 | 阶段准确率、证据覆盖率、MTTA | 判断分析能力 |
| 遏制 | MTTC、误杀率、回滚率 | 判断处置能力 |
| 合规 | 审计完整率、审批合规率 | 判断可举证 |
| 效率 | 分析师负担、自动化比例 | 判断可持续 |

#### 30.6.3 评测与回归

- 历史安全事件回放覆盖钓鱼、横向、C2、勒索、云泄露。
- 红队攻击模拟验证检测与遏制链路。
- Prompt Injection 红队覆盖邮件、命令行、日志、Webhook。
- 在线 A/B 验证分析师采纳率与误杀率。
- 每周复盘 Top 误报与误杀，沉淀为规则与 Playbook。

#### 30.6.4 Playbook 与自动化分级

| 级别 | 形态 | 人工参与 |
|---|---|---|
| P0 | 文档步骤 | 全人工 |
| P1 | 半自动脚本 | 人工确认关键步 |
| P2 | 受控工作流 | 低风险自动、高风险审批 |
| P3 | 自动处置 + 观察 | 人工监督、可随时接管 |

**要求**：Playbook 版本化、带前置校验、TTL 与回滚步骤；自动化只覆盖已验证的低风险场景。

#### 30.6.5 成本优化

- 模型分级：分诊与摘要用小模型。
- 证据裁剪：只保留关键实体、时间窗与异常字段。
- 缓存：资产画像、情报、常见 Playbook。
- 查询收敛：先聚合指标再下钻原始日志。
- 早停：攻击链已收敛即停止扩线。

#### 30.6.6 产品对比

| 产品/场景 | 核心 | 关键挑战 |
|---|---|---|
| SIEM | 日志汇聚与检测 | 噪音、查询成本 |
| EDR/XDR | 终端检测与响应 | 误隔离、覆盖 |
| SOAR | 编排与自动化 | 动作安全、审批 |
| 威胁情报平台 | IOC/IOA | 时效与置信度 |
| 云安全态势 | 配置与权限风险 | 多云一致性 |
| SOC Agent | 研判 + 受控遏制 | 误杀与审计 |

#### 30.6.7 常见误区

| 误区 | 问题 | 正确做法 |
|---|---|---|
| 每条告警单独调查 | 见树不见林 | 实体 + 时间窗归并 |
| 先封禁再取证 | 证据破坏 | 先取证后遏制 |
| 封禁 NAT/网关出口 | 大面积断网 | 识别共享出口 |
| 把服务账号当普通账号 | 业务中断 | 账号类型识别 |
| 只封 IP 不封域名/凭证 | 攻击者换路继续 | 多层封堵 |
| 自动遏制无 TTL | 永久误杀 | TTL + 撤销接口 |
| 模型决定遏制动作 | 注入/越权 | 策略引擎裁决 |
| 审计可写才留痕 | 无法追责 | 审计前置 |
| 重装即恢复 | 根因未除 | 先清除持久化与轮换凭证 |
| 只做检测不做复盘 | 同类攻击反复 | Playbook 与回流 |

#### 30.6.8 高频追问

- **如何避免封禁核心资产或共享出口？** → 资产关键度 + 爆炸半径校验 + 高风险审批 + TTL/回滚。
- **如何防日志/邮件中的 Prompt Injection？** → 不可信数据隔离，策略引擎独立裁决，工具白名单与参数校验。
- **如何保全证据？** → 先只读取证与快照，再隔离；审计追加写、哈希链防篡改。
- **遥测超时怎么办？** → 降级读输出已有证据；遏制动作 Fail-Closed。
- **如何评估 SOC Agent？** → 历史回放 + 红队 + 误报/误杀率 + MTTD/MTTC + 未授权动作数。
- **误杀了怎么办？** → TTL 自动解除/一键回滚 + break-glass + 复盘更新资产画像。
- **识别到 C2 但情报未确认怎么办？** → 结合本地行为证据，先低风险阻断，不单独凭情报封禁。
- **如何判断横向移动？** → 关联登录源、远程执行、SMB/WinRM 与凭据复用。
- **多个案件同一实体怎么办？** → 实体级锁与案件合并，避免重复遏制。
- **如何防止重复遏制？** → 幂等键 + 资源状态 + `CANCEL_ALREADY_CONTAINED`。
- **审计服务挂了还能处置吗？** → 低风险只读可继续；高危写禁止。
- **如何沉淀 Playbook？** → 成功案件转步骤，版本化，先半自动再受控自动。

#### 30.6.9 答题提纲与练习

**25 分钟答题提纲**：

| 时间 | 内容 |
|---|---|
| 0–3 min | 澄清：告警量、资产规模、攻击面、合规 |
| 3–6 min | 容量：告警/案件/工具/LLM QPS、token |
| 6–11 min | 五层架构：接入归并 → 门控 → 研判 → 遏制 → 审计 |
| 11–16 min | 实体关联、ATT&CK、证据时间线 |
| 16–21 min | 遏制分级、爆炸半径、TTL、注入隔离 |
| 21–25 min | 降级、审计、评测、Playbook |

**练习**：

1. 设计日 100 万告警的 SOC Agent，给出五层架构。
2. 设计实体关联与案件归并规则，要求不漏多阶段链路。
3. 设计只读取证 DAG 与证据时间线。
4. 设计遏制动作的风险分级、审批与 TTL 回滚。
5. 设计审计不可用、遥测超时时的降级方案。

#### 30.6.10 一页纸速记

**主线与放大器**

- SOC Agent = 归并 + 研判 + 遏制 + 审计。
- 三个放大器：身份、资产、合规。

**归并与遏制**

- 假设失陷、证据先行、遏制可逆、审计前置。
- 实体 + 时间窗归并成 `case_id`，按 ATT&CK 还原攻击链。
- 遏制看爆炸半径：核心资产、共享出口、服务账号、特权身份。

**输入与审计**

- 低风险自动 + TTL，高风险审批 + 双人复核。
- 先隔离保全证据，再清除持久化与轮换凭证。
- 载荷与命令行是不可信数据，策略引擎独立裁决。
- 审计不可写，禁止高危写操作。
- 没有红队与历史回放，就无法证明 SOC Agent 可靠。
