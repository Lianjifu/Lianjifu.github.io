## 系列定位

本系列记录 OpenClaw v2026.9.2 的源码结构。它不是使用手册，也不是产品评价，而是「读一遍源码，看清一次委托如何落地」的工程笔记：每个模块回答一个具体问题，答案必须能在源码里找到落点。

## 硬规则

1. 模块顺序不可打乱；后篇只引用前篇结论，不重讲定义。
2. 机制专名只在对应模块首次出现：Envelope 协议仅 03、Provider / Runtime 抽象仅 04、会话三层存储仅 05、钩子链仅 06。
3. 性能数据仅 08 给出基线，其他模块不重复贴数字。
4. 异常矩阵仅 09 汇总，其他模块只描述本模块的失败点。
5. 目录树与路径引用仅 10 完整给出，其他模块按需引用局部路径。
6. 每篇必须给出源码落点（路径或符号名），没有落点的结论不写。

## 章节骨架

每篇按「总—分—总」组织：开篇先把结论给出来，正文分段展开，结尾再收成结论。读者进入正文前先拿到框架：

```
导语段（.oc-lead）
引导思考表（table.guide-card.collapsed，四行：它为什么存在 / 它解决什么问题 /
          它在系统中的位置 / 它如何工作）
本章全景（.oc-keypoint + .oc-overview 表 + .oc-cards 路线图）—— 总
h2 章.段 段标题（seg-N，3–5 段）
  段标（.oc-part-lead，说明这一段回答什么）
  h3 章.段.节 小节（sec-N.K）
    本章要点（.oc-keypoint）
    思考笔记（.thinking-note，每个小节恰好一个）
    h4 子小节（sec-N.K.M，标题不带编号）
      h5 更细（原 h4，标题不带编号）
    图示（figure + mermaid + figcaption）
    数据表、代码块、列表
h2 章.段 总结
  h3 章.段.1 一句话总结
  h3 章.段.2 本章结论（ol.oc-points，3–5 条）
  h3 章.段.3 下一章
  h3 章.段.4 相关阅读
```

- 层级共四级：h2 段 → h3 小节 → h4 子小节 → h5 更细。编号只到 h3（`2.1.3`），h4 与 h5 不带编号。
- 侧栏目录只收 h2 与 h3：段为 level-2，小节为 level-3。链接数量必须与 `docs/article-manifest.json` 中该篇的 `headings` 计数一致。
- 「引导思考」表逐篇手写，内容必须来自该章正文，不得跨章搬用；迁移时残留的同名重复表要删掉。
- 「本章要点」与「思考笔记」都放在小节开头：先要点，再笔记，再正文。

## 思考笔记

每个小节恰好有一个 `.thinking-note` 面板，位置固定在小节开头（本章要点之后、正文之前）。原本落在子小节里的思考笔记上移并合并进小节的面板；没有思考笔记的小节要补写一条。

面板内的标题统一写「思考笔记」（迁移前混着「要点」「提示」三种写法）。面板样式来自 `css/2026.css`。

## 结尾小节

每篇最后一节固定为「总结」，结构固定为四小节：

```
h2  章.段 总结
  h3  章.段.1 一句话总结    —— thinking-note，给出本章的落点与边界
  h3  章.段.2 本章结论      —— ol.oc-points，3–5 条，逐条对应前面各段
  h3  章.段.3 下一章        —— 指向下一篇讲什么、接口在哪
  h3  章.段.4 相关阅读      —— 指向系列内其它篇目的锚点
```

原来的「阅读路径 + FAQ + 总结」三段式（阅读路径 / 常见问题 / 一句话总结 / 相关阅读）已去掉前两段：阅读路径按读者类型分叉，与正文目录重复；FAQ 的内容多在正文对应小节已经讲过。删掉后只留结论和横向链接。2026-11-08 又把结尾从两小节扩成四小节：结尾是「总—分—总」里的第三次「总」，只留一句话不够用。

## 图示规则

本系列共有 155 张 Mermaid 图示，全部带题注（`图 X.Y · 说明`），题注随正文一并维护。

- 图示写 `<figure><div class="mermaid">…</div><figcaption>…</figcaption></figure>`，不要用 `<pre class="mermaid">`。
- **图示源码是文本，不是标记**：节点标签里的 `<br/>`、`<b>` 必须转义成 `&lt;br/&gt;`、`&lt;b&gt;` 再写进页面。直接写尖括号，浏览器会把它当元素吃掉，渲染器读到的源码里换行和加粗就没了——标签会连成一长串。
- Mermaid 源码是语法，不是中文散文：源码里的 `:` `,` `(` `)` 保持半角，不要做全角标点转换。
- 图示宽度按栏目宽定：缩到一半以上就等比缩到栏宽，能一眼看全；再宽的保持自然尺寸，容器横向滚动，并给出「图比正文宽」的提示。
- 宽图的滚动条常驻可见，鼠标竖向滚轮悬停在图上会转为横向平移；点击图示放大后，弹窗按自然尺寸显示，同样可横向滚动。
- 图内文字不能被裁切；若 `foreignObject` 装不下文字，先改图，不靠 CSS 缩放补救。
- Mermaid 运行时（554 KB）按需加载：图示接近视口时才下载并绘制，图示源码始终留在 HTML 里。未渲染时显示占位框，不显示源码。

### 长链图示改写（2026-11-08）

「缩到一半以上就等比缩到栏宽」这条规则只对宽度适中的图示有效。模块 02 的「智能体 5 层状态机」原是一条 `flowchart LR` 长链，11 个状态加 4 个分支节点自然宽度 2084px，是正文栏宽（836px）的 2.5 倍；按规则缩到 40% 已经读不清，只能保持自然尺寸横向滚动，读者在正文里永远看不到完整链路。

改法是把它重画成三段式纵向图，而不是缩小：

```
flowchart TD
  subgraph QUEUE["排队"]      # session lane → global lane
  subgraph EXEC["一次执行"]    # attempt → subscribe → wait compaction → finalize
  subgraph ERR["错误处理"]     # error? →(yes) rotate profile → compact → fallback
                               # error? →(no) 完成
  QUEUE --> EXEC
  EXEC --> ERR
  FB --> AT
```

自然宽度降到 776px，小于栏宽，缩放规则直接按原尺寸绘制，图示在正文里完整可见。分段还顺带把「排队 / 一次执行 / 错误处理」三段流程显式标出来，与图下的状态表对照。

两条写图示的坑：

- subgraph 里的 `direction LR` 只在**该段没有任何跨段节点级连线**时才生效。一旦某个节点连到段外的节点，方向会被重置成父级方向，整段退化成竖排。所以跨段一律用 cluster 级连线（`QUEUE --> EXEC`），段内保持节点级连线。
- 本篇页面的 Mermaid 源码里 `>` 一律转义：`-->` 写成 `--&gt;`，节点标签里的 `<br/>` 写成 `&lt;br/&gt;`。改源码时漏掉转义会让浏览器把源码当标记吃掉。

## 全系列重构（2026-11-08）

十篇原本是「导语 → 引导表 → 平铺的编号小节 → 总结」的结构：每篇 12–21 个一级小节直接摊开，读者看不出哪些小节在回答同一类问题；侧栏目录 28–63 条，越靠后越难用。这次统一改成「总—分—总」。

**每篇的结构变化**

- 开篇加「本章全景」三件套：`.oc-keypoint` 给出 3–5 句结论（总），`.oc-overview` 表给出「本章回答 / 核心机制 / 关键数字 / 读完能做什么」，`.oc-cards` 给出分段路线图。
- 正文按 3–5 段分组，段标题升为 h2（`seg-N`），原一级小节降为 h3（`sec-N.K`），原二级小节降为 h4 且去掉编号，原三级小节降为 h5。编号从两级变三级，读者看到的层级和段结构一致。
- 每段前插入 `.oc-part-lead` 段标，一行说明这一段回答什么问题。
- 每个小节恰好一个思考笔记，位置固定在小节开头；原本散在子小节里的 55 条上移并合并进所属小节，另有 80 条为缺笔记的小节补写。
- 结尾从两小节扩成四小节：一句话总结 → 本章结论（3–5 条）→ 下一章 → 相关阅读。
- 侧栏目录从 28–63 条收到 18–29 条：段为 level-2，小节为 level-3，链接数与 manifest 的 `headings` 计数一致。

**顺带修掉的迁移遗留**

- 十篇正文各有一份重复的引导思考表（`.guide-card` 之外还留着同名无 class 的表），读者会看到两遍。
- 43 个「本章要点」块的外层 div 丢了 `oc-keypoint` 类，一直是裸 div，没套上设计好的要点面板。
